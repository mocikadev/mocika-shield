首批实施：新增 CLI 私有 `mcp` 模块，传输/工具映射、启动策略、进程桥接和结果白名单各有明确职责。核心、GUI、Android 壳及旧命令公开接口未改；同一执行器通过绝对路径调用，标准错误不转发，业务输入目录不作为工具查找基准。SDK 精确锁定 `rmcp 3.9.0`、关闭默认特性，仅服务端和本机传输；Rust 下限 1.88，本机编译器满足，未升级工程工具链或 Android 4.4 独立锁文件。锁文件新增 14 个包，无原有包版本升级；SDK 自身的新 SHA-256 版本不替换核心原算法。

停止与协议回归：轻量 Java 夹具产生心跳，验证超时、MCP 取消通知、输入断开及单活动调用，终态后心跳不再增长；同时核对检查工具未继承签名密码。输出/路径/配置参数只能来自宿主策略与有限输入，超限/畸形消息不触发工具；结果不包含输入自由文本或配置原文。准备/异常时没有收尾证明仍为 `unconfirmed`；未知或停止未确认不改判成功。

一次默认/特性构建并行复测串用了同一 `target/debug/shield`，使默认入口拒绝测试失败；确认测试目标覆盖后改为串行复跑，默认模式入口测试通过，没有放宽门禁或修改旧执行代码。后续两种特性测试须串行，或使用不同目标目录。

剩余边界：本轮仅协议专项，不是当前 Agent 已注册的 MCP 工具，不证明客户端用户授权/取消按钮行为。只读阶段不注册写工具，`--allow-execution` 当前明确拒绝；计划缓存/消费、执行进度、状态查询、执行背压/晚取消和正式 `.app` 共包均尚未实施。进程组及路径检查面向可信本机环境，不宣称同权限恶意隔离、逃组/双重崩溃自动清场或完整 JDK 冻结。后续在同一分支推进完整阶段，再集中审查提交，不发布新版本。

### 第二阶段：执行、状态与取消

2026-11-09：按既定方案继续使用 `arch-guard` 复核，属于已批准架构内的结构性实施，不另建 crate、工作流或工程副本。将 SDK 接口、单次编排、会话状态和传输生命周期分别留在 CLI 私有边界；底层加固、签名、任务停止和提交实现未改。CLI 参数和旧配置不迁移，`mcp-server` 仍默认关闭，现有 App 构建不启用 MCP。

已实现：

- 宿主显式 `--allow-execution` 且提供固定配置时，才额外注册执行和状态查询；直接调用未注册工具也不能越权，不只依赖工具列表/注解。密码、路径和配置不能通过执行工具参数覆盖。
- 就绪计划保存随机引用、原参数及摘要，最多 16 条、10 分钟有效。摘要不匹配不消费；开始尝试后，无论执行前阻断、签名失败、取消或未知结果都已消费。运行记录不被到期清除，终态再保留 10 分钟；无持久任务库或自动重试。
- 状态查询不争抢工作许可，不启动 Java；执行中可返回已观察到的固定阶段，取消后可取终态。异常退出守卫将未完成的尝试保守记为未知，不使计划复活。
- 对 CLI 事件流逐条检查协议、任务身份、序号及阶段单调性；唯一终态还须匹配退出码、计划摘要、交付和清理证据。未知/截断回执记为提交不确定，不透传 stderr 或原始日志。
- 有进度标识时发送阶段通知，无标识时状态仍可查询。CLI 进度队列有限且不阻塞监督；通知等待与标准输出写入/刷新设有限期限，阻塞请求取消。已发布成功不会因晚取消降成“未发布”或被删除；若交付后本机检查失败，保留已收到的交付证据、整体标记未知。

验证证据：

- 原生环境为当前 macOS、Java 17；协议协商为 `2025-11-25`，未改变系统 Java。使用约 641 KiB 自有 APK、临时 PKCS12 和已签名副本，不读取生产证书或 GUI 数据库，不安装设备、不启动 GUI、不上传资料。
- 真实专项三项均显式运行通过，最终合跑 178.19 秒，不计入默认忽略项：正常计划→加固/签名→独立验签/证书一致→摘要和 SDK 16 KB ZIP 对齐；执行中的查询/重复拒绝、结束后重复拒绝和晚取消；解包阶段的 MCP 取消及输入断开；故意错误私钥密码导致签名失败；规划后输出占用和固定配置漂移阻断。
- 复核时发现原共享夹具只查根目录，而本轮输出已在授权子目录；已强化为检查实际输入/输出目录后重跑上述三项。取消终态还断言清理完成；原 APK、签名输入副本、配置摘要不变，没有默认路径产物或实际授权目录的任务残留。该结论是桌面管线及 ZIP 对齐，不是 Android 安装运行、ELF 页对齐或跨系统矩阵结论。
- 轻量/组件覆盖计划到期、满额、跨会话拒绝、单次消费、异常回执、未知不重试、缺凭据、权限/参数、配置/路径变化和状态查询。输出背压使用受限异步管道组件验证取消信号，执行停止路径另有真实取消/断开证据；不将组件测试冒充特定宿主的输出阻塞/按钮端到端验收。
- 全量默认并发回归首次有两项夹具未在六秒内进入证书工具；单独串行复跑通过，未改产品期限或停止逻辑。隔离的是多个调试 MCP 进程同时启动的夹具竞争，不是服务内并发：状态查询、忙返回和取消仍实际并发。测试客户端还保留交错响应，避免等待状态查询时丢掉执行回执。隔离后默认并发回归通过。
- 开发特性常规回归：CLI 单元 102 项通过、15 项原条件忽略；公共命令 8 项、只读 19 项、计划 20 项、探针 3 项、缺资源应用 1 项通过；MCP 标准流子进程 12 项通过、1 项真实只读专项仍默认忽略，真实执行三项按原声明默认忽略后另行显式运行。核心单元 203 项、资源契约 11 项、诊断 5 项通过，既有脚本测试 92 项通过；忽略项未计为通过。

当前交付边界：完整 `.app` MCP 共包、源码目录外完整包验收、宿主 Agent 实际 MCP 注册/授权/按钮，以及额外平台/JDK 尚未补齐。现有构建脚本仍只启用原 Agent 执行特性，不把 MCP 静默带入公开包。阶段代码和文档保留同一分支，未提交推送、创建 PR 或发布；下一步集中收口审查及共包决策，不重复扩大功能。

收尾补充：

- 审查发现，只有单个计划不可重试还不足以保护停止未确认后的会话，客户端仍可能请求新计划。已补充会话级停写：观察到未知结果、提交不确定或清理未确认即停止新规划/执行，既有未消费计划和记录到期都不能绕过；状态查询与只读检查保留，人工确认后再由用户建立新会话。没有自动重试/重连或新的持久任务服务。
- 对能够证明未启动 CLI 的取消/输出拒绝，单独报告 `not_needed`，不误报清场未知或锁死整个会话；旧 CLI 早退缺乏收尾证据时仍保守处理。追加单元覆盖准备取消、异常回执锁定、未消费旧计划拒绝及记录过期不解锁；MCP 专项单元 12 项通过。普通签名失败若已完成清理，不会因此锁定后续新计划。
- 默认 CLI 回归通过：单元 73 项、只读协议 21 项、计划 20 项，默认仍拒绝 MCP 入口。两种特性严格 Clippy、Rust 格式与差异空白检查通过；收尾状态守卫只改 MCP 私有模块，未改核心算法、GUI、壳、安装包开关或 CI。真实三项完整专项的证据如上，状态守卫追加后针对性复跑失败/阻断链路，不把差异测试写成重新完成全系统矩阵。
