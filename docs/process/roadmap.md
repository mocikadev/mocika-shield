# Mocika Shield 路线图

更新：2026-11-12。这里只保留当前工作、候选方向和停止项；已发布版本见[历史档案](roadmap-history.md)。

## 当前基线

- 稳定版为 **1.4.3**，维护 `1.4.x`；**1.5.0-beta.2** 已公开为预览，**1.5.0-beta.3** 正在发布准备。不替代最新稳定版，不移动公开标签。
- 公开预览版为三平台 GUI 共包 CLI／MCP，Skill 独立安装；稳定版 1.4.3 尚未包含新增 Agent 能力。
- Android 4.4 仍限 v7a／NEON；主流混合 ABI 单包兼容不等于承诺所有 4.4 硬件。
- 保持本地离线定位，不向加固后的 APK 增加联网采集，不托管用户 APK、证书或密码。

## 当前工作：预览版维护与可靠性

GUI／CLI 共用配置和证书，Skill 独立安装，MCP 复用 CLI；不增加确认层、后台服务或独立 CLI 发布包。

三平台执行和共包、Windows Java 参数适配已实现。macOS 本机 Java 8／17、Linux／Windows 实际安装包 Java 17、三平台最终源码专项均通过。完整状态和 CI 依据只维护在[平台验收表](agent-desktop-platforms-plan.md)，工具限制见[适配设计](../design/java-tool-adapter.md)。

下一步：

1. 三平台发布已完成，官方 macOS 包通过包级 CLI／MCP、标准／工控加固签名和产物核对；不为文档回填重复完整测试。
2. [桌面可靠性维护](desktop-reliability-plan.md)及 Windows 补验已随 Beta.2 交付；三平台发布构建通过，官方 macOS 包通过 Java 8／17 的签名、双模式加固、MCP 及 V4 输出保护抽验，不重复 Android 全系统矩阵。Fedora 实际渲染问题仍未确认。
3. 三平台 Agent 用法和历史文档已统一整理。[统计构建身份隔离](../design/telemetry-build-identity.md)已合入并完成生产增量迁移和 Worker 部署；原趋势经维护者浏览器确认，私有查询正常。以 Beta.3 交付客户端变更，发布后抽验官方 macOS 包及真实维护使用的身份入库；未完成前不宣称新上报闭环通过。不增加 Agent 业务能力，不修改公开 Beta.2 标签。

本阶段不追加 MCP 纯加固不签名、清空全局默认或输出目录持久化等入口能力；既有差异见[使用说明](../ops/agent-setup.md)。额外宿主注册、GUI 人工交互和设备业务矩阵未全验，不把它们冒充通过，也不要求用户重复整套已通过测试。

## 维护与待证据问题

- 优先复现重复且可定位的用户失败；匿名计数仅作线索，观察期不作为实现前置条件。
- #121 Fedora 空白窗口仍待环境与日志；#110、#116、#132 是未排期功能建议。
- #117、#119、#120、#135 已处理关闭；#119／#120 的实际场景缺用户确认，有新证据可重开。
- #2、#109 因信息不足收口，不等同确认修复；#109 收到授权样本后再定位。
- QQ 群中文文件名个例不能由其他平台回归推定已解决，边界见[中文兼容说明](../design/chinese-toolchain-compatibility.md)。

维护统计和构建身份服务端已部署，新客户端及新入口生产上报闭环尚待验收，查询口径见[统计说明](../ops/project-statistics.md)。不回填缺失快照，不凭下载量或版本号估算精确用户，不追加 APK 运行期采集或硬件指纹。

## 后续候选

| 方向 | 进入条件 |
|------|----------|
| 发布供应链完善 | 可追溯产物、依赖清单；签名／公证另需账号、证书及维护投入 |
| AAB 正式支持 | Google Play 应用签名与内部测试轨道真实闭环；已有实验不等于正式支持，见[结论](../design/aab-feasibility.md) |
| 工具链进一步轻量化 | 原始条目复制、Manifest 处理先证明收益、兼容和可靠回退，不直接替换 apktool，见[设计](../design/toolchain-modernization.md) |
| 可选资源保护 | 有真实需求、显式资源清单及应用侧读取接口，不用透明 Hook，见[研究](../design/asset-protection.md) |

候选不等于排期；本轮不恢复这些实现任务。

## 暂停与停止项

| 方向 | 决定 |
|------|------|
| API 29 以上完整内存 DEX | 暂停：真实大 APK 长期内存性价比门槛未过，见[设计](../design/memory-dex-production.md) |
| DEX 结构／方法代码分离 | 停止产品接入：依赖高风险私有运行时或独立虚拟机，见[研究](../design/dex-code-separation.md) |
| ART／系统 Hook、自修改代码、可写可执行内存 | 不采用，与兼容和安全边界冲突 |
| 在线、移动端或批量加固及 TUI | 不在当前计划 |

## 执行规则

`main` 保持可发布，使用临时功能／修复分支，合并后清理；一个完整阶段集中提交与 PR，不积累调试碎片。测试和文档只保留可维护的契约、验收入口与必要证据，不堆每轮日志。重型 CI 仅手动或发布时运行；不改用户全局 Java、Root、证书或 Agent 配置。
