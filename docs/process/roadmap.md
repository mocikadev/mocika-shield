## 已交付能力与验证边界

1.4.2 的工控混合架构、壳类名/JNI、Native 暴露面及 Manifest 字段治理已完成交付，过程转入[历史档案](roadmap-history.md#142-兼容维护与壳特征治理归档)，不再作为下一开发阶段。rc.3 已获用户在 Android 4.4／6.0／10.0／11.0 上确认；后续新壳的 32／64 位真机、覆盖、缓存、安全策略、Windows 资源及 16 KB ARM64 专项通过，但当前新壳 Android 4.4 未重新实测，不扩大为完整系统矩阵通过，不要求用户重复验收。

新核心兼容旧资源，旧核心明确拒绝新资源；DEXB、缓存身份/目录、加载策略与最低系统要求不变。中文工具链和错误报告证据补齐已随 1.4.2 交付；原生 Windows 个例及桌面未验交互不改写为通过。1.4.0 的预检、配置持久化、失败诊断与应用分享记录见[历史档案](roadmap-history.md#140-可靠性与使用效率归档)，1.4.1 的关联 JDK/keytool 修复见[工具探测设计](../design/java-tool-discovery.md)。

## 当前维护重点

当前新增优先事项：按维护者确认的“一套业务、多种入口”原则统一 GUI／CLI／Skill／MCP 与未来 TUI 的业务能力和本地资料，见[共享应用设计](../design/shared-application.md)与[阶段任务](shared-application-plan.md)。采用已确认的 `shield-app` 应用库承载证书、配置及参数解析，`shield-core` 保持 APK 核心职责；保留原数据目录与密文兼容，不新增常驻服务。GUI 回接、跨进程配置、CLI 管理及已批准的受控 Agent 共享范围已实现，当前集中审查与交付，不据此宣称公开安装包或全部入口写能力已更新。

共享应用及独立签名基线已合入，GUI／CLI 共用资料与配置，Skill 为 0.3.0；MCP 已接通脱敏查询、共享受控加固及单次签名。当前功能分支的[资料管理首批](../design/shared-mcp-management.md)新增业务设置查询／保存、证书偏好和默认切换，已通过本机完整包与当前 Agent 的修改、签名及恢复闭环，进入完整阶段 PR 审查。不改原目录／密文，创建／导入／删除后置，公开安装包及宿主原生注册不据此推定已更新。

受控共享身份使用[无状态绑定](../design/shared-agent-binding.md)，不新增计划数据库。CLI 及 MCP 固定证书、模式、策略和版本，文件另行核对；MCP 只在会话内保存绑定并一次消费，不向模型暴露。源码、独立技能定位和完整包实际结果见[共享阶段记录](shared-application-plan.md)，跨平台／设备启动和宿主注册不据此推定已验。

最新状态：CLI、独立 Skill 与 macOS 共包已随 PR #152 合并主干，公开稳定版仍为 1.4.3；源码合并不等于安装包已更新。维护者确认先以当前 Mac 原生验证为准推进[本地 MCP](../design/local-mcp.md)：先只读工具和访问边界，再复用受控执行器接入执行/取消，任务见[专项计划](local-mcp-plan.md)。Linux/Windows 后置，不新增日常重型 CI，不为阶段开发机械发布版本。以下 Agent 段落为已完成基线与验证边界，尚未发布的限制继续有效。

本地 MCP 开发分支已接通只读工具及宿主显式许可下的加固签名、会话计划消费、进度和状态查询。当前 Mac 的真实协议专项已覆盖成功验签/对齐、执行取消/断开、签名失败和规划后阻断；macOS 共包脚本已显式启用 MCP，GUI 不启动服务。完整应用包在源码外中文空格路径通过只读发现、双资源规划、真实加固签名、独立验签/对齐与取消/断开，原包、输入、配置及应用包未变。默认 CLI 源码构建和公开安装包未变。后续先补共享应用能力，再集中收口；这些是此前外置配置阶段的证据，不等同于新共享库接入、跨平台或宿主 Agent 已注册验收，详细证据见专项计划。

1.4.3 的任务相关工具依赖、Java 就绪引导、真实 APK 成本基线和已对齐产物复用已交付，移入[历史档案](roadmap-history.md#143-工具链就绪与对齐效率归档)。发布资源版本传递和 Windows 检查脚本输出编码的修补也已包含在正式产物中，不再作为待开发任务。

维护 `1.4.x` 稳定线，不固定下个版本。重复出现、具备样本或充分诊断证据的用户失败仍优先处理；固定的“工具执行失败”等分类只是线索，不直接确定修复内容。持续观察不作为有证据修复的前置条件，也不反复要求用户重测已通过版本。

维护者已于 2026-11-06 批准本地 Agent 接入方向，按 CLI、Skill、本地 MCP 的顺序推进，详见[设计](../design/agent-integration.md)与[阶段记录](agent-integration-plan.md)。主干已完成只读环境检查、APK 预检、加固后签名的执行前计划，以及经确认的最小共享资源校验接口；资源选择、协议/策略和所需壳文件已与请求模式绑定，工控资源缺失不回退。底层工具密码传递也已收紧；保留旧接口兼容，不改 GUI/壳、不新增联网或 CLI 发布 CI。旧只读计划仍标记不可执行，受控写操作使用独立入口；内部 macOS 实验闭环不等于正式 Agent 功能已交付，正式分发和客户端验收仍各设门槛。

受控执行已确认采用 [CLI 工作子进程隔离](../design/agent-executor.md)，首版仅 V1–V3、明确拒绝 V4，旧签名不变。暂存/无覆盖提交、有界协议、任务状态、私有材料及 macOS 原生停止/父死租约已通过组件验证。默认关闭的 `agent-executor` 开发特性已接通统一计划、工作入口及父端提交，真实小包和约 407 MiB 的 ClassIn 包完成加固、签名、验签/证书及独立 SDK 对齐核对，原包不变；另以小包验证执行异常、内部取消/超时、材料变化和无覆盖提交，并补充执行器及 Java/keytool 的阶段身份约束。检查路径、摘要及物理文件身份，持续替换或链接改向阻断交付，但不承诺完整 JDK 冻结或同权限恶意隔离。该闭环仅验证 macOS、Java 17，未安装运行，不作性能或全系统兼容结论；双重异常退出和逃组仍不在自动清场保证内。

已确认并接入源码开发特性的 [单任务命令契约](../design/agent-cli-contract.md)：独立 `shield agent plan/protect`、受控规划、执行前匹配摘要、统一逐行 JSON、信号与可选标准输入取消、输出读端断开和有界收尾。真实小包验证规划→执行、配置漂移拒绝及执行阶段取消通过，旧命令不变。本阶段已集中审查，补齐最后复核取消、矛盾终态和发送失败的边界回归，并随 PR #152 集中合并。

维护者已确认 CLI 与 GUI 同包分发、独立运行、共享工具和双资源，不新增独立 Release 资产。主干已接入 macOS `.app` 共包构建与现有发布入口，应用内 CLI 显式启用执行实验特性；在源码目录外的中文/空格路径完成真实小包规划、加固、签名、证书/独立 SDK 对齐及应用未改动检查，GUI 未启动。普通 CLI 源码构建默认行为不变，当前公开安装包没有改变。当前 Agent 也已按技能指引实际完成显式接入，该阶段审查和合并已完成，不要求再另开会话重复验收。Linux/Windows、Intel/通用架构及额外 JDK 继续保留各自原生门槛，不增加日常重型 CI 或提前宣称三平台支持；后续 MCP 共包已在开发分支显式接入，状态以上方最新记录为准，不将原 CLI 验收自动视为 MCP 验收。

官方 Skill 改为根目录 `skills/mocika-shield/` 独立分发，README 提供入口；不随 App 携带、不影响 App 构建，CLI 与 GUI 共包保持不变。技能维护自身版本及 CLI 协议兼容范围，通过本次路径、专用宿主变量或 PATH 定位命令，无效明确配置不回退，歧义请用户选择。用户按 Agent 或技能管理工具安装和更新，路径/签名资料在技能之外保留；不自研安装升级器、不在任务中自更新。说明见 [Agent 接入](../ops/agent-setup.md)，设计、过程和行为场景分别归位。[当前会话显式使用验收](agent-session-validation.md)已覆盖正常执行、解包阶段 Ctrl+C、缺凭据/输出占用/计划漂移的停止和模拟升级；早退清理状态保守未确认已记录，不改判成功。自动发现、其他 Agent 与客户端按钮行为另行补测；后续 MCP 独立实施，不塞进 Skill 或为其提前发布新版本。

整包免解压、二进制 Manifest 直接修改及未变 ZIP 条目原始复制仅保留为后续研究。现有基线已经确认重建成本，但尚不足以证明替代 apktool 的兼容性与收益，不修改正式主流程。若以后启动，须独立方案、受限原型、可靠回退和真实产物安装/运行验收，不沿用签名阶段的局部提速结论。

## 后续候选

候选方向不等于已排期版本；只有需求、依赖条件和验收资源同时具备后才进入下一版本。

| 方向 | 当前状态 | 进入条件 |
|------|----------|----------|
| 发布供应链完善 | 可先做基础项 | 补充产物来源证明、依赖清单和可追溯记录，只放发布流程；签名与 macOS 公证仍需账号、证书及维护投入 |
| AAB 正式支持 | 条件受阻 | 已有单 base 模块实验，仍需 Google Play 账号、Play 应用签名和内部测试轨道真实闭环，见[AAB 可行性结论](../design/aab-feasibility.md) |
| 工具链进一步轻量化 | 基线已取得，后续研究暂不实施 | 原始条目复制与二进制 Manifest 处理须另行验证兼容性、收益及可靠回退，不直接替换 apktool，见[设计](../design/toolchain-modernization.md) |
| 可选资源保护 | 需求驱动 | 有真实用户场景、显式资源清单与应用侧读取接口，不用 Hook 透明拦截，见[资源保护研究](../design/asset-protection.md) |

## 已暂停或停止的方向

| 方向 | 状态 | 结论 |
|------|------|------|
| API 29 以上完整内存 DEX | 暂停产品接入 | 真实大 APK 长期内存性价比门禁未通过，不预占新版本，见[内存 DEX 设计](../design/memory-dex-production.md) |
| DEX 结构与方法代码分离 | 停止产品接入 | 现有公开运行时仍需完整 DEX，继续依赖高风险私有运行时或独立虚拟机，见[代码分离研究](../design/dex-code-separation.md) |
| ART/系统 Hook、自修改代码、可写可执行内存 | 禁止 | 与多版本兼容、安全软件风险和项目安全边界冲突 |
| 在线加固、移动端或批量加固 | 不在当前计划 | 保持本地离线桌面定位，不托管 APK、证书或密码；建议不等于排期 |

## 执行与交付规则

- `main` 始终可发布，使用临时 `feat/*` 或 `fix/*`，合并后删除；不新增长期 develop。
- 稳定版反馈持续观察，但只有可复现高优先级缺陷抢占开发，不把观察期作为实现前置条件。
- 一个版本聚焦一个主题，不把预检、运行时安全、AAB 和工具链重写混成一次发布。
- Alpha 完成计划能力，Beta 起冻结功能与协议，RC 只修阻塞问题；不为补丁机械走完整预发布序列。
- 一个完整阶段形成代码、测试和文档后再提交，不因细小修改堆积 PR，不新增日常重型 CI 或 CLI 发布包。
- 不新增 APK 联网、云端业务处理或原始日志上传，不擅自修改用户 Java、Root 或证书。
- 已完成内容进入 Release Notes、历史档案和专项设计，不继续堆回当前任务。
