# 提交信息规范

所有提交信息必须遵循以下格式：

```
<类型>: <简短描述>
```

## 类型列表

| 类型 | 含义 | 说明 |
|------|------|------|
| `feat` | 新功能 | 引入新功能，通常影响用户行为 |
| `fix` | 修复 | 修复 bug，解决错误或异常行为 |
| `docs` | 文档 | 仅修改文档（README、注释等） |
| `style` | 代码风格 | 仅调整格式（缩进、空格、分号等），不影响逻辑 |
| `refactor` | 重构 | 代码重构，不新增功能也不修复 bug |
| `perf` | 性能优化 | 提升性能，如减少时间/内存消耗 |
| `test` | 测试 | 增加/修改测试用例 |
| `build` | 构建系统 | 修改构建流程、CI/CD 配置、依赖、预构建产物等 |
| `ci` | 持续集成 | 修改 CI/CD 配置文件或脚本 |
| `revert` | 回滚 | 撤销之前的提交（需包含 `Reverts commit <hash>`） |
| `chore` | 杂项维护 | 日常维护，如更新依赖、清理临时文件、版本号升级等 |

## 示例

```
feat: 支持 V3 签名提取
fix: 修复 Manifest 多行属性解析失败
docs: 更新 BUILD.md 中的 NDK 版本说明
refactor: 提取签名逻辑为独立模块
chore: 升级 zstd 依赖至 0.13
```
