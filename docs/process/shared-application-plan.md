## 当前补充修复：用户名环境缺失

维护者已要求修复实际 Agent 调用发现的用户名变量缺失问题。边界见设计中的密文兼容章节；本批不发布、不改变加密写入格式或真实资料，使用当前仓库的独立修复分支，完成后集中提交。

- [x] 复核实际会话失败与环境对照证据，确定是同一库的派生上下文不一致，不是证书查询／路径别名问题。
- [x] 记录共享应用库内的最多双候选读取方案，保留原写入、回滚、路径／HOME 和整条记录一致性边界。
- [x] 实现私有密文上下文与 Unix 有界系统账户查询，不扩大公开 API 或给各入口补环境。
- [x] 纯规则和真实子进程覆盖有／无用户名交叉读取、旧写入兼容、混合密码拒绝、坏密文及原记录／绑定不变。
- [x] 默认及 MCP 相关回归、严格检查、完整 macOS `.app` 和当前 Agent 原始 Node 环境的真实签名通过。
- [x] 同步实际结果并集中交付本批修复提交／PR；实际编号以仓库记录为准，合并另行确认。原生宿主注册和其他平台实机验收仍独立记录，不自动发布。

本批架构为共享库内的局部兼容扩展：私有 `SecretKeys` 拥有原写入密钥及最多一个只读候选，密码编码不变；私有账户模块仅封装 Unix 当前有效账户的线程安全查询，固定缓冲上限 64 KiB，失败不猜账户。Unix 显式依赖工作区已有锁定的 `libc`，锁文件仅增加该依赖关系，无依赖版本升级。SQL、绑定算法、GUI／CLI／MCP 的公开协议、壳和发布流程不变，无新 crate、全局环境修改或迁移任务。

首轮源码 MCP 常规回归有 4 项通过、1 项失败、2 项忽略，第三次签名返回 `TRUSTED_FILE_CHANGED` 而非预期的 V4 拒绝；当时多个构建／检查及后续同特性测试构建并行，开发 CLI 位于可被重建的同一路径。该门禁正确阻断，未放宽可信文件检查、错误断言或任务期限；构建结束后原样独立重跑，最终 5 项通过、2 项保留条件忽略，82.04 秒。首轮未额外捕获具体文件改写时刻，不扩大宣称所有偶发问题根因均已清除；完整包和当前 Agent 成功证据不代替本次常规回归结果。

## 执行契约与状态

- 已确认目标：一个工具、多种入口；共享加固、签名、证书管理及业务偏好，CLI 显式保存的资料可在 GUI 读取，反向亦然。
- 已确认架构：新增 `shield-app` 共享应用库，业务用例依赖 `shield-core`，GUI／CLI 依赖应用库；不新增服务或反向引用。维护者已明确选择推荐方案。应用库已承载证书用例并复用核心工具／诊断，不为未来功能预加依赖。
- 工作区：沿用 `feat/local-mcp`，保留前期未提交 MCP 代码及验收证据，不建新 clone／worktree、不先发布当前隔离形态。
- 数据：实现与自动回归使用显式隔离目录及合成证书。后续桌面补测获维护者单独授权使用真实资料库，仅新增合成测试记录、临时调整并恢复业务偏好；不修改原有证书材料，不更改 Java 或宿主全局配置。清理测试记录另行确认。
- 非目标：Android 壳／DEXB／NDK、GUI 换框架、TUI 实现、网络服务、统计采集扩展、全套执行器重写、独立 CLI Release、每次提交的重型 CI。
- 版本：公开稳定版继续 1.4.3，暂不预占版本，不为目录提取机械发布。新 workspace 成员实施时必须纳入版本同步脚本和其测试。
