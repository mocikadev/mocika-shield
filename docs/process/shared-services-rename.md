# 共享应用服务库重命名

2026-11-09，维护者确认将共享应用库统一为 `shield-services`，避免 `shield-app` 与 `apps/` 中的可运行应用混淆。`runtime` 容易误指 Android 壳的运行时加载，不采用。此处“服务”仅为本地库职责，不新增后台服务。

## 范围与任务

本批为跨工作区的命名调整，不拆分／合并 crate，不改变依赖方向、状态所有权、业务 API 或发布边界。以证书生命周期 PR #158 为基线独立提交；未经另行确认不合并该 PR，也不发布。

- [x] 调查 workspace、GUI／CLI 依赖、测试、脚本、CI 和文档引用；确认真实资料和密码派生不依赖 crate 名称。
- [x] 将目录改为 `crates/shield-services/`，包名与依赖改为 `shield-services`，Rust 引用与文档测试改为 `shield_services`。
- [x] 同步版本脚本、Makefile、原有 CI 命令和当前架构文档；历史执行证据保留旧名并标注，不升级版本或第三方依赖。
- [x] 核对机械差异、锁文件、持久化上下文和无遗漏引用；运行默认与开发特性回归、严格检查及脚本检查。
- [x] 构建完整 macOS `.app` 并验证包内调用；不启动 GUI 或重复未变的 Android 系统矩阵。
- [x] 集中一个重命名提交／PR，实际编号以仓库记录为准；不混入功能改造，不自动合并或发布。

应用标识、`config.toml`、`shield.db`、`keystores/`、密文派生、已有证书 ID、CLI 命令与输出格式均保持。`shield-core` 继续提供 APK 底层能力，GUI／CLI 调用共享服务，Skill／MCP 继续调用 CLI，不增加兼容转发 crate 或旧名别名。

## 验证记录

`cargo metadata --offline --locked --no-deps --format-version 1` 成功，仅有新包名，旧目录已不存在。移动后的 24 项文件逐一与基线做名称替换对照，除库入口职责注释外内容相同；目录定位、密文派生与写入、SQL／托管发布等实现不变。构建前锁文件逐字核对只有三个本地包名及依赖引用替换；构建后 Cargo 自动重排包段和依赖顺序，最终按包段／依赖排序规范化复核仍只有改名变化，无版本、第三方依赖或校验值变化。

默认 `cargo test -p shield-services -p shield-cli -p mocika-shield --offline --locked --quiet` 通过：服务库 56 项单元、1 项密文进程回归、4 项共享状态进程和 4 项编译约束；GUI 后端 94 项、CLI 单元 85 项及相关命令／管理／签名／加固集成回归。原条件忽略项不计通过。执行开发特性单元 107 项、MCP 特性单元 140 项通过，各有 17 项原条件忽略；服务库／CLI 默认及 MCP 特性全目标严格检查通过，未扩张为 GUI 全量严格检查通过。

脚本测试 92 项通过，版本／共包脚本语法、`make -n test`、格式及差异空白检查通过。首次格式检查因新名称导致三处导入排序／换行变化而停止，执行现有格式化后回归通过；辅助核对脚本最初发现本机 Python 不含 `tomllib`，改用更严格的逐字替换对照完成核对，没有安装依赖或改变工程配置。CI 仅替换已有手动完整检查中的包名，没有新增作业、触发条件或日常重型检查。

原 `scripts/build-macos-app.sh` 生成新的完整 arm64 `.app`，前端类型／生产构建、GUI／CLI、JAR 与双资源比对、内层及整包临时签名验证通过。包内 CLI 在源码外中文空格路径显式运行 `certificates::真实创建导入校验签名删除在同会话完成且文件保留` 专项，1 项通过、11.82 秒；创建／导入、失败校验恢复、默认切换、真实签名、同名不覆盖及删除保留文件继续使用原断言，其余真实专项不冒充此次已运行。

当前 Agent 另使用重命名前保留的同一份合成测试库和证书，将新完整包复制到独立中文空格路径，不提供 `USER/USERNAME` 或密码环境，也不读取库内密码、重新导入或创建证书。经新包公开 CLI 查询原编号后实际单次签名成功，退出 0、标准错误为空；独立 V1／V2／V3 验签、SDK 16 KiB 对齐及应用签名通过。原数据库、证书文件和输入 APK 摘要全部与运行前一致，没有新增／删除证书登记或数据迁移，产物和临时应用保留在本次私有目录。

残余旧名仅在明确标注的历史过程及本次名称对应说明中。未改变应用标识、密码上下文、命令协议、版本、壳或 Skill；`services` 没有引入网络服务或后台进程。工作区成员数量及依赖方向不变，新增名称无兼容别名和重复转发实现；三平台原生构建、GUI 可视交互和宿主原生注册不因改名扩大验收声明。撤销本次命名提交即可回到旧源码名称，不需要迁移用户资料。
