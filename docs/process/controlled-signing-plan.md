# 受控独立签名实施与验收

独立签名于 2026-11-09 经 #155 合入，已随三平台 1.5.0-beta.1 预览包交付。用法见[接入说明](../ops/agent-setup.md)，业务契约见[设计](../design/controlled-signing.md)，最新平台结果见[验收表](agent-desktop-platforms-plan.md)。

## 已完成

- 核心检查未加固／DEXB v5 证书绑定，拒绝未知、截断、重名和冲突载荷。
- 非签名 ZIP 内容摘要保持业务条目，不忽略整个 META-INF；签名前后内容和目标证书独立核对。
- CLI `agent sign` 一次调用内部规划、签名、验签并无覆盖交付，`sign-plan` 仅用于显式预览。
- 仅接受共享证书 V1–V3；默认项或编号不明确时失败，不改偏好，不要求重新输入已保存密码。
- MCP `shield_sign` 沿用原共享模式、执行开关和证书范围，不新增计划调用、摘要回传或确认步骤。
- 进度、忙状态、状态查询、取消、超时、断开与未知停写共用现有执行器；没有第二套提交逻辑。
- Skill 已包含单次签名指引，仍独立安装／升级，不随 App 携带。

## 真实验收

使用自有 APK、JKS／PKCS12 临时证书和隔离资料，覆盖默认／编号／唯一允许项、普通包换证书警告、已加固包绑定一致／不一致、错误密码、V4 拒绝、预览及输出冲突。

源码和完整 macOS 应用均完成独立验签、证书／摘要、SDK 16 KB ZIP 对齐和业务内容保持；源码外运行的包内 CLI／MCP 自行找到资源，输入、资料与应用包未变。正常调用不依赖标准输入开启，也不需要前置计划。

停止专项实际挂起签名步骤并核对后代停止、取消／超时／断开无交付；提交前相关材料变化阻断，无关名称／备注／默认项变化不换证书。Linux／Windows 后续真实结果以平台验收表为准，不沿用 Mac 结果外推。

## 修复过的边界

- Hello 后、Start 前材料复核失败，须保留具体材料变化错误和停止要求，不能误覆盖为协议失败。
- V4 等普通规划失败在确认工作组和管道停止、私有目录回收后，应返回真实清理状态；没有证据仍为未知。
- 一次签名的组合调用共享同一绝对期限，但不能把这项规则误用到旧接口，改变其原计时边界。
- 已知交付、清理和未知回执分开记录，晚取消不删除成品，失败不自动换证书或重试。

用户名环境缺失的旧密文兼容已另在[共享服务记录](shared-application-plan.md#用户名环境缺失兼容)收口，不在各入口补环境或重新导入。宿主原生注册、按钮交互和 Android 安装启动不由本专项自动证明。

## 持续回归

保持普通／受控签名、共享／外置来源、不同计划版本及材料集合分开验证。完整阶段集中提交；只影响文档时不重跑签名或打包，不保留临时分支、日志路径和每轮重复测试总数作为长期说明。
