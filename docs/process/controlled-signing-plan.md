### 底层签名检查批次

已实现 `shield-core::inspect_signing_input`：流式计算非签名 ZIP 内容摘要，读取当前 DEXB v5 明文证书绑定，保持 APK 只读且不解密业务 DEX。只排除明确的 JAR 签名元数据，业务 META-INF、清单、DEX、资源和 Native 库均属于内容不变量；ZIP 顺序、压缩和签名块不作为业务内容。中央目录另查连续性，避免 ZIP 库折叠重名条目后漏检。取消检查点在分块读取和条目处理期间调用。

### MCP 单次独立签名批次

源码只增加一个 `shield_sign`，沿用共享模式、原执行开关和原证书范围。参数只有相对输入／输出及可选编号，不新增授权选项、计划调用、摘要回传、密码输入或确认。只读、外置执行、共享只读、共享执行的工具数分别保持 3／5／4／7，签名注解准确标为写入但不破坏已有文件，不将注解当成权限令牌。

职责仍按原模块分工：参数映射生成固定 `agent sign` 调用；签名编排单独处理选择和结果；会话以明确类型保存加固计划或运行中的签名记录，不能用空摘要伪造签名计划。单活动、容量、期限、未知停写及原状态查询共用。多项范围只通过原 CLI 脱敏查询选定范围内默认项，不在 MCP 复制 SQL／密码解密；唯一允许项直接固定。新签名组合调用使用同一个绝对期限，默认查询与签名不分别重新计时；原单次接口保留原计时边界。没有新增依赖、数据库、后台服务、网络或 GUI 配置字段。
