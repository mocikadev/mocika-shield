## 关键设计决定

- 核心规则归 `shield-core`，本地资料归 `shield-services`；GUI／CLI 只适配入口，MCP 不另写执行器。
- 父进程拥有期限、停止确认和最终提交权；工作进程只处理私有暂存材料。停止或提交状态未知时保留材料，不自动重试。
- 公共事件信封版本为 1；外置加固计划为 2，共享加固计划为 3，独立签名计划为 4。不同计划不能混用。
- 受控任务限 V1–V3；V4 明确拒绝。普通签名的 V4 支持不受此限制。
- 共享加固回传不含路径、Alias 或密码的绑定参数；执行固定原证书和有效参数，不重新选择默认项，不新增计划数据库。
- 安装包资源必须完整；缺失时不从源码、用户目录或网络自动补齐。不改系统 Java 或 Agent 全局配置。

执行器细节见[设计](../design/agent-executor.md)，原生文件／进程差异见[三平台适配](../design/agent-desktop-platforms.md)。

## 实际验证与限制

macOS 先完成自有约 641 KiB 样本的真实加固、签名、证书一致性、产物摘要和 SDK ZIP 对齐检查；另用授权的大样本验证约 407 MiB、32 个 DEX 的处理闭环。大样本调试流程约 14 分钟，不作为发布性能基线，临时签名副本不能用于正式业务覆盖升级。

异常专项覆盖预先取消、执行失败、执行中超时／取消、工作进程异常退出、材料变化、输出竞争和收尾不确定。真实协议结果与组件测试分别记录，不将默认忽略项计为通过。

三平台源码及实际安装包的最新证据统一维护在[平台验收表](agent-desktop-platforms-plan.md)，不在此重复每次测试数量。macOS 当前 Agent 的显式 Skill 使用和标准流调用已有记录；其他宿主的自动发现、原生注册、审批与取消按钮未逐一验证。

签名和 ZIP 对齐通过不等于 Android 安装、启动或完整业务通过；设备回归仍按[测试清单](test-checklist.md)选择受影响范围。

## 后续维护

- Beta 冻结新增功能；优先处理可复现故障。
- 定位／共享／受控／MCP 边界改变时，分别运行对应脚本或集成测试，不为纯文档回填重复完整打包。
- 完整包、平台和 Java 组合的新增承诺必须附实际证据，不能由其他平台结果外推。
- 当前未开放项只在[接入说明](../ops/agent-setup.md#当前工具与能力)维护一份；候选方向以[路线图](roadmap.md)为准。
