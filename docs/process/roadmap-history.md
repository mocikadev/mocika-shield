# 路线图历史档案

仅记录已交付能力、重要验证和停止决定。当前排期见[路线图](roadmap.md)，具体发布内容以对应 Release 为准；不保留失效的“当前阶段”和逐步待办。

## 1.5.0 预览：Agent 与多入口共享

2026-11-11 公开 `1.5.0-beta.1`，不替代稳定版 1.4.3。

- GUI／CLI 共用 `shield-services`、配置、证书及业务偏好。
- 三平台 GUI 共包受控 CLI／本地 MCP；Skill 位于根目录，独立安装升级。
- 支持共享受控加固、单次独立签名、证书生命周期及偏好管理，GUI 无需常驻。
- 首轮未公开构建的 Windows 准备脚本输出编码失败，经明确授权更新未公开标签，最终三平台发布成功；公开后不再移动标签。

实际包与源码专项见[平台验收](agent-desktop-platforms-plan.md)，使用与入口差异见[接入说明](../ops/agent-setup.md)。

## 1.4.3 工具链与对齐效率

2026-10-29 公开，标签指向 `2b74d7e`，最终发布构建 `40649340237` 成功；四个安装包、三份校验和及双语说明核对通过，见[发布记录](release-1.4.3.md)。

- 校准 Java／keytool 任务依赖：纯加固和已保存证书签名不额外要求 keytool，证书管理及自动签名前的指纹核对保留。
- 对已对齐、符合受限 ZIP32 资格的产物复用，先核对布局、CRC 和长度；未知或复杂布局沿用重写路径。
- 两个本机大包的先期独立签名对照约 24.5／26.6 秒降至 8.3／8.4 秒；最终资格检查复用约 1.95／2.05 秒，不是全加固或所有设备提速承诺。
- 修复 Bash 资源版本传递和 Windows 检查输出编码，三平台打包前检查双资源版本。不通过单改元数据掩盖错配。

完整 macOS 应用完成中文路径双 DEX 加固后自动签名、V1–V3、证书一致性和 ZIP 16 KB 对齐；未重复 Android 全系统矩阵。

## 1.4.2 中文兼容、工控混合 ABI 与壳特征治理

2026-10-26 公开，见[发布记录](release-1.4.2.md)。

- 中文路径／Alias 的 Java 输出与参数兼容、用户确认错误报告的有限证据补齐。
- 单包兼顾 4.4 ARM 工控与新系统主流 ABI；旧 armeabi 按明确排除意图处理，不宣称 4.4 支持 64 位或 x86。
- 同批 R8／JNI 映射、壳完整类名冲突检查，Native 最小导出与构建路径审计。
- Manifest 改用中性字段：新核心兼容旧资源，旧核心拒绝新协议；不双写旧字段、不改 DEXB／缓存身份。
- Worker 维护聚合修复：新旧表合并、跨版本去重、7／30 日窗口和 GitHub 数据失败隔离；独立部署，不因此新增桌面 RC。

用户已确认 rc.3 在 Android 4.4／6.0／10.0／11.0 正常。后续名称／字段治理另有 32／64 位真机、Windows 资源和 16 KB ARM64 证据；不能将 rc.3 反馈改写成新壳已经全矩阵实测。

具体方案分别见[混合 ABI](../design/android-4.4-mixed-abi.md)、[壳身份](../design/stub-identity.md)、[Manifest](../design/manifest-runtime-contract.md)及[中文兼容](../design/chinese-toolchain-compatibility.md)。

## 1.4.1 Java 工具探测

关联所选 Java 的实际 JDK 定位 keytool，兼容系统启动器、符号链接和 Java 8 的 jre 布局。保持 PATH 优先与原回退规则，不自动改用户默认 Java；真实用户环境仍需按系统和安装方式核对，见[探测设计](../design/java-tool-discovery.md)。

## 1.4.0 预检、诊断与使用体验

正式版交付见[发布记录](release-1.4.0.md)。

- 单 APK 风险预检、签名一致性阻断和可复制诊断。
- 加固页方案摘要／设置抽屉、直接编辑输出文件名、持久化业务偏好与证书选择。
- 版本化匿名失败阶段和原因统计；每份经用户确认发送错误报告。
- Beta.6 起按包名记忆加固／签名分享选择，成功后发送有限应用信息；与匿名统计独立。
- Manifest 用户个例缺样本时使用自建夹具调查，不把提议升级 apktool 或自建测试通过当作用户问题已修复。

后续缺陷分别按补丁版本处理，不因观察期阻塞其他独立维护工作。

## 1.3.0 缓存与环境保护

已交付 Native 库任务别名、签名保护的 DEX 缓存根摘要、整体重建、只读写入、每次启动检查和标准／严格保护。Java 8 证书／签名支持及固定双语 Release Notes 流程完成。

真机覆盖首次／缓存启动、Root ADB 下两种策略、篡改缓存重建和同签名升级。私有目录是普通未提权环境的隔离边界，不能保证 Root 下业务 DEX 保密。详见[运行时安全](../design/runtime-security.md)。

## 1.2.x 兼容修复与基础能力

- Android 5.0～6.0 Element 工厂注入、4.4 Dalvik 工控兼容及双 NDK。
- V2／V3-only 内容签名、MSHD 大载荷识别与核心重复加固拒绝。
- ARouter 首次扫描和跨加固方案升级缓存处理，Android 9 系统共享库优先。
- `extractNativeLibs=false` 的 Stored Native 与 ZIP 16 KB 对齐。
- 统一任务快照、可选自动签名、证书管理、密码加密和版本提示。

1.2.7 的工控用户确认核心运行正常，但未逐项测试全部业务；不能扩大到未知 CPU／厂商硬件。具体设备和发布审计保留在[测试清单历史记录](test-checklist.md#关键改动验证记录)。

## 研究结论与未交付项

| 方向 | 结论与重启条件 |
|---|---|
| 完整内存 DEX | API 31 以上独立候选有完整性／组件／恢复证据，但大 DEX 长期内存门槛未过，暂停进入 GUI |
| DEX 方法代码分离 | 离线抽取、认证载荷和逐字节恢复已验证；缺少符合安全／兼容边界的运行时恢复路径，停止产品接入 |
| AAB | 实验不等于正式支持；仍缺 Google Play 应用签名及内部测试轨道闭环 |
| 批量／在线／移动端加固、TUI | 不在当前实现计划；不因旧路线图曾列出就自动恢复任务 |
| 自定义 ART Hook／可写可执行代码／Native 自修改 | 不采用，不通过隐藏行为绕过安全软件检测 |

研究与测量的技术细节保留在对应设计文档；早期逐步任务和调试过程可通过 Git 历史追溯，不再复制整份旧路线图。
