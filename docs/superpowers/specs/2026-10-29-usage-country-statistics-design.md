# 匿名使用国家／地区统计设计

## 目标与边界

维护者希望了解桌面工具使用者的大致国内外分布。沿用匿名统计开关与随机安装标识，仅在 `/events/daily` 成功接收当天快照时，保存 Cloudflare 基于网络出口推断的国家／地区。不修改 GUI、CLI、加固核心、Android 壳、客户端协议、桌面版本或发布标签。

不保存原始 IP、省份、城市、经纬度或任意请求头，不关联应用分享包名、错误报告或自然人。地区是网络出口观察，不是实际居住地；代理、VPN、企业出口、地区缺失和未开启统计都会影响覆盖。历史数据不回填。

## 方案比较与选择

- 修改现有每日任务表：文件较少，但地区观察跨版本共用，而现有计数主键包含版本；会混合不同职责，并扩大既有写入失败范围。
- 独立国家／地区日表：多一次有条件写入，但能独立控制去重、保留、失败隔离与回滚。采用此方案，维护者已确认只改服务端并更新仓库说明。
- 新增公开地区接口或客户端字段：当前没有需求，不实施。直接通过既有授权查询 D1。

## 架构与契约

架构等级 L2：在现有 Worker 内增加 `usage-country.js`，负责国家／地区代码校验、附属观察写入及清理；`index.js` 只在原计数事务成功后调用，并将其纳入既有定时清理。不新增依赖、不复制任务聚合、不改变公开返回字段。

新增 `daily_usage_country`：

| 字段 | 含义 |
|---|---|
| `anonymous_id` | 现有随机匿名安装标识 |
| `observed_date` | 服务端接收时的 UTC 日期 |
| `country_code` | 白名单中的两位国家／地区代码 |
| `observed_at` | 首次成功记录的服务端 UTC 时间 |

主键为 `(anonymous_id, observed_date)`，日期索引支持查询与保留清理。当日第一次成功取得有效代码后固定；同日跨版本、重试或网络切换不覆盖。未知地区不写行，后续有效请求可以补齐当天观察。

只读取 `request.cf.country`，不从 JSON 或 `CF-IPCountry` 等客户端可传字段兜底。接受 ISO 3166-1 两位代码及 Cloudflare 可能提供的 `XK`；`XX`、`T1`、空值及非法代码视为未知。

仅当 `body.usage_date` 等于本次服务端接收 UTC 日期时写入。历史补传、未来日期和无效请求不产生地区观察；不得把本次网络出口伪装成过去日期的地区。原有计数事务失败也不写地区。地区附属写入使用独立错误边界，失败仅记录固定提示，不打印标识、代码、IP、正文或数据库异常，不改变原上报的 204 结果。

`USAGE_COUNTRY_ENABLED` 是维护者服务端开关，仅值为 `true` 时采集，缺失或其他值不采集；部署配置默认开启。关闭采集仍执行既有地区保留清理。

## 私有统计口径

维护 SQL 文件 `tools/stats-worker/queries/country-distribution.sql` 仅供授权 D1 查询，参数依次是起始 UTC 日期、结束 UTC 日期和需要排除的已登记自测标识（可空）。不将参数、匿名标识或地区明细写入公开历史。

- 活跃分母沿用新旧每日表中的匿名实例并集，在指定日期范围跨日期、跨版本去重；不使用请求数或任务数代替。
- 单日查询令起止日期相同；7／30 日窗口按各实例在窗口内最近一个有效观察日归属国家／地区，每个实例只计一次。
- 没有窗口内有效观察的活跃实例归入 `country_code = null`，展示为“未知”。不以窗口外地区推断。
- 同时返回总活跃、已定位实例和覆盖率。各组实例数之和等于同口径活跃分母；无活跃时返回空数组，覆盖率不伪造为 100%。
- 查询正常只表示能计算；上线初期旧日期没有地区是覆盖不足，不是没有海外用户。
- 保留含当天的 90 个 UTC 日期，按既有每日定时任务删除更早的地区行；清理执行前可能短暂多保留一个调度周期。既有每日计数、报告及应用分享的生命周期不变。

## 上线、兼容与回滚

先执行新增的 `0005_usage_country.sql` 增量迁移，再部署 Worker；同步 `schema.sql` 只用于新数据库，绝不向现网重放整个初始化或旧迁移。新增表不修改或回填任何历史数据。旧客户端协议和 204 响应保持不变，公开 `/stats/trend`、`/stats/summary` 不增加地区字段。

上线前记录当前部署版本、变量名及数据库结构；部署保留已有密钥、变量、绑定、域名与定时任务。生产验证只读，不伪造普通用户事件；未收到真实有效观察时如实记录“待自然上报”，不冒充失败或零覆盖结论。

紧急时用服务端开关关闭附属采集，正常计数继续，清理继续；必要时回滚到已记录的旧 Worker 版本，新增空闲表保留，不执行删表等破坏性回滚。若回滚旧代码，需另外保证新增表按保留口径清理。

## 验收

真实 SQLite 覆盖迁移保留旧数据、首次有效地区、重试／跨版本／网络切换、未知后补齐、请求头及 JSON 伪造、历史与未来补传、原计数或地区写入异常、UTC 日期边界、90 日保留边界、窗口与自测排除、公开输出隔离。完整 Worker 测试、维护脚本测试与部署预检通过后部署；不触发桌面三平台打包。
