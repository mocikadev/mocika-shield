# Beta.6 发布与应用分享上线任务

> 维护者已于 2026-09-18 指定按 `1.4.0-beta.6` 发布，并要求一并处理远端数据库与遗漏项。沿用已审查实现，不增加新功能；在当前工程分支执行。

**目标：** 发布包含应用分享的 Beta.6，并使对应 Worker/D1 接收链路可用，保留匿名统计和错误反馈兼容。

**架构：** 沿用独立应用分享协议及表，先增量建表，再关闭入口部署、验证旧通道，最后启用新入口。异常先关闭新入口，不删除旧表或回滚用户数据。

**技术栈：** 现有 Rust/Tauri、GitHub Actions、Cloudflare Worker/D1、固定 Wrangler 版本。

**设计依据：** [应用分享设计](../../design/application-usage-sharing.md)、[应用分享运维](../../ops/application-usage-sharing.md)、[发布流程](../../process/release.md)。

## 全局约束

- 发布标签固定 `v1.4.0-beta.6`，不得修改已公开 Beta.5 标签或发布内容。
- 现有 main 受保护，完整阶段一次提交/PR，必需检查通过后合并，再从 main 打标签；不绕过保护。
- 仅增量迁移 `0004_application_usage.sql`，不对已有库执行完整 `schema.sql`。
- 独立密钥只写 Worker secret，不打印、不写源码、客户端、文档或提交。
- 线上验证只用明确的自建测试包身份、随机专用编号；清理只按这些编号，不按日期或版本批量删数据。
- 保留旧 `ERROR_REPORT_RATE_SECRET`、`ERROR_REPORTS_ENABLED` 和 DB 绑定，部署使用 `--keep-vars`。
- 实际 UI/Tauri 自动签名与 Windows/Linux 原生运行仍是未完成的人工项，Beta 发布不能将这些写成通过；不扩造界面自动化框架。

## 回滚与剩余项

新接收异常时先将 `APPLICATION_SHARING_ENABLED` 设为 false，保留新增表与旧通道；客户端网络失败不影响任务。数据库恢复仅在确认损坏和范围后另行处理，不自动覆盖线上新记录。

真实桌面界面/Tauri自动签名及跨平台原生验证、首轮定时清理观察作为明确剩余项记录，不用“全部验收”概括当前证据。发布结束更新每项实际结果和版本/PR/流水线链接。
