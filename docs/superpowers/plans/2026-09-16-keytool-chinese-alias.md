# 中文证书 Alias 编码修复记录

初始修复随 1.4.0 Beta.4 交付。当前处理还包括后续 Windows Java 无损参数适配，见[中文兼容说明](../../design/chinese-toolchain-compatibility.md)和[工具适配设计](../../design/java-tool-adapter.md)。

## 原因与处理

keytool 输出编码与 Rust 解码不一致会使中文 Alias 乱码，继而匹配失败，并非字体或“不支持中文”。

初始修复统一 keytool 命令的语言及 UTF-8 文件／标准流编码，严格解码；不能用替换字符当作有效 Alias，也不根据乱码自动猜测原始值。完整链路仍须验证 Unicode 参数传递，不能只保证输出可读。PKCS12 按实际返回的 Alias 保存，匹配大小写不敏感。

## 实际验证

2026-09-16 在 macOS arm64，以 Java 8／17／25、UTF-8／GBK 模拟输出、JKS／PKCS12 及英文／中文／混合 Alias 共 36 组验证创建、识别、导入、重开数据库、APK 签名与指纹一致，原 keystore 不变。使用临时证书和自有 APK，未改系统默认 Java 或用户材料。

修复前 Java 8＋GBK 下英文可签名，中文在证书校验时匹配失败；修复后矩阵通过。该结果不是 Windows 原生代码页或真实用户个例确认，也不证明所有路径和证书组合兼容。

## 回归要求

- 检查创建、查询、校验、保存重开及签名，不只看界面文字。
- 无效 UTF-8 必须失败，不自动迁移已保存的乱码 Alias。
- Windows 扩展路径规范化、无控制台窗口与参数保真分别验证。
- 用户仍有问题时按实际系统、JDK、路径和样本定位，不用模拟环境结果提前关闭个例。

初始编码依据为 [OpenJDK JEP 400](https://openjdk.org/jeps/400)。临时日志路径、旧版测试数量和逐步提交指令不作为长期文档保留。
