# 统计口径与维护收口实施计划

> 执行方式：维护者已确认按建议执行，在当前工程内由主代理实施，按任务验证；整阶段形成一个提交与 PR，不另外克隆工程，不改桌面版本或发布标签。

## 目标与设计

设计依据：[项目维护统计](../../ops/project-statistics.md)。修正匿名安装实例跨版本重复计数，提供真正去重的近 7／30 个 UTC 日期窗口；维护脚本直接读取 GitHub 和 Worker，公开 Release 版本号匹配与未匹配数据分开标记，不声称能鉴定官方二进制或真实人数。

架构等级 L2：从 Worker 入口提取只读使用聚合到 `usage-queries.js`，复用新旧表去重规则；`github-summary.js` 仍只处理历史汇总接口的 GitHub 数据与部分不可用状态。Python 维护采集器根据同次 GitHub Release 列表标注版本，不让 Worker 统计查询依赖 GitHub。无新增依赖、表、迁移或客户端字段。

备选：只在手工查询中去重会保留错误公开口径；删掉汇总接口会破坏旧消费者。选择修正趋势并让原汇总接口可降级，保持成功时旧字段不变，GitHub 不可用时返回空值与明确可用性标志，数据库查询失败返回受控 503。

## 全局约束

- 桌面端、加固资源、rc.4、最低系统版本及既有标签保持不动。
- 不删除、回填或更改真实上报，不上传或公开匿名标识、应用包名和错误报告正文。
- 新旧表相同匿名标识、日期和版本优先第二代表；事件次数仍按版本求和，实例数跨版本去重。
- 周／月窗口含今日且今日未结束；不能用每日或各版本的实例数之和代替窗口去重数。
- 下载只排除校验和和草稿，不根据猜测扣除机器人或自测次数。
- 本地验证、整批复核与本地提交后部署 Worker；将线上记录补入同一本地提交后再推送一个 PR，避免为补记录强推公开历史。合并及正式版发布不自动进行。

## 复核重点

1. 同一实例同日切换两版、跨日使用仍只计一个窗口实例。
2. 遗留表与第二代表重叠不重复事件，空数据库窗口计零、缺字段不伪造零。
3. GitHub 403、超时或数据库异步失败返回受控结果，不泄漏上游正文或凭据。
4. 版本号匹配只取已公开 Release；未发布、自改、空版本不能当官方安装来源。
5. 公开输出和 stats 历史仅白名单聚合；历史快照不改写为新口径。
