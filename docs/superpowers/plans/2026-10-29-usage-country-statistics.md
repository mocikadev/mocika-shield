# 匿名使用国家／地区统计实施计划

> 执行方式：维护者已要求“制定方案、任务计划，然后执行”，由主代理在当前工程连续实施，使用执行计划技能逐项验证；阶段形成一个提交与 PR，不另建克隆或工作树，不自动合并。

**目标：** 在不升级客户端的情况下，增加仅维护者可查询的国家／地区分布。

**架构：** Worker 独立附属模块与日观察表，原使用计数事务不变。维护 SQL 去重查询，不新增公开接口。

**技术栈：** JavaScript ES 模块、Cloudflare Workers／D1、原生 Node 测试和现有 SQLite D1 测试适配器，无新增依赖。

**设计：** [国家／地区统计设计](../specs/2026-10-29-usage-country-statistics-design.md)。

## 全局约束

- 当前工程、单一阶段分支；GUI、CLI、Android 壳、客户端协议、版本及标签不变。
- 只读取 Cloudflare 提供的国家／地区代码，不保存 IP、省市、经纬度，不与包名关联，不新增公开输出。
- 同实例同 UTC 日首次有效地区固定、跨版本去重；不回填补传历史；保留含当日 90 个 UTC 日期。
- 国家／地区保存失败不得令已成功保存的原计数返回失败。
- 线上先增量迁移、再部署；保留既有配置与回滚版本，不制造生产测试事件，不删除业务数据。
- 遵循阶段提交偏好，任务之间不制造碎片提交；计划和执行证据随阶段一并提交。

## 复核重点

1. 过去／未来快照的有效出口不能错误归属为过去／未来地区。
2. 同一匿名实例在同日两版和多次网络变化后只能留一个日观察；窗口也只归属一次。
3. 缺失／伪造代码、UTC 跨日与附属数据库故障不得污染统计或中断主路径。
4. 旧数据库升级不丢原数据，公开响应不泄漏新表、标识或地区。
5. 90 日保留、自测排除、未知分组与空窗口不能改变总活跃口径。
