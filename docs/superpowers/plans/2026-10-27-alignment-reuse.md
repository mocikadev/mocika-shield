# 已验证对齐产物复用方案与任务

## 证据与决定

维护者已确认根据[真实 APK 基线](../../design/apk-processing-baseline.md)实施局部优化。两个大包独立签名约四分之三耗时位于对齐/整包重写；加固后签名还会再次执行同一对齐入口。本轮不跳过 apktool，不修改 DEX 压缩档位，不增加 GUI、配置、遥测或发布任务。

比较后选择最小实现：

| 方案 | 收益与边界 | 决定 |
|------|------------|------|
| ZIP 资格及解压内容校验后复用 | 同次加固后签名不再重压所有条目；仍需流式读取内容校验 CRC 和声明长度，不代表全面 ZIP 安全审计 | 本轮实施 |
| 未改变压缩条目原始复制并重排 | 可覆盖尚未对齐输入，但固定 zip 2.4.2 的公开原始复制接口不能直接指定对齐，且明确不校验 CRC；需自行处理布局或调整依赖 | 本轮不实施，不绕过校验或私用依赖内部接口 |
| 绕过 apktool 或修改压缩策略 | 影响 Manifest/资源或产物体积，兼容风险超出已确认的局部优化 | 暂缓 |

未对齐或 Native 压缩策略不匹配的输入继续使用既有重写路径；不是全部签名都能获得相同收益。不增加“相信已对齐”标志，不以用户声明或上一次缓存结果为依据。

## 架构与契约

初始判断为 L1；复核固定版本 ZIP 库时发现其会将中央目录同名记录合并，故调整为 L2 的私有边界：只读快路径资格检查独立放在 `zipalign/reuse_layout.rs`，负责保守核对 ZIP32 头部与条目连续性，不负责解压、写入或业务加固；父模块继续负责 CRC/长度、对齐策略与交付。GUI、CLI 和签名调用方式不变，不新增公开 API、依赖或可变状态。相对扩大为通用 ZIP 重写器，收窄资格判断并对未知布局回退是唯一符合本轮边界的方案；不使用依赖私有接口。

资格检查限定普通单磁盘 ZIP32、中央记录无去重遗漏、本地头与中央目录一致且连续的布局。前缀、条目间隙、APK 签名块、重复名称、数据描述符、ZIP64或未知标志不复用，仍走旧重写路径。此模块只读取固定长度头部、有界文件名和附加字段，不生成 ZIP 布局，也不替代 ZIP 库的解压/CRC 校验。函数按目录资格与单条目一致性划分，布局检查不能将普通文件内容校验错误吞成成功。

- 先读取 ZIP 条目头，确认所有非目录条目的既有 4 字节/16 KB 偏移，以及请求的 Native 压缩策略；不满足时走旧路径，避免对必然重写的包重复解压。
- 候选复用的非目录条目必须逐条流式读到 EOF，触发库内 CRC 校验，再确认实际读到的字节数等于声明长度；文件内容损坏报错且不修改原文件，不在数据错误时回退成成功。空目录只接受 Stored、零长度、零 CRC，否则回旧路径规范化。
- 未对齐输入继续逐条读出和重压，增加声明长度一致性检查；压缩方式、Native Stored 要求、Archive 注释和权限沿用已有策略。
- 重写后的临时产物先验证对齐及 Native 策略，再通过 tempfile 的替换操作交付；不先删除原文件，避免校验或交付失败破坏输入。
- 快路径不改一个字节，包含合规 ZIP 附加字段；APK 签名块等复杂布局按上述规则回退。它不鉴定签名或承诺应用能运行，后续签名校验职责不变。

## 验证边界与停止条件

不重新运行每个大包的完整解包/重建基线：本轮只影响对齐，复用既有产物做同输入对照即可。性能结论仅针对本机样本，不推断 Android 启动速度或其他平台。使用临时测试证书的业务 APK 只做离线签名/布局验证，不安装、不覆盖业务应用，也不宣称其运行时签名绑定已通过。

不满足受限资格的布局继续走完整重写；任一路径的普通文件内容损坏或输出校验失败都拒绝成功。重复名称、非规范空目录等布局沿用旧流程归一化处理，不宣称新增了通用 ZIP 安全审计，也不保证清理压缩流尾随字节。若原始复制需要手写 ZIP 写入布局、引入依赖升级或更改公开契约，停止扩大范围，另行评审。保留原流程入口，不削弱 `extractNativeLibs=false`、16 KB 对齐、证书指纹绑定或签名校验。


本表不是先前“原始 APK 独立签名”基线的重复测量：输入已改为同一份已对齐产物，不拿之前 30/35 秒直接计算收益。也不是加固总流程提速约三倍；资源重建仍未改变。单次、本机、执行顺序与文件缓存限制保留，不能承诺所有平台或 APK 的收益。

## 架构复核与交付状态

### 2026-10-28 复核修补方案与任务

复核已构造并对照旧实现：错误空目录 CRC、本地附加字段内部长度越界会被首期快路径原样保留，外部 `unzip -t` 报错；旧重写路径会规范化。另发现条目磁盘号缺少限制，以及解压 EOF 不证明压缩数据范围内没有尾随字节。本轮先修补资格边界再交付，不修改版本、界面、壳或发布流程。

架构判断为 L1：规则仍归 `zipalign/reuse_layout.rs`，只增加私有的有界附加字段检查函数，父模块继续管理数据读取与替换。既有私有模块足以承载，不新增解析依赖、通用 ZIP 解码器或公共 API。

- 附加字段：分别按本地头、中央头声明的有界区间检查每个字段的头部与载荷长度；残缺头、越界载荷和 ZIP64 字段不进入快路径。完整未知字段仅核对结构，不解释其语义；不要求本地与中央附加字段相同，对齐填充本来就可能只在本地出现。
- 空目录：仅接受 Stored、压缩/解压长度均为零、CRC 为零的形式；其他形式回旧重写路径规范化。普通文件内容 CRC/长度错误仍报错，不借回退吞掉错误。
- 磁盘号：除 EOCD 外，每个中央条目的起始磁盘号也必须为零，否则不复用。
- 压缩尾随字节：本轮明确保留现有解压器语义，不另行解析 DEFLATE 或重复解压。CRC 和长度仅认证解压内容，不能证明声明压缩范围被精确消耗；允许存在解码器忽略的尾随字节，不将本优化描述为通用 ZIP 完整性/安全审计或隐蔽数据清理。增加行为测试记录边界；若以后要求清理，需单独评审流消费校验方案。

职责由父模块的对齐/内容校验和私有子模块的只读资格守卫构成；不新增生产依赖、公开 API、状态缓存、协议或反向调用。原有写入器不扩大成通用 ZIP 重写器，异常布局保留原路径；默认 Java、业务证书与 APK 均未修改。Windows/Linux 原生环境未在本轮实测，临时替换的跨平台行为基于既有 tempfile 公共接口，不将 macOS 结果扩张为原生三平台验收。
