# 匿名使用统计方案

Mocika Shield 默认开启匿名使用统计，用于了解实际启动、加固和签名使用情况。用户可以在设置中关闭统计。

## 数据范围

客户端按日期在本地累计启动、加固和签名次数。服务端以随机匿名 UUID 和日期为唯一键保存每日汇总，同一天的后续上报覆盖为最新累计值，不会重复计数。上传字段仅包含随机匿名 UUID、日期、应用版本、系统平台、CPU 架构和功能计数，不包含 APK、路径、包名、证书、密码或项目内容。

## 数据生命周期

应用启动后立即上传当天累计快照，避免只启动一次的用户永远无法计入活跃设备。加固和签名事件先写入本地，再经过短暂防抖合并上传，避免一次操作产生多次网络请求。

当天记录上传成功后继续保留，用于承接后续事件并再次上传完整累计值；此前日期的记录上传成功后删除。上传失败的数据保留并在后续同步或启动时重试，本地最多保留 30 天未上传记录。统计服务异常、网络超时或额度耗尽均不得影响应用启动、加固和签名。

## 服务端

数据通过 Cloudflare Worker 写入 D1 数据库。统计服务地址为：

`https://mocika-shield-stats-api.xuechao-suo.workers.dev`

公开趋势与当前汇总接口使用短时缓存，降低 D1 读取和 GitHub API 请求量。Worker 可选配置只读的 `GITHUB_TOKEN` 密钥；未配置时使用 GitHub 公开接口匿名额度。

部署或升级统计服务时执行：

```bash
cd tools/stats-worker
wrangler d1 execute mocika-shield-analytics --remote --file schema.sql
wrangler deploy
```

如需配置只读 GitHub 令牌，使用 `wrangler secret put GITHUB_TOKEN`，不得把令牌写入 `wrangler.toml` 或前端代码。

## 维护统计口径

匿名使用数据仅代表开启统计并成功上报的客户端，不代表全部用户。每日维护快照只纳入已经结束的 UTC 日期；采集失败时明确标记不可用。项目不公开展示匿名使用、下载、访问或仓库关注趋势。
