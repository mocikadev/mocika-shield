# 项目维护统计

本文档说明 Mocika Shield 仅供维护者使用的聚合统计方案。项目不再提供公开统计看板，README 和 GitHub Pages 均不展示下载、星标、访客、克隆或匿名使用趋势。

## 目标与边界

维护统计用于辅助判断：

- 各平台发布包的大致下载情况
- 新版本发布后的下载变化
- 仓库近期访问趋势
- 开启匿名统计的桌面工具产生的启动、加固、签名和固定失败阶段汇总

这些数据都不是精确用户数：

- 下载次数包含重复下载和维护者测试下载
- GitHub 独立访客与独立克隆是最近 14 天窗口内的近似值
- 克隆数据可能包含机器人、CI 和重复拉取，只作为排查线索
- 星标代表公开关注，不等于实际使用
- 匿名数据只覆盖允许并成功完成上报的客户端
- 版本号由客户端声明；匹配公开 Release 只说明版本号相同，不证明使用官方安装包。未匹配也可能是自行构建，不据此判定恶意请求。

服务端可能同时收到其他构建的兼容协议请求。活跃、启动、加固、签名、地区、应用分享和错误报告的未筛选总量，均描述**全部成功接收的客户端记录**，不能直接写成本项目用户或官方产物使用量。维护快照的 `population_scope=all_received_installations` 与 `source_attribution=unverified_client_version` 明示该边界；历史未含标记的快照不回填。未匹配版本保留在原统计中，不能未经证据删除或指定来源。

## 当前维护查询与计数规则

查看最新状态时分别查询两个来源，不使用历史快照冒充实时数：

- GitHub API：仓库关注、公开 Release 安装包下载和 Traffic。校验和及草稿不计下载；不凭下载分布扣除机器人或维护者下载，无法可靠识别时保留原始次数并说明限制。
- Worker `/stats/trend`：匿名日趋势、版本分布、固定失败分类和滚动活跃；必要时经现有授权直接查询 D1。应用分享和错误报告只走维护者私有 D1 查询，不进入公开趋势或 stats 历史。
- 国家／地区分布：仅通过私有 D1 查询服务端日观察，使用现有匿名实例去重口径；未知进入分母并同时报告覆盖率，不进入公开接口或 stats 历史。见[国家／地区统计运维](usage-country-statistics.md)。
- 任何来源失败只将对应指标标记不可用，不把不可用填零，不让 GitHub 异常影响匿名入库。

日活 `active_devices` 实为随机匿名安装实例数：对合并后的数据按 UTC 日期、`COUNT(DISTINCT anonymous_id)` 去重。近 7／30 日的 `activity_windows` 在整个窗口内独立去重，含今日，日期范围由 `start_date/end_date` 明示；与只保存完整日的日趋势不同，窗口是采集时的即时结果，不能解释为完整周或自然月。

第一、二代表同标识、日期、版本重叠时优先第二代表；不同版本的事件次数保留相加，实例数去重。第三代来源表迁移部署后，合并其独立事件分段，不抹掉同日旧分段；跨表、来源、版本的活跃仍按匿名标识去重。各版本日活之和、每日活跃之和均不能作为总日活或周／月活。一个实例可能使用多版本，不等于一个自然人或组织；不能精确剔除未登记的自测。

维护快照每个 `version_trend` 行新增 `release_version_match`：`true` 匹配本次采集的已公开 Release，`false` 未匹配，Release 列表不可用时为 `null`。保留完整版本号，查看时将匹配与未匹配分开列出，不把二者解释为已鉴定的官方／非官方安装来源。

相同匹配标记也适用于失败阶段、原因与分类覆盖行。需要按版本范围比较时，使用私有 [`usage-version-scope.sql`](../../tools/stats-worker/queries/usage-version-scope.sql)：四个参数依次是起止 UTC 日期、成功获取的公开 Release 版本 JSON 数组（去除标签的 `v` 前缀、排除草稿）、待排除自测标识或 `null`。版本列表查询失败时不执行筛选，也不传空数组冒充查询成功。返回全部接收、匹配版本、未匹配版本三组；每组跨日和跨版本独立去重，同一实例可跨组，组人数不可相加。查询不返回标识或改写历史。

应用分享和错误报告使用私有 [`report-version-scope.sql`](../../tools/stats-worker/queries/report-version-scope.sql)，三个参数依次是起止 UTC 日期、公开版本 JSON 数组；分享按 `success_date/tool_version`、报告按服务端 `received_at/app_version` 统计。包名在每组内独立去重，跨组可能重叠，不能相加。查询只返回数量，不输出包名或报告正文，也不将这两类私有明细写入快照。国家／地区的未筛选结果仍是全部接收实例的网络出口分布，不据此推断本项目用户的实际所在地。当前协议不提供来源认证，不新增硬件标识、联网校验或客户端内置“认证密钥”来伪造可信来源。

`active_devices_definition=distinct_installation_per_utc_period` 标识新口径。旧客户端仍可正常上报；旧接口缺少窗口时 `activity_windows_available=false`、`activity_windows=null`，不以日趋势加总补算。已有历史快照不回填，新旧口径须按该标识区分。可用字段缺失和没有使用记录不是同一件事。

### 构建身份查询

新实现自动记录工具自身的构建名称、应用标识和可用提交号，不采集进程列表或路径。实现及部署清单见[构建身份隔离](../design/telemetry-build-identity.md)。**生产迁移和 Worker 部署已完成；首个携带身份的客户端目标为 Beta.3，正在发布准备；Beta.2 及更早客户端没有这些字段。** 历史继续按版本分析，不能回填成本项目身份。当前新表为空，不能把身份匹配组尚无记录解释为本项目没有活跃。

维护者可运行已通过生产只读验证的私有 [`usage-source-scope.sql`](../../tools/stats-worker/queries/usage-source-scope.sql)：参数依次为起止 UTC 日期、成功获取的公开 Release 版本 JSON 数组、当前本项目产品名称、应用标识、排除自测标识或 `null`。名称和标识从所分析发行版的打包配置核对，不以页面标题或硬编码的“官方”标记替代；版本列表失败时停止分类查询。

结果为全部接收、本项目身份匹配、其他声明身份、旧／未知来源。`identity_coverage_percent` 是窗口内至少有一条身份记录的实例比例，不代表该实例所有操作都已归属；各组实例可能重叠，不可相加。名称、标识和版本匹配不是官方来源认证。

[`usage-source-versions.sql`](../../tools/stats-worker/queries/usage-source-versions.sql) 的三个参数为起止 UTC 日期、排除自测标识或 `null`，返回声明名称／标识／版本／提交号的聚合，不返回匿名标识。需要整个来源跨版本去重时使用前一查询，不能把明细行人数相加。上述结果不进入公开趋势或 `stats` 快照；旧 Worker／缺表失败标为尚未部署或不可用，不报零。

### 兼容汇总接口

`/stats/summary` 仅保留给旧消费者，不是维护查看的主入口。GitHub 仓库和下载查询分别有超时与失败隔离；失败字段为 `null`，`availability` 指明来源状态，使用统计正常时仍返回 200。D1 查询异常返回受控 503，不缓存错误响应，不公开原始异常。

2026-10-26 已用实时 Tail 确认旧接口 500 的直接原因：Worker 没有 GitHub 密钥，上游请求出现 403，入口直接返回 Promise 而未等待，导致异步拒绝绕过 `try/catch`。D1 与趋势接口当时正常。修复不要求增加 GitHub 令牌，不改变上报地址和数据库结构。部署与验证记录见[本次维护计划](../superpowers/plans/2026-10-26-maintenance-statistics.md)。

## 数据与存储

| 指标 | 来源 | 用途 |
|------|------|------|
| 发布包及平台下载量 | GitHub Releases | 观察版本和平台需求 |
| 访问与克隆 | GitHub Traffic | 维护分析，不公开展示 |
| 星标、复刻、未关闭事项 | GitHub Repository | 维护分析 |
| 启动、加固、签名与固定失败阶段计数 | 匿名统计 Worker / D1 | 按桌面工具版本观察使用趋势与异常集中情况 |

校验和文件不计入发布包下载量。采集结果保存到 `stats` 分支的 `data/history.json`，不进入 `main` 提交历史，也不生成 HTML、SVG 或其他公开页面。

## 自动化流程

工作流每天北京时间上午 9 点运行，也支持手动执行：

```text
读取 stats 分支历史数据
        ↓
调用 GitHub API 和匿名统计接口
        ↓
按 UTC 日期追加或替换当日快照
        ↓
保存 data/history.json
        ↓
提交并推送 stats 分支
```

同一天重复执行会替换当天快照。Traffic 权限不足或匿名统计接口不可用时，对应数据明确标记不可用，不会错误写成零，也不阻断其他指标采集。

## 权限与安全

如需读取 GitHub Traffic，使用只限本仓库、只读管理元数据的细粒度令牌，并保存为 Actions 密钥 `STATS_TOKEN`。不要复用维护者日常使用的宽权限令牌。

匿名统计保存随机匿名标识、日期、桌面工具版本、平台、架构和聚合计数；新客户端另保存工具自身的构建名称、应用标识和可空提交号。失败仅保存固定操作阶段，不保存错误原文。不包含 APK、证书、密码、路径、APK 包名、最终用户标识或项目内容。随机标识只用于同一桌面工具安装实例的日期／窗口去重，不读取硬件、账户、网络或系统唯一标识。Worker 令牌不得写入前端、仓库文件或公开响应。

国家／地区是独立附属观察，仅保存既有匿名标识、观察 UTC 日期、两位国家／地区代码与首次记录时间；不保存原始 IP、省市或经纬度，不与应用分享包名关联。沿用匿名统计开关，保留含当日 90 个 UTC 日期，同日跨版本只留一条。历史不回填，窗口按最近有效观察归属，必须显示未知与覆盖率；不能据此判断真实所在地或自然人数。

`/stats/trend` 始终保留按日期的 `data`，新版响应额外提供 `versions` 与 `failure_breakdown`。维护脚本遇到旧响应或细分字段缺失时，明确写为不可用，不将历史空白解释为零或重新归属版本。

## 本地验证

```bash
GITHUB_TOKEN="$(gh auth token)" \
python3 scripts/project_stats.py \
  --repository mocikadev/mocika-shield \
  --history-file /tmp/mocika-stats/history.json \
  --output-dir /tmp/mocika-stats

python3 -m unittest scripts.tests.test_project_stats
```

生成结果应仅包含 `data/history.json`。
