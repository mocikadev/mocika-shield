# 项目关注度统计

本文档说明 Mocika Shield 的公开项目统计方案、数据口径、自动化流程和维护方式。统计目标是帮助维护者了解项目关注与实际使用趋势，不把下载次数或匿名汇总包装成精确用户数。

## 目标与边界

统计系统回答以下问题：

- 各系统平台的发布包大致被下载了多少次
- 新版本发布后下载量是否增长
- 仓库近期有多少访问和完整克隆
- 星标、复刻和未关闭问题数量如何变化
- 开启匿名统计的客户端产生了多少启动、加固和签名操作

当前方案同时读取 GitHub 聚合数据和 Cloudflare Worker 提供的匿名客户端每日汇总。客户端数据只包含随机匿名 UUID、日期、应用版本、平台、架构和计数，不包含 APK、证书、密码、路径、包名或项目内容。

必须始终明确：

- 下载次数不等于独立用户数，同一用户可能重复下载或下载多个格式
- 独立访客与独立克隆是 GitHub 在最近 14 天窗口内计算的近似值
- 星标代表公开关注，不等于实际使用量
- 首次建立快照时只有累计基线，无法还原此前每一天的下载增量
- 匿名使用数据只代表允许并成功完成上报的客户端；当天数据会持续变化，完整日趋势只展示已经结束的 UTC 日期

## 数据口径

| 指标 | 来源 | 保留方式 | 含义 |
|------|------|----------|------|
| 发布包下载量 | GitHub Releases | 当前值短时缓存 + 每日累计快照 | 使用意向的近似指标 |
| 系统平台下载量 | 根据产物文件名归类 | 每日累计快照 | Windows、macOS、Linux 需求分布 |
| 仓库访问与独立访客 | GitHub Traffic | 每日保存最近 14 天汇总 | 近期关注度 |
| 仓库克隆与独立来源 | GitHub Traffic | 每日保存最近 14 天汇总 | 源码使用或开发关注度 |
| 星标、复刻、未关闭事项 | GitHub Repository | 当前值短时缓存 + 每日快照 | 复刻对应 GitHub Fork；未关闭事项包含问题与拉取请求 |
| 启动、加固与签名计数 | 匿名统计 Worker / D1 | 最近 14 天每日汇总 | 实际使用趋势的近似指标 |

校验和文件不计入发布包下载量。命令行压缩包按文件名归入对应系统平台，无法识别的平台归入“其他”。

## 存储与分支

统计实现放在 `main` 分支：

- `scripts/project_stats.py`：采集、合并历史数据并生成页面和图表
- `.github/workflows/project-stats.yml`：每日自动任务与手动补跑入口

生成结果放在独立的 `stats` 分支：

```text
stats
├── data/history.json
├── charts/download-trend.svg
├── charts/platform-downloads.svg
├── charts/traffic-trend.svg
└── index.html
```

这样不会让每日数据更新污染 `main` 的提交历史。根目录 README 通过 `raw.githubusercontent.com` 引用 `stats` 分支中的图表。

## 自动化流程

工作流每天北京时间上午 9 点运行，也支持在 Actions 页面手动执行：

```text
读取 stats 分支历史数据
        ↓
调用 GitHub API 获取最新聚合数据
        ↓
调用匿名统计接口获取最近 14 天汇总
        ↓
按 UTC 日期追加或替换当日快照
        ↓
生成累计下载、平台分布和流量趋势图
        ↓
更新静态统计页
        ↓
提交并推送 stats 分支
```

同一天重复执行会替换当天快照，不会产生重复日期。没有数据变化时不会创建空提交。

## 图表设计

README 展示一张简洁的系统平台累计下载图。完整统计页展示：

- 各系统平台累计下载量
- 各正式版本与预发布版本累计下载量，并按系统平台拆分
- 每个版本的具体发布产物下载明细
- 发布包累计下载趋势
- 最近 14 天访问与克隆趋势
- 接近实时的累计下载、星标、复刻与未关闭事项
- 每日快照中的独立访客与独立克隆
- 今日仍在累计的匿名使用摘要、最近完整日活跃设备，以及近 14 个完整日的启动和加固成功趋势

趋势图只显示可验证的数据点，不补造首次快照以前的历史。

## 权限与安全

工作流默认使用 GitHub 自动提供的令牌读取公开发布数据，并把结果写入 `stats` 分支。该令牌通常无权读取 Traffic 接口，此时访客与克隆显示为“不可用”，不会被错误记为零，也不影响下载趋势持续更新。

如需启用访客与克隆统计，应创建只用于本仓库统计的细粒度令牌，授予读取仓库管理元数据所需的最小权限，并保存为仓库 Actions 密钥 `STATS_TOKEN`。不要复用维护者日常使用、能够访问多个仓库的宽权限令牌。

匿名统计接口是公开聚合读取接口，不需要 Actions 密钥。`STATS_TOKEN` 只用于读取 GitHub Traffic，与客户端匿名统计无关。Worker 的当前汇总默认读取 GitHub 公开接口，也可通过 Worker 密钥 `GITHUB_TOKEN` 使用只读令牌提升额度；令牌不得写入前端或公开响应。生成结果只包含聚合数字和公开发布产物名称，不包含匿名 UUID、网络地址或任何用户文件信息。

## 本地验证

使用当前登录的 GitHub CLI 令牌生成统计结果：

```bash
GITHUB_TOKEN="$(gh auth token)" \
python3 scripts/project_stats.py \
  --repository mocikadev/mocika-shield \
  --history-file /tmp/mocika-stats/history.json \
  --output-dir /tmp/mocika-stats
```

使用固定样例运行测试：

```bash
python3 -m unittest scripts.tests.test_project_stats
```

## 故障处理

- Traffic 接口权限不足时对应指标显示为“不可用”；配置 `STATS_TOKEN` 后会从下一次快照开始记录
- 匿名统计接口失败时，任务日志会输出警告，页面显示“匿名使用统计接口本次采集不可用”；GitHub 下载和仓库指标仍继续更新
- 当前汇总接口使用短时缓存。页面加载期间，近实时卡片显示“加载中”，避免将旧快照误认为当前值
- 当前汇总接口请求成功后，页面显示接口更新时间；接口暂时失败时，页面恢复每日快照值并明确标注快照时间，不影响历史图展示
- 匿名统计请求必须携带项目自己的 `User-Agent`；Cloudflare 可能拒绝 Python 默认的 `Python-urllib/*` 请求标识
- `stats` 分支被删除后，可手动执行工作流重新初始化
- Release 产物被删除后，其计数将不再出现在最新快照，但历史快照仍保留旧记录
- README 图表短时间未更新通常是 GitHub 图片代理缓存，不代表每日任务失败
