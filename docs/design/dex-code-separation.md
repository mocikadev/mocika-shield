# DEX 方法代码分离研究结论

**已停止产品接入。** 离线原型已验证结构／方法指令分离与可逆恢复，但在不依赖系统 Hook、私有 ART 或独立虚拟机的条件下，没有满足兼容、内存和安全边界的运行时落点。本研究不进入正式 Stub、DEXB、APK、CLI 或 GUI，也不预占版本。

## 研究目标

让结构载体不包含完整方法实现，使提取单一文件不能直接获得完整业务 DEX。目标是增加完整重建成本，不是损坏 magic／checksum 后宣称“无法脱壳”，也不承诺对已控进程保密。

## 已完成的离线原型

| 范围 | 证据 |
|---|---|
| 只读解析与清点 | 方法指令、边界及稳定 DEX／类／方法身份检查 |
| 抽取和恢复 | 生成占位载体、单独保存指令，恢复后逐字节一致 |
| 兼容样本 | Java、R8、反射、Kotlin、多 DEX、ARouter 与 JNI 语义回归 |
| 认证清单与代码载荷 | 校验载体身份、索引、完整性、密文与版本，错误时不消费业务 DEX |
| 分层认证 | 逐 DEX 分片与整组索引，验证成员缺失／错序／替换、nonce 重复和篡改 |
| 真实样本 | 授权的 12 DEX 样本逐份恢复一致；认证索引额外成本约占分片密文 0.003% |

这些实现只在测试私有研究入口使用，不表示正式 APK 已具备方法级保护。

## 离线认证的重要约束

- 结构载体 SHA-256、DEX 稳定身份、数量／顺序、分片 nonce 和密文摘要一起绑定。
- 总索引与分片使用不同认证上下文，整组核对后才依次解封；不因单个分片通过而允许缺失其他成员。
- 研究中由随机 96 位 nonce 基值和有界计数器保证包内唯一；同密钥跨包仍须重新生成安全随机基值，不能复用测试固定值。
- 顺序消费减少恢复阶段临时峰值，不等于运行时只需保存一小段完整代码。
- 测试格式不是新 DEXB 协议；若未来恢复研究，正式协议和密钥派生须另行评审。

## 运行时路径为什么停止

| 路径 | 决定 |
|---|---|
| 私有目录重建完整 DEX | 兼容，但再次产生可提取明文文件，失去本研究的主要收益 |
| 每个 DEX 单独类加载器 | 改变跨 DEX 顺序和类身份，不能作为通用 APK 方案 |
| 全部重建后使用内存加载器 | 仍需持有完整 DEX，不能消除已知长期内存成本 |
| AppComponentFactory／稳定代理 | 解决加载器时序，不提供方法片段定义或回填能力 |
| ART／系统 Hook、运行时改写代码页 | 依赖高风险私有实现，违反既定兼容和安全边界 |
| 自定义解释器／虚拟机 | 是独立执行引擎专项，不能作为本研究的顺手延伸 |

Android 公开[内存加载器](https://developer.android.com/reference/dalvik/system/InMemoryDexClassLoader)接收完整 DEX；[组件工厂](https://developer.android.com/reference/android/app/AppComponentFactory#instantiateClassLoader(java.lang.ClassLoader,%20android.content.pm.ApplicationInfo))不提供方法片段恢复接口。完整内存候选的大包成本见[测量结论](memory-dex-production.md)。

## 安全软件与兼容边界

参考实现的公开问题曾涉及厂商检测、市场拒绝和签名／壳特征；这些反馈只能提示风险，不能证明某个单一行为必然触发所有引擎。原审查来源保留为 [系统 Hook 反馈](https://github.com/luoyesiqiu/dpt-shell/issues/51)和[固定壳特征反馈](https://github.com/luoyesiqiu/dpt-shell/issues/128)，不依赖其二进制或照搬实现。

本项目不采用系统函数／ART Hook、私有符号扫描、可写可执行代码页、Native 自修改或加密后运行时修补代码段；不通过持续随机化、隐藏 Hook 或对抗分析工具来规避检测。固定名称治理只减少无意义特征，不承诺绕过安全检测。

若未来重新评审，扫描只用自有或许可明确的样本，固定同一证书比较原包、正式加固和候选，分别记录引擎、检测名称及新增行为；未经授权不上传业务 APK。出现稳定拦截，优先移除风险行为，而不是隐蔽它。

## 重新评审条件

只有稳定公开 API 能提供所需的片段恢复能力，或项目明确批准独立虚拟机研究时才重启。仍须证明：

- 结构和行为往返正确，覆盖多 DEX、反射、JNI、ARouter、异常和延迟加载。
- 比现有文件／完整内存方案有可复现的保护收益，不是简单修复头部即可还原。
- 启动、峰值和长期内存成本可接受，不靠减少测试范围隐藏兼容问题。
- 新协议拒绝未知版本，标准／工控资源不被隐式升级，回退路径和用户承诺明确。
- 安全软件新增检测无法通过删除风险行为解决时停止。

保留离线原型和负面结论即可；不继续扩大格式、分片层级或制造新的阶段任务。
