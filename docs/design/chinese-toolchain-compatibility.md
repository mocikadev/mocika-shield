# 中文路径与 Java 工具输出兼容

## 证据与边界

2026-10-12 QQ 群反馈：中文 APK 文件名时加固报错乱码，签名识别失败，尚缺操作系统、Java 诊断及完整错误信息。

本机对同一个已签名 APK 做英文名、中文带空格文件名对照，在 JDK 8/11/17、UTF-8/C 区域设置共 12 组签名验证均成功、指纹一致。另用真实 apksigner 的文件不存在错误复现：输出 GBK 时按 UTF-8 读取会损坏中文路径。只确认输出编码缺陷，不将用户签名识别失败归因为同一问题，也不宣称 Windows 中文路径已完整验证。

## 修复计划

- [x] 真实 apksigner 非 UTF-8 错误输出回归先失败，再修复。
- [x] 共享核心统一 Java 工具文本协议，覆盖 APK 签名验证、证书指纹读取、签名、apktool 解包/重打包、版本与运行目录探测、GUI 关于页工具版本。
- [x] keytool 继续使用已有 UTF-8 与英文参数，并共用编码规则；不修改用户系统环境变量，不设置 `sun.jnu.encoding`，不改名输入 APK。
- [x] 核对前端文件名/目录、Unicode 持久化、Manifest 与 APK 名称、证书 Alias/密码以及错误输出；记录未确认风险，不扩大为全项目重构。
- [x] 执行核心、CLI、GUI 相关检查，真实 JDK 中文路径与中文证书回归；明确原生 Windows 验证边界。

## 架构

共享核心私有 `java_process` 模块负责 Java 子进程文本编码参数，通过 `utils::java_command` 暴露给 GUI；保留 `keytool_command` 公共接口。无新增依赖、配置、数据库或 APK 协议变化。参数仍由 `Command` 独立传入，不拼接 shell 命令。编码统一仅影响工具文本输出，不承诺修复旧 JVM 启动器的路径转换问题。

## 中文链路审计

| 链路 | 检查结论与处理 |
|------|----------------|
| Java 工具输出与错误分类 | 原先默认输出可能为 GBK/ASCII，而 Rust 按 UTF-8 读取；本次统一子进程标准输出、标准错误编码和工具语言，避免中文损坏及分类漏匹配。保留不合法输出的人读降级，不以猜编码替代协议。 |
| APK 输入、输出、JAR 与证书路径 | `Command` 分参数传递，不经过 shell，中文、空格和 `&` 不拆分。Windows 可执行文件路径继续通过 `dunce` 简化；未设置文件系统编码，不将 stdout 编码修复等同于旧 Windows JVM 路径支持。 |
| 前端文件名与输出路径 | `src/lib/path.ts` 处理 Unicode 字符串和两种目录分隔符，未发现将中文转为本地代码页的操作；本次不改默认文件名或界面。 |
| 证书 Alias 与指纹 | 既有 keytool 输出严格按 UTF-8 解析；保留 PKCS12 实际 Alias 与大小写兼容逻辑。中文 Alias 和中文证书路径已真实回归。 |
| 配置、数据库与密码 | TOML/JSON、SQLite 文本参数及 `enc:v1` 密码加解密按 Unicode/UTF-8 处理，未发现中文转码缺陷。未更改密码存储格式、派生密钥或历史记录，不保证所有 JDK/证书格式接受任意非 ASCII 密码。 |
| Manifest 与应用显示名 | GUI 的二进制 Manifest 和资源字符串池有 UTF-8/UTF-16 解码分支；与 Java 控制台编码是不同链路，本次未发现需修改的中文问题。 |
| 非 Java 系统工具 | `open`、`explorer` 等采用独立路径参数；通用进程输出和外部 zipalign 不能套用 Java JVM 属性。后续遇实际乱码按具体工具处理。 |

### 保留风险与后续验证

- **原生 Windows 待验证**：中文用户名/JDK 安装目录、APK/JAR/证书/输出目录组合，以及旧 JDK 对系统代码页之外字符的处理。本机 macOS 测试不能替代这些验证；如仍出现找不到文件，需检查传入参数是否已被 JVM 启动器转换。
- **非 UTF-8 文件名**：部分调用使用 `to_str().unwrap()` 或 `unwrap_or("")`。合法中文不触发该问题，但 Unix 任意字节文件名可能导致异常或空参数。后续单独改为 `OsStr` 参数或显式错误，不混入这次输出编码修复。
- **外部 JVM 配置覆盖**：用户的 `_JAVA_OPTIONS` 等可能覆盖 JVM 属性；本次不删除用户环境变量，也不静默改系统配置。复现时需同时核对这些变量，禁止记录含密码的完整命令行。
- **特殊 Unicode**：表情、组合字符及超长路径未全覆盖。DEX 的修改版 UTF-8、应用资源字符串和文件系统路径也不是同一种编码，不能做全局替换。
