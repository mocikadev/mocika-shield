# 受控独立签名与 MCP 接入方案

2026-11-09：维护者已要求按简化方案制定任务并实施，随后明确不得给任务流增加反复确认。本文件采用共同执行许可、单次工具调用、自动内部规划的方案；不再采用最初拟议的独立签名权限开关。任务见[实施计划](../process/controlled-signing-plan.md)。当前公开稳定版仍为 1.4.3，新接口按阶段实现，不以文档声明已可使用。

## 目标与范围

让 Agent 使用已保存证书给 APK 独立签名，不调用加固、不注入壳、不解密或改写业务 DEX。先在现有 CLI 受控工作进程中补齐签名任务，再由 MCP 调用；GUI、普通 `sign`、已有加固计划和外置来源保持兼容。

首版限当前 macOS 开发特性、共享证书编号及 V1–V3 单 APK。支持普通未签名／已签名 APK，并在能够确认本工具加固包的证书绑定时允许同证书签名；不支持 V4 多文件交付、任意外部临时密钥、其他工具加固格式识别或签名轮换证明。MCP 不开放证书导入、创建、校验、偏好、默认项、删除或配置保存。批量、网络服务、模型 SDK、自动安装、发布、全局 Agent 注册和新增日常重型 CI 不在本批范围。

## 实施前代码依据

- `apps/shield-cli/src/automation/execution/worker.rs` 固定执行加固后签名；`plan::Sources` 固定包含 apktool 和壳资源，不能让仅签名用户准备无关材料。
- `task_lifecycle::ArtifactEvidence` 当前必须有 `protection_checked: true` 才可提交；`worker_protocol` 和 MCP 结果投影也是加固语义。不能对普通签名伪造该字段为真，或全局关闭这个检查。
- 普通 `shield sign --certificate-id` 已复用共享库及 `sign_apk_with_progress`，但不是受控取消／无覆盖提交接口；直接包装不能继承现有 MCP 承诺。
- `shield-core::signing` 当前只在 V4 开启时传 `--v4-signing-enabled true`，关闭时省略参数。前次普通签名夹具目录出现过 `.idsig`，但还没有隔离其生成原因；须用干净目录和真实 bundled apksigner 复现，再决定参数修补，不能把侧车存在直接当成根因已确认。
- `apk_inspect::check_apk` 可识别 MSHD 尾块，但未公开 DEXB 内证书绑定读取能力；仅比较 APK 当前签名不能保证换证书后壳可启动，未签名加固输出更不能据此推定绑定。

上述为实施前依据。已在干净目录确认 V4 工具默认行为，签名调用现显式传布尔值；只读检查由 `inspect_signing_input` 提供。受控 CLI 与单次 MCP 独立签名已在 macOS 开发特性接入，并完成本机源码协议和完整 `.app` 验证；错误分类／清场证据及验收边界见[任务记录](../process/controlled-signing-plan.md)。实际宿主接入仍未验，不能据此宣称公开安装包已支持。

## 架构选择

这是架构级扩展：新增受控任务种类和公共计划契约，同时补核心只读检查。推荐方案不新增 crate、持久化、后台服务或核心签名执行接口，不重写现有父端监督器。

| 方案 | 收益与代价 | 决策 |
|---|---|---|
| MCP 直接包装普通签名 | 代码较少，但缺少受控准备、停止证明和统一无覆盖交付；现有普通签名可原地写回 | 不推荐作为受控工具 |
| 在已有执行器中增加类型明确的独立签名分支 | 复用工作组、租约、期限、父端唯一提交；单独维护签名计划、材料集合和产物证据 | 推荐 |
| 先重写为通用任务／插件框架，再迁入签名 | 可统一更多未来能力，但扩大当前状态机和全部调用方迁移，未证明有必要 | 暂不采用 |

职责保持：`shield-app` 提供共享签名身份、记录绑定及只读复核；`shield-core` 提供 APK 内容／绑定检查、对齐、签名与验签；CLI 私有模块拥有计划、工作进程与提交；MCP 只做宿主权限、会话及结果映射。SDK、SQL 连接、密码材料不穿透这些边界。

## 签名任务与验证证据

- 保留现有加固请求、计划版本 2／3、材料包 1／2、验收条件及旧命令。新签名任务使用独立请求／来源类型，不给旧加固请求补一组可缺省的签名开关来绕过资源检查。
- 源码已新增 `shield agent sign-plan` 与 `shield agent sign`。两者只在既有 macOS 执行特性中开放；默认源码 CLI 不扩大实验能力，普通 `shield sign` 不改为受控协议。
- `sign` 单次调用自动完成内部规划、固定材料、核对并执行；不要求先调用 `sign-plan`、手工复制摘要或额外确认。`sign-plan` 仅供显式要求预览／排障的场景，不成为执行前置步骤。
- 指定证书 ID 时使用该记录；未指定时沿用 GUI／CLI 的共享默认项，并在内部规划时一次固定，不保存“稍后读取默认项”。MCP 继续尊重已配置的原证书范围；默认项不在范围时可使用唯一允许项，多项且无法确定时返回固定选择错误，不循环提问或猜测。项目覆盖如提供，固定其完整身份，仅允许合法工具／签名设置，不混入外部 keystore、Alias 或密码环境。
- 新签名计划使用版本 4，公共事件信封仍为 1，操作分别为 `agent_sign_plan`／`agent_sign`；计划摘要明确绑定 `sign` 操作、输入、输出、相关证书记录、实际文件、Java/keytool/apksigner 及有效签名版本。旧结果解析器不能据版本／字段相似接受新计划。
- 签名私有绑定不含路径、Alias 或密码，外层明确操作类型和独立版本；内部复用应用库记录承诺，不复制 SQL／解密算法。默认项、备注及其他记录变化不换身份；选中材料或实际文件变化则阻断。
- 工作进程来源及材料集合为输入、keystore、apksigner，可选项目文件；Java/keytool 独立固定并复核。不包含 apktool、标准／工控资源，不接受运行模式、保护策略和 ABI 排除参数。
- 新签名启动描述、材料索引与工作消息须有独立版本／种类校验。不同任务的证明不能互换，旧加固缺角色仍拒绝；同一二进制身份检查继续有效。
- 进度为准备、检查、对齐、签名、验签；状态机按任务要求验收，不通过缺少加固阶段来推断任务类型。复用原工作组停止、父死租约、有界协议、唯一终态和父端提交，不复制控制器或新建任务服务。
- 签名证据包含签名有效、证书一致、对齐通过及非签名内容保留。普通 APK 的加固验证为“不适用”，不伪造 `protection_checked: true`；加固任务的原强制条件不放宽。

非签名内容比较使用 ZIP 条目名和解压后的内容摘要，不要求 ZIP 偏移、压缩字节或 APK 签名块不变。仅排除明确的 JAR 签名元数据，不忽略整个 `META-INF/`；重复条目、读取失败和不确定输入明确拒绝。读取、摘要和 Java 均纳入任务期限，不在父端计时外执行工具。

内部兼容采用最小扩展：签名启动描述为 4、来源证明为 3、材料索引为 3；旧加固的相应版本不变。签名来源固定 `operation: sign`，内部结果必须带 `task_kind: sign`，公共结果再按操作投影成计划 4。父端在创建任务时固定签名内容摘要；签名候选必须带该摘要、且不能声称执行了加固验证，旧加固候选仍必须通过原加固验证。工作消息信封仍为 1，但不能用另一类任务的来源、结果或验收证据代替；执行器仍要求同一二进制身份。

在已按共享应用方式预配置证书的源码开发构建中，一次执行示例：

```bash
shield agent sign -i input.apk -o output-signed.apk
shield agent sign -i input.apk -o output-signed.apk --certificate-id 证书编号
```

可选 `--config shield-cli.toml` 只提供项目签名版本和工具覆盖；证书仍来自共享资料库，不从项目中拼接密码或临时材料。`sign-plan` 只是把上述命令中的 `sign` 改为 `sign-plan` 的预览入口，执行不依赖其返回摘要。两种入口均不接受运行模式、ABI 或用户回传绑定。

## 已加固 APK 与证书绑定

核心已增加最小只读检查入口，复用现有 MSHD 定位规则，返回未检测到本工具格式、当前格式绑定声明或无法识别／损坏，保持类型和错误语义明确。

- 只解析当前 DEXB v5 的有限明文头，不解密 DEX，不加载全部密文、不修改格式或签名绑定。
- 严格检查块边界、长度、计数、签名指纹编码、必要头部和密文标签长度；未知版本、冲突／重复块或疑似损坏不能降成普通未加固输入。
- 明文绑定只是该格式声明，不是已认证的来源证明或运行时解密成功。记录和复核完整输入及业务条目摘要，防止规划／执行之间漂移；不宣称这能识别所有第三方壳或保证业务可运行。
- 加固输入选择的证书必须匹配该绑定，否则拒绝，不能用“允许重签”绕过。签名后复核绑定与业务内容未变。
- 普通已签名输入按用户明确的签名任务执行；若证书改变，结果给出无法保证覆盖升级的固定警告，不为已明确的选择再加确认步骤。本次任务仍只写新输出，不修改原文件。

首版无法安全读取的旧格式交回人工处理，不为本功能更改 Android 壳或补兼容解密器。

## V4、暂存与最终提交

首版有效版本若含 V4 或 V1–V3 全关闭，规划即拒绝，不静默降级。验证关闭 V4 时实际命令和输出集合；若确认省略参数导致侧车，修补共用参数构造为明确传入布尔值，覆盖开启／关闭及旧 GUI／CLI 签名回归，不升级 JAR 或擅自删除用户已有侧车。

签名仅写任务私有目录，父端独占最终提交，目标必须为包外授权目录中的新 APK。占用、链接、目录、原地签名均拒绝；不能先删除旧目标。任务暂存内的非预期侧车不作为最终交付，须明确验证、收尾并核对单文件结果，不把它当成功双文件输出。

超时、取消、断开、输入／证书／工具漂移或验收失败不发布最终文件；停止／提交未知时保留材料并锁定后续执行。已发布后晚取消不删除产物。沿用现有断电／逃组／双重崩溃保证边界，不作任意故障原子事务承诺。

## MCP 简化入口与会话

沿用宿主现有 `--allow-execution`，启用一次即允许已实现的加固和独立签名，不新增 `--allow-sign` 或签名专用白名单。未启用时仍保持只读；原外置模式继续兼容，首版独立签名使用已接入的共享来源，证书范围沿用已有启动配置，不要求每次任务重新配置。

执行模式仅增加一个 `shield_sign` 工具：接收现有根目录内的相对输入／输出及可选证书编号，一次调用完成内部受控规划和签名。明确的任务请求即为本次执行意图，不要求用户再确认、复制摘要或先创建计划。未指定证书时按上一节解析共享默认项。保留原状态查询，不新增签名专用状态工具，不接密码、Alias、配置、任意工具、环境变量名或版本覆盖。证书管理写操作不因此开放。

内部记录新增明确任务类型，仍共用既有容量、期限和单活动调用门槛。签名记录创建后直接进入执行状态，仅作为状态／收尾引用，不生成需要模型再次消费的待确认计划。原加固计划的一次消费规则不变，签名引用不能被加固执行入口接受。两类任务共用未知状态停写规则，不能借另一任务类型、新任务或记录过期绕过。

MCP 私存绑定并白名单映射结果；不把原始 CLI 输出、密码、路径或 Alias 发给模型，不把通用加固标记强加给普通签名。输入断开／背压按原桥接请求受控收尾，记录证据而不是杀父进程后推定清场完成。

源码中已实现上述单次工具。唯一允许项无需查询默认列表；范围多项时只通过原 CLI 的脱敏证书结果选择范围内默认项，不在 MCP 直接读取数据库或密码。默认查询和签名共用同一调用期限。签名结果和进度通知提供同一会话引用，通知使用 `_meta["mocika-shield/plan_id"]`，便于请求取消后继续用原状态工具查询，不增加前置计划或确认。

已停止的规划错误必须显式关闭私有目录后才能报告清理完成；CLI 内部错误对象携带这一事实，而不是让 MCP 按错误码把 `unconfirmed` 猜成 `complete`。无清场证据、管道／工作组停止未确认或提交未知时仍保持保守状态并锁定会话。实际宿主自身授权策略不由本工具绕过。

## 验收、兼容与回滚

先用隔离资料、合成 JKS／PKCS12 和自有 APK 验证；本机真实资料库先前的使用许可不延伸为本阶段可删除、改默认项或拿业务证书签名的许可。

覆盖普通未签名、普通同证书／换证书、当前格式加固未签名／已签名、错绑定／损坏／未知格式、V4 及实际输出集合。独立验签、选中证书指纹、官方 SDK ZIP 对齐和非签名内容保留均须实测，既有输入和资料不变。

受控路径另验准备／签名期间取消、超时、断开、后代停止、原地／已有输出拒绝、源变更、提交前记录变更、晚取消及未知锁定。MCP 另验共同执行开关、证书默认／显式选择、跨任务引用、原加固一次消费、容量、参数拒绝及无秘密结果，不拿 CLI 通过代替它。

增加无人值守验收：预先配置证书后，用一次工具请求完成签名；关闭标准输入也不能等待终端确认、读取密码提示或卡在交互中。缺证书、歧义、占用、错误密码、绑定不符及工具缺失均在有限时间返回结构化错误，禁止为了提高成功率自动修改配置、证书或覆盖输出。

完整 macOS `.app` 必须在源码外中文空格目录使用包内 CLI／JAR 验证。实际 Agent 宿主注册和模型行为另行记录：当前宿主无动态本地 MCP 注册接口，不修改全局配置、不擅自新建 Agent 任务；暂不能注册不阻止底层开发，但不能写成宿主已验。

不预占版本、不发 Alpha／Beta／RC，不新增重型 CI。按完整阶段集中提交；独立签名仅在当前 Mac 开发构建验收，未公开发布，设计文档不替代实际能力检查。移除新增入口即可撤回新能力，不影响现有执行开关；共用 V4 参数修补的回滚单独评估，不回退或放宽旧加固的验收约束。
