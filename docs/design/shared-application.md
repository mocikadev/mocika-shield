# 多入口共享应用能力与本地数据

最后更新：2026-11-09。维护者已明确要求：GUI、CLI、Skill、MCP 及未来 TUI 是同一工具的不同入口，加固、签名、证书管理及其业务配置应共享，不维护互相隔离的产品状态。本文替代早期 Agent 设计中“禁止使用 GUI 证书库”的目标约束；当前实现与授权限制见下节，目标本身不作为验收证明。任务与证据见[实施计划](../process/shared-application-plan.md)。

## 目标、范围与非目标

当前实施状态：GUI、普通及受控 CLI 已接共享库；Skill 0.2.0 已更新相应指引，MCP 已按[宿主白名单共享](shared-mcp.md)接入脱敏查询及受控加固。MCP 独立签名和管理写工具后置，不表示全部入口已有全部写能力或公开安装包已更新。命令见[操作说明](../ops/shared-data-cli.md)，证据见实施计划。

- 在任一入口明确导入、创建或修改的证书，其他入口下次查询时可见；默认证书和业务偏好来源一致，不要求先启动 GUI。
- 加固、独立签名、证书管理、业务配置管理均有共用应用能力；CLI 提供终端和结构化适配，Skill 调用 CLI，MCP 在宿主授权范围内调用相同能力。能力对等不等于接口形式或默认权限完全相同。
- 本次命令参数只影响本次任务；仅显式保存操作改变默认配置。任务开始后使用不可变快照，不受其他入口切换默认项影响。
- 原有 `shield-cli.toml` 保留为可选项目覆盖，适用于 CI、独立数据目录及无桌面环境；它不是第二套全局证书库，不再作为所有自动化操作的前置条件。
- 主题、窗口、更新提示等界面设置不强行暴露为业务接口；未来 TUI 只接现有共享层，本阶段不实现 TUI。
- 不改 Android 壳、DEXB、缓存、NDK、资源协议或加密算法；不新增后台服务、网络 API、遥测、技能安装器或日常重型 CI。不在此阶段改造 GUI 为另一种框架或替换其执行控制器。

## 当前问题与代码证据

| 能力／状态 | 当前实现 | 调整方向 |
|---|---|---|
| 加固、签名、APK 检查 | 核心复用；普通及显式共享受控 CLI 复用应用参数与身份 | 补后续入口授权，不重写算法 |
| 证书导入、创建、校验及偏好管理 | `shield-app::certificates` 承载，GUI 及 CLI `cert` 复用 | 补后续 Agent 授权和工具，不复制服务和存储 |
| 证书与默认证书 | `shield.db` 的 `certificates`、`app_state` | 保留单一数据库与 ID，不复制或导出成另一份证书列表 |
| 加固默认项 | GUI 与 CLI 共用模型／存储；受控共享规划固定有效值 | 补后续入口，不改变旧脚本默认行为 |
| CLI 配置 | 保留项目文件；显式共享来源可免项目文件，外部材料兼容 | 保持来源整体选择，禁止混合材料 |
| Agent／MCP | 受控共享 CLI、MCP 白名单查询及共享执行已接入 | 后续单独设计签名／管理写权限，不另建执行器 |
| Skill | 0.2.0 已按 CLI 扩展共享受控、资料管理与普通签名 | 独立升级，普通命令不冒充受控保证，实际模型验收另记 |

必须先解决的兼容风险：

1. `cert_store.rs::derive_crypto_key` 使用既有固定上下文、数据库路径、托管证书目录及用户环境。只改变模块位置不能改变这些输入；目录迁移、改品牌字符串或擅自重新规范化路径可能让旧密码无法解密。
2. 原 `AppConfigState` 只有进程内 Mutex、缓存全量写回；现已改用共享存储，锁内重读与字段差异合并。剩余入口不能重新引入缓存全量覆盖。
3. 原 `CertificateRecord` 可序列化、可调试且含密码；现已拆开不含密码的公开摘要与不可直接序列化／Debug 的内部材料，后续 CLI 不能绕过此边界。
4. 共享库已提供目录定位、证书用例及固定错误；GUI 只适配 Tauri 路径与诊断。CLI 不得链接 GUI、复制源文件或跨目录 `#[path]` 引用。
5. GUI 和受控 CLI 的任务生命周期不同。共享业务参数不要求立刻统一两者进程监督，否则会扩大为另一项执行器迁移。

## 架构选择与确认

这是架构级调整，涉及依赖方向、持久化所有权及自动化契约。共享原则及下表推荐的 `shield-app` 承载方案均已获维护者明确确认，按阶段实施；若改变数据模型或依赖方向，须重新确认。

| 方案 | 取舍 | 结论 |
|---|---|---|
| 新增 `crates/shield-app` 共享应用库 | 明确隔离本地数据、证书用例与参数解析；GUI／CLI 可独立依赖和测试；增加一个工作区成员及版本同步项 | 推荐 |
| 在 `shield-core` 增加应用状态模块／特性 | 少一个 crate，但加固算法核心混入 SQLite、配置并发和用户状态；需要额外特性隔离 | 可选，不推荐 |
| GUI 暴露本地服务，CLI 转发或直接引用 GUI 源码 | 需运行 GUI／新增服务生命周期，或造成反向依赖与复制规则 | 不采用 |

推荐依赖方向：

```text
GUI ─────────┐
CLI ─────────┼──→ shield-app ──→ shield-core
未来 TUI ────┘
Skill ──→ CLI
MCP ────→ 受控 CLI／其命令适配
Android 壳：不依赖 shield-app
```

`shield-app` 负责本地应用目录、配置更新、证书管理、签名身份与任务请求解析；不负责窗口、终端、SDK 消息、网络上报、进程全局信号或 APK 最终提交。采用现有具体存储实现，不预建插件、通用仓储接口、事件总线或后台任务库。内部模块按状态生命周期划分，不机械按行数拆分；SQL、连接和加密实现私有。

`shield-core` 保持 APK 算法、签名工具、预检和资源契约；Tauri、clap、rmcp、SQLite 连接不得穿透核心业务请求。GUI `main.rs` 仍只做命令适配和状态注入；CLI 不读取或链接 Tauri 类型。

## 共享状态与配置规则

### 单一位置与可选隔离

- 默认复用现有应用标识 `dev.mocika.shield-gui` 对应的配置和数据目录，不因新增 CLI 改名。`config.toml`、`shield.db`、`keystores/` 继续各归原处，不把配置目录和数据目录误认为所有平台上相同。
- 共享目录定位由应用库统一提供，并与 Tauri 实际返回值逐平台核对；不能使用当前 CLI 工具缓存目录冒充 GUI 数据目录。
- 为测试和 CI 提供显式隔离目录上下文，各入口使用相同上下文才共享；无效显式目录应报错，不回退用户真实库。目录上下文是本地调用者／宿主配置，不由 MCP 工具任意切换。
- 本轮不读取、迁移或写入维护者真实证书库。测试只用独立临时目录和合成证书；真实资料迁移必须另行确认。

### 配置优先级

从低到高为：内置安全默认值 → 当前应用上下文的共享业务偏好 → 显式项目配置 → 本次显式参数。参数缺省必须保留“未指定”信息，不能让 clap 默认值覆盖共享设置。

证书来源须作为整体解析：显式证书 ID 与显式 keystore 材料冲突时报错，不拿共享密码去匹配另一个文件。用户明确指定的证书不存在、密码无法解密或材料失效时，停止，不换用默认证书。GUI 加固页已保存的专用证书选择也属于共享业务字段，不能擅自把它改成全局默认证书；独立签名使用同一全局默认来源。具体优先级在命令契约中明确并覆盖测试。

MCP 的授权目录、执行许可和可选证书允许列表是宿主限制，优先于业务默认值；项目配置不能扩大权限。受控输出仍要求明确、包外、不存在，不因共享输出偏好而静默选择或覆盖文件。ABI 排除继续逐次授权，不自动记为下一次同意。

### 多进程更新与可见性

- 证书写入采用有限等待的 SQLite 事务；设置默认项、删除记录和相关偏好更新保证一致，不以多个进程内 Mutex 冒充跨进程锁。
- TOML 使用独立的稳定锁文件进行跨进程互斥，在锁内重新读取最新文档、只更新目标字段、保留其他分区和未知字段，再同目录临时文件原子替换；目标文件损坏或格式版本过新时拒绝写入，不重置默认值覆盖原文。锁定临时文件或被替换的目标 inode 不算有效锁。
- 不把进程启动时缓存的完整配置重新覆盖磁盘。GUI 在重新查询／进入页面／重新获得焦点时读取有效状态；执行中的任务仍使用旧快照，不承诺首版跨进程实时推送。
- 更新默认值的同时运行任务时，两者独立：保存只影响后续任务，不修改正在运行的证书、策略或输出。长时间 Java 操作不持有数据库写事务或配置文件锁。
- 物理删除 keystore 默认关闭，显式删除也只允许符合托管规则的文件，不删除外部导入原件；其他入口正在使用材料时，不声称删除能撤销已开始的任务。

当前实现约束：

- `ApplicationPaths` 保留原应用标识，采用与 Tauri 相同的 `dirs` 目录算法；GUI 初始化会核对两者结果。使用 `dunce::simplified()`，不对既有密钥派生路径执行 `canonicalize()`。隔离目录无效时不回退真实用户目录。
- `ConfigStore` 只读不创建文件；更新持有固定的 `config.toml.lock`，最多等待三秒。使用 Rust 标准库文件锁，因此桌面共享库声明 Rust 1.89 下限；这不是完整依赖图的最低版本认证，Android API 19 的 Rust 1.77.2 不变。
- 配置上限 8 MiB。语法／类型错误、未知格式版本、非普通目标文件均拒绝写入；已经加载的配置被删除后不使用缓存重新创建。锁文件保留，不按“过期文件”删除；进程退出由系统释放锁。
- 更新区分字段未指定、设置值和显式清空，其他分区及未知字段保持。首次初始化只补缺失字段，不轮换已有匿名标识、不重置统计／分享选择；重写 TOML 不保证保留原注释或排版。
- 同目录私有暂存文件写入并同步后原子替换；不承诺断电后的目录持久性，也不构成阻挡同权限恶意进程替换文件的沙箱。只有遵守同一锁协议的写入者受保护，旧版进程仍须先退出。
- SQLite 写操作在读取相关状态前开启立即事务，默认项与证书查询使用一致读快照；忙等待仍有三秒上限。数据库事务内不调用 Java 或网络。
- GUI 保存提交字段补丁，页面切换、焦点恢复或重新可见时刷新；本窗口保存串行化，晚到的旧查询不覆盖新状态。运行中／已锁定任务不跟随默认值变化，预检相关参数变化会使旧请求失效。不新增轮询或跨进程推送；桌面实际焦点交互尚未人工验收。

## 证书模型与服务边界

共享服务覆盖列表／详情摘要、导入、创建、校验、编辑偏好、设置／清除默认项、删除记录。保留现有约束：材料保存后不可通过编辑修改，PKCS12 使用实际 Alias，匹配大小写不敏感，创建密码长度不放宽。

CLI 当前实现：资料管理固定单 JSON；查询使用只读既有数据库，不初始化或解密密码。新增证书偏好补丁在事务内只改目标字段，不携带材料。已有库被删除后不自动创建空库。新导入／创建只接固定密码环境变量，尚无终端隐藏输入；删除须显式确认且只删记录，不删文件。写后回读失败保留结果未确认语义，不能自动重试。普通共享签名立即解析身份和材料快照，默认项后续变化不替换该快照；签名版本按记录→项目→本次解析，材料来源冲突拒绝，旧命令事件协议不变。

- 对外返回不含密码的证书摘要；内部签名材料不实现直接 Serialize／Debug，不通过通用查询返回。GUI 可以由适配器保持旧字段形状，但密码继续为空，不借迁移扩大前端权限。
- 密码只在本机受信任服务和工具子进程中使用，日志、结果、错误、计划和模型上下文均不携带明文。保留 `enc:v1` 格式及原解密兼容，不自动接受旧明文或重置无法解密的记录。
- CLI 本地导入／创建从交互式隐藏输入或宿主环境获取新材料密码；禁止要求用户粘贴到 Agent 对话。新接口不把密码写入项目 TOML 或 argv，不在本轮删除旧参数造成兼容回归。
- 导入／创建是显式持久操作；仅在签名命令传入临时 keystore 不自动存库。编辑与删除按稳定 ID 定位，不根据名称、排序或默认证书猜测目标。
- 同时导入／创建的文件分配必须无覆盖，失败不能抢删另一个任务或遗留“记录成功但文件丢失”的状态；原有服务的文件分配逻辑需跟随提取一起审查。
- 应用层返回类型化错误／核心诊断；GUI 转换为现有交互诊断，CLI／MCP 转换固定错误和有限摘要，不透传原始工具输出。

## 加固、签名与任务快照

普通 CLI 当前已接入：`shield-app::protect` 纯函数解析共享、项目和本次覆盖，不运行 Java、不存储或序列化密码。CLI 的普通执行模块负责其现有进度与单任务临时产物，核心仍执行实际加固、签名、资源和 ABI 校验；不复用或绕过受控执行器的内部进程协议。GUI 的生命周期保持原样，未为共享设置重写窗口任务控制器。

兼容策略：普通旧 `protect` 不隐式读取 GUI 偏好。显式共享开关、隔离目录或新项目字段进入新流程；新流程固定模式及本次签名材料，输入／输出仍须明确。默认项的继承偏好与 ID 一次查询固定，签名失败无最终输出；最终单 APK 采用同目录暂存、验证和无覆盖硬链接，未知提交保留材料，不将此解释为进程隔离／取消保证。新流程暂不交付 V4 附加文件，明确拒绝，不静默降级。旧受控入口拒绝新共享项目字段，避免未绑定身份就读共享库。

任务快照包括有效运行模式、保护策略、签名版本、选定证书身份、输入输出、资源选择和显式 ABI 排除。共享层解析业务值，各入口继续持有其既有生命周期和进度适配，不复制核心 APK 操作。

记录级绑定已由共享存储提供：同一读事务生成内部材料快照与非秘密承诺，原普通共享签名解析也已复用；提交前检查只查询相关列，不解密或哈希整个数据库。材料快照无 Serialize／Debug，公开绑定只有版本、ID 与密文／相关字段承诺；不把明文密码作公开摘要，也不冒充外部 keystore 文件校验。开发特性下的受控 CLI 已显式接入，完整传输与检查点见[无状态绑定设计](shared-agent-binding.md)；Skill、MCP 和公开 Release 不自动随之具备共享能力。

默认项在规划开始时解析并固化；执行必须匹配同一快照。规划后切换 GUI 默认项不应暗中替换原证书；选中证书被删除、材料／相关签名偏好变更、输入或实际工具变更则明确重新规划。无关备注、校验时间、其他证书变化不应仅因整个数据库字节变化而使计划失效。必须绑定本次相关记录和材料，不能仅保存“以后读取默认证书”。

复用原 CLI 工作子进程、凭据传递和无覆盖提交；不通过共享数据库把密码写到公开计划或临时明文 TOML。若现有执行协议无法表达共享身份，应先更新契约和有界消息测试，再迁移，不把整份数据库交给模型或复制到任务输出。

普通 CLI 的加固、签名与新管理命令在本机按相同服务解析；独立签名的参数／进度可以单独适配，但不借此绕过受控入口的授权和输出保护。旧自动化命令默认行为保持兼容，新的共享来源通过明确契约接入。

## CLI、Skill、MCP 与未来 TUI

CLI 按 `cert`、业务 `config`、加固、独立签名组织能力；最终子命令和协议在实现阶段核对现有命名，本文不把示意命令当成已实现接口。管理命令提供版本化结构化结果，区分查询与持久化修改；删除记录、删除文件、改默认项和批量修改不能混为一个隐式操作。

Skill 只在对应命令通过验收后扩展操作指引及自身版本；新增独立签名／证书管理需各自授权，不将一次加固授权理解为删除证书授权。无密码的查询可以由 Agent 使用；导入／创建所需秘密由本机交互或宿主准备，缺少安全输入途径时不能诱导模型收集密码。

MCP 继续默认只读。执行与管理权限分别由宿主显式授予，不因开启加固而默认开放删除库中任意证书。证书查询只返回必要摘要；管理操作限制证书集合／导入目录，密码来源由宿主预先绑定，不接受模型指定任意环境变量、数据库路径、配置文件或程序。共享既有证书可以免去重复注入密码，但不免去本次操作授权。

未来 TUI 直接依赖相同应用库和数据上下文，不复刻数据库、默认值解析或核心加固逻辑，不要求透过 GUI RPC。

## 迁移、回滚与验收

先提取纯共享能力并让 GUI 回接，在隔离目录验证旧数据；再补配置并发与 CLI 管理，再接执行／Skill，最后扩展 MCP。每一步保持可编译、文档区分“已实现”和“目标”，不用一次大改宣称全部完成。

首批不改旧目录、SQL 表名／列、证书 ID、密码派生上下文和格式。需要新增字段时必须做显式版本、兼容与备份设计；结构提取不能顺带重加密或移动用户资料。迁移成功才减少旧模块，不能永久留下两套写者。

在生产数据未变化的阶段可回退代码；一旦变更持久化格式，需要匹配的迁移／回滚门槛，不能仅回退二进制。测试备份需包括 SQLite 一致性和原密钥派生环境，复制数据库到新目录不代表可直接解密。旧进程不遵守新配置锁时无法保证并发安全，应要求先退出旧版，不能同时运行旧版和新入口写配置。

验收至少覆盖：旧密文读写兼容、两个入口互相可见、中文 Alias／路径、默认证书与加固页选择、跨进程不丢字段、坏配置不覆盖、秘密不输出、材料编辑拒绝、任务快照／计划漂移、真实小包独立签名及加固签名、取消和完整 `.app` 源码外验收。当前 Mac 先行，Windows／Linux 的目录与锁语义各自验证；不能把 Mac 结果扩写成三平台已通过。
