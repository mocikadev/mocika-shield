## 测量方法与局限

- 复用 CLI JSON 进度事件，按事件接收时间分段；不修改生产代码。检查阶段包括签名预检，DEX 阶段包括类冲突校验、缓存身份、路由扫描、压缩与加密，不将阶段直接等同于单个函数。
- 仅在测量子进程 PATH 中放临时 Java 转发器，执行同一 `/usr/bin/java`；同目录提供 keytool 链接以避免改变关联查找路径。转发器只追加固定调用类别，不记录命令参数或密码，计数排除任务外的签名校验。
- 以 500 毫秒间隔采样隔离 TMPDIR 的 `du -sk`，不是真正峰值，不包括外部目录下的最终输出和 JVM 其他缓存，也不代表累计磁盘写入量。临时目录清理与采样可能竞争，缺失条目不视为任务失败。
- 每种样本只采用一个完整成功的加固轮次，不声称统计显著性或冷缓存基准。第一次测量 runner 原计划重复两轮，为控制成本取消重复轮次，并停止了一次尚未完成的 B 试跑；已完成 A 的结果保留，B 使用新隔离目录重新完整测量。中断不计产品失败，缓存状态可能受之前读取影响。
- 曾对首次重建中的 Java 尝试一次线程栈查询，但未能建立 attach 握手，未获取栈，不进一步绕过或重复尝试；不能据此把重建耗时归因到具体 Java 函数。
- 独立签名只对原包执行，以新建临时证书测工具成本。它不是“原证书加固后自动签名”链路，不能拿这些产物覆盖业务应用或验证加固 APK 启动；不安装、不读取业务签名资料。

## 结果与后续

### 纯加固

| 项目 | A：Release | B：Debug |
|------|----------:|---------:|
| 总耗时 | 230.181 秒 | 267.311 秒 |
| 首次进度之前 | 0.599 秒 | 0.044 秒 |
| 检查（含原包签名预检） | 7.025 秒 | 4.568 秒 |
| 解包 | 31.540 秒 | 33.721 秒 |
| Manifest 处理 | 0.001 秒 | 毫秒取整为 0 |
| DEX 处理 | 22.617 秒 | 55.479 秒 |
| 壳注入 | 0.301 秒 | 0.573 秒 |
| 重建 | 148.390 秒 | 151.560 秒 |
| 对齐、产物检查与末尾清理 | 19.708 秒 | 21.366 秒 |
| Java 版本探测 | 3 次 | 3 次 |
| apksigner 调用 | 2 次 | 2 次 |
| apktool 调用 | 2 次 | 2 次 |
| 临时目录抽样最大值 | 1,045,952 KiB | 1,251,964 KiB |

重建约占总耗时的 64.5% / 56.7%，是这两个样本的最大阶段；观测到 aapt2 与后续 Java 重建进程工作，但没有函数级采样证据，不将整个重建时间都归因于资源编译或 ZIP 压缩。DEX 阶段在 B 中显著增加，与 DEX 总量差异方向一致，仍不能据此认定全部来自压缩。

### 独立签名

| 项目 | A：Release | B：Debug |
|------|----------:|---------:|
| 总耗时 | 29.727 秒 | 34.617 秒 |
| 准备 | 0.041 秒 | 0.047 秒 |
| 对齐（含复制临时输入及整包重写） | 22.609 秒 | 26.835 秒 |
| apksigner 实际执行及收尾 | 7.073 秒 | 7.732 秒 |
| Java 版本探测 / apksigner 调用 | 各 1 次 | 各 1 次 |
| 临时目录抽样最大值 | 674,008 KiB | 818,844 KiB |

对齐阶段约占独立签名耗时的 76.1% / 77.5%。不能把它等同于仅“补几个字节”：当前实现会解压每个 ZIP 条目、重新压缩写出，再替换文件。两份独立签名产物均通过 apksigner 校验；它们使用测试证书，不是可用于业务覆盖安装的产物。

### 验证结论与下一步

- 四个完整测量任务均返回成功，无任务标准错误；原始输入 SHA-256 在测量前后相同。临时证书不使用业务密码，两份签名产物单独验证成功。
- 临时测量 runner、其 CLI 和 Java 子进程均结束；未启动 GUI、模拟器或设备应用。PR #143 合并后的主干轻量 CI 通过，不触发新发布。
- 本轮临时脚本按 L1 处理，仅消费既有事件与固定调用类别；无新增生产依赖、公开 API、网络采集或协议变化。详细数据只留本机，不进入公共统计。
- 优先评估同次“加固完成后自动签名”的重复对齐，以及对齐时未改变条目的重复解压/压缩；它们是源码确认的重复工作，不等于已经测出可节省的精确时间。
- 下一阶段先做受限原型和前后对照，保留条目内容/CRC 校验、压缩策略、16 KB 对齐、证书绑定及失败关闭。不能只验证偏移就跳过内容完整性检查，不能把未验证输入直接标为已对齐。
- 整包重建是最大阶段，但直接绕过 apktool 涉及二进制 Manifest、资源及兼容边界，放在前述低风险项之后评审。本轮不重写、不降低 Zstd 档位、不增加 UI 选项；也不因 7 次 Java 调用就优先做微小启动优化。
- 本轮是两个真实包的单次、本机、特定工具与旧兼容资源基线，不证明跨平台、所有 APK、Android 运行速度或正式新壳矩阵。真实工程正在使用该目录，不能把样本目录当临时目录清理。

本轮私有详细记录位于 `/tmp/mocika-apk-cost.VZ6p8O/report.json`，只将去业务化的样本规模、聚合阶段数据和验证边界写入本文；不提交业务包名、签名指纹、完整路径或样本文件。
