# 匿名统计的构建身份隔离

更新：2026-11-12。实现经 #168 合入，生产增量迁移和 Worker 部署已完成。1.5.0-beta.3 已公开为预览版；官方 macOS 包已通过抽验，正常 GUI 启动已确认构建身份写入生产 D1，不将单平台验收扩大为全部平台运行通过。

## 目标与非目标

按桌面工具实际构建的名称、应用标识和版本解释使用量，避免仅凭版本号把不同构建混为本项目。新增信息只描述工具本身，不扫描系统进程，不获取可执行文件路径、机器名、账户名、仓库地址或用户 APK 信息。沿用匿名统计开关，不增加弹窗或界面选项。

名称、标识、版本与提交号都是客户端声明，组合匹配也不是官方产物认证。下游没有合入实现、删除上报或保留全部身份字段时，不能强制识别；旧数据不倒推归属。不引入内置认证密钥、硬件指纹或运行时联网验包。

## 方案与边界

本次为跨客户端与 Worker 的兼容协议变更。沿用现有 GUI 统计、Worker 和 D1，不改共享核心、证书库、CLI／MCP、Android 壳、加固格式或发布流水线，不增加依赖或后台服务。

| 选择 | 取舍 |
|---|---|
| 新接收入口与来源隔离表（推荐） | 保留旧表及协议；有身份和未知来源计数相互隔离，代价是查询需要合并新旧表 |
| 改造现有表主键 | 需要重建线上计数及诊断表，迁移和回滚风险更高，不采用 |
| 仅增加附属名称记录 | 可以观察名称，但相同实例、日期和版本仍互相覆盖，不满足计数隔离目标 |

GUI 私有构建身份模块只负责值校验、不可变快照和键生成，不依赖文件系统或网络。配置状态持有本进程的身份，事件记录使用该身份；网络层只上传已保存快照。Worker 的来源校验与存储映射独立于路由，查询不将来源标签当作认证结果。

## 构建身份

| 字段 | 来源与约束 |
|---|---|
| `product_name` | Tauri 最终生效配置的 `productName`；非空、无首尾空白及控制字符，最多 128 个 UTF-8 字节 |
| `application_id` | 同一最终配置的 `identifier`；最多 128 字节，只接受字母、数字、点和连字符 |
| `build_revision` | 已有编译期 Git 提交号；仅接受 7～40 位小写十六进制，否则为空，不上传 Git 输出原文 |
| `app_version` | 沿用已有桌面工具编译版本；不接受前端或待加固 APK 输入 |

Tauri 已将构建后的配置嵌入程序；在启动时读取该固定配置，不再次解析源码 JSON，兼容平台配置和构建覆盖。下游更改产品配置后重新构建，可自动得到新名称；只改窗口标题、安装文件名或图标不保证改变产品名称。缺少合法名称／标识时继续按未知来源记录，不写死本项目名称作为回退。

来源键由上述名称、标识、可空提交号的 JSON 数组计算 SHA-256；客户端用于本地分桶，服务端从校验后的值独立计算，不信任请求自带摘要。它只用于分桶，不是签名或认证。版本仍是独立计数维度；相同名称不同提交可独立保存，查询时按需合并。

## 客户端兼容与快照

- 旧 `telemetry.daily` 保持旧语义，旧积压仍发送原入口，不补上当前身份。
- 新增独立 `telemetry.daily_sources` 分区，避免旧程序把不认识的来源键归并进旧日计数。现有配置服务按字段差异保存，旧入口应保留该未知分区；需要回归证明。
- 新事件在记录时保存身份快照；同版本改名、不同标识或提交的事件分桶保存，不在上传时用当前构建覆盖历史身份。
- 网络发送旧／新分区时分别使用旧／新入口。新入口不可用时保留积压，不回退旧入口，避免旧服务忽略身份后误收并造成重复统计。
- 成功上传仅清理对应分区的历史快照，当天累计快照保留；既有 30 日积压保留边界不扩大。统计关闭后不发送新旧分区；失败诊断仍沿用固定分类，不带错误原文。
- 不改匿名标识生成方式、应用目录或配置文件名；同一标识可能跨构建出现，不能将各来源去重人数相加。

## 服务端与查询

新增 `/events/daily-v3`，只接收 `schema_version=3` 与合法 `build_identity`。流式请求上限 64 KiB；身份字段严格校验，拒绝身份对象内额外字段；新字段非法时整条拒绝，不悄悄转为本项目或旧协议。原 `/events/daily` 保持旧客户端兼容，但拒绝带新身份的请求，避免新 Worker 接受协议降级。

增量迁移只新增 `daily_usage_v3`、对应固定失败阶段和原因表及索引。主键在既有匿名实例、日期和版本之外加入服务端来源键；计数重传取同一累计快照的最大值，不累加 HTTP 次数，旧快照不能覆盖新值。新客户端单项单日上报上限 10000，本地累计不归零。阶段和原因使用同一来源维度，不与旧表互删。

统一查询保留旧第二代表优先于第一代表的去重规则，再合并第三代表。新旧客户端在切换当天分别保存的是不同事件分段，不因同标识、日期、版本而丢弃旧分段；新入口禁止回退旧入口是避免双写的前提。总活跃始终按匿名实例跨日、跨版本、跨来源去重；次数保留各分段。

公开趋势及现有快照保持全部成功接收口径，不公开名称、应用标识、提交号或匿名明细。私有查询额外提供：

- 已声明构建身份的名称／标识／版本分布及跨版本去重计数。
- 本项目名称＋标识＋公开版本同时匹配的组、其他声明身份组、旧／未知来源组。
- 身份覆盖率；匹配失败或公开版本列表不可用不得填成零或视为可信分类。

私有版本分组与国家／地区活跃分母同时纳入新表；地区仍不关联用户 APK。应用分享与主动错误报告本轮不改协议，继续只能按版本筛选，不能将其匹配结果冒充新增身份归属。

## 部署与回滚

1. 本地证明旧库可增量迁移、重复执行不改变旧表和原始记录；记录生产 Worker 版本及绑定。
2. 仅执行[新增迁移](../../tools/stats-worker/migrations/0006_usage_build_identity.sql)，核对三个新表为空、旧表结构不变。不得重放整个 `schema.sql` 或包含旧操作的迁移。
3. 部署已验证 Worker，保留现有变量、密钥、绑定、域名与定时任务；先验证旧入口及趋势正常，新入口非法请求拒绝，不构造生产普通用户事件。
4. 桌面客户端在下一次明确批准的预览版构建中交付；不移动或替换已公开 Beta.2。发布前新表无自然上报属于正常，不能宣称已识别真实用户。
5. 回滚优先恢复已记录 Worker 版本，新表保留。旧 Worker 对新入口返回 404，新客户端保留积压；不删除表、不重归属历史，也不将第三代表重复写入旧表。
