# 可选资源保护研究

本文记录对 `assets/`、`res/raw/` 等高价值业务文件进行可选保护的研究边界。典型对象包括离线模型、数据库、规则文件、音视频和游戏资源。该能力不属于默认 APK 加固流程，也不代表能够阻止已控制应用进程的攻击者取得运行时明文。

## 采用的方向

- 由用户显式选择需要保护的资源，不默认加密全部资源。
- 加固端将目标文件转换为带版本、路径标识和完整性认证的加密载荷。
- 应用通过 Mocika Shield 提供的读取接口获得字节流、临时文件或受控缓存。
- 优先支持 `assets/` 中由业务代码主动读取的独立文件，再评估 `res/raw/`。
- 根据文件大小支持整块或分片认证加密，避免大型模型和视频造成不可接受的启动内存峰值。

## 不采用的首轮方案

- 不通过 Hook 透明拦截或替换系统 `AssetManager`。
- 不承诺第三方 SDK 在完全不改代码时仍能直接读取加密资源。
- 不加密 Android 安装、资源索引、主题、布局或系统启动阶段必须直接访问的文件。
- 不把明文长期释放到公共存储；确需临时文件时只能使用应用私有目录并定义清理策略。
- 不复用 DEXB v5 表示资源载荷；资源格式必须独立版本化并失败关闭。

## 首个原型范围

1. 仅支持用户列出的 `assets/` 文件。
2. 提供输入流和字节数组两种应用侧读取方式。
3. 使用认证加密并绑定应用签名，篡改、错签名或版本不匹配时拒绝返回明文。
4. 覆盖小文件、百兆级文件、随机读取需求和并发读取。
5. 记录 APK 体积、首次读取耗时、峰值内存、缓存占用和异常恢复。

首个原型不进入 GUI 默认选项；应先通过独立样本验证业务改造成本，再决定是否提供资源清单界面或 CLI 配置。

## 关键问题

- 用户如何稳定标识经 aapt2 处理前后的资源路径。
- 大文件使用整块认证还是分片认证，如何避免可交换分片和回滚。
- 需要文件描述符、随机访问或 mmap 的第三方 SDK 如何接入。
- 多进程并发、进程重启和缓存清理如何保持一致。
- AAB Asset Pack、动态功能模块和 Play 分发是否保留载荷结构。
- Android 4.4 与现代系统在文件映射、私有缓存和密钥派生上的差异。

## 验收与停止条件

- 未配置的资源完全不改变；配置资源无法从 APK 静态获得可用明文。
- 错签名、载荷篡改、分片错序和缓存损坏均失败关闭。
- 应用侧接口具备清晰的生命周期和错误语义，不要求业务依赖 ART 或系统私有 Hook。
- 性能按文件大小和访问模式可预测，不在主线程隐式解密大型文件。
- 若主要用户场景都依赖第三方 SDK 的原始文件路径且无法合理改造，保留调研结论，不进入正式实现。
- 若 AAB 分发会改变或拆分载荷，等待正式 AAB 链路解决后再继续。

## 路线定位

资源保护只有在出现明确用户样本和读取方式后才安排版本。它与 DEX 内存加载、方法代码分离和反调试相互独立，必须使用独立配置、协议、回归和发布说明，不能作为默认“更强保护”打包上线。
