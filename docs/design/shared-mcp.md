# MCP 共享资料与证书范围

2026-11-09：维护者已确认采用宿主显式启用、固定应用上下文及证书编号白名单的方案。本文扩展[原本地 MCP](local-mcp.md)，不替代[受控共享绑定](shared-agent-binding.md)。源码已接入，实际测试与未覆盖范围见[共享应用计划](../process/shared-application-plan.md)。

## 选择与边界

采用显式共享模式，保留原外置配置模式。没有自动开放整库，也不保持另一套隔离产品状态或要求 GUI 常驻。已合入基线提供脱敏证书查询、共享受控加固、[单次独立签名](controlled-signing.md)及[资料管理首批](shared-mcp-management.md)，复用原执行开关与证书范围。当前分支按[生命周期方案](mcp-certificate-lifecycle.md)补证书校验／导入／创建／删除记录，清空全局默认仍未开放；实际结果见[专项计划](../process/mcp-certificate-lifecycle-plan.md)。

Skill 可经已实现 CLI 使用上述管理能力，不等于 MCP 已有相同工具或写权限。不新增依赖、数据库、网络接口、后台服务、遥测、安装器或日常重型 CI；不修改壳、GUI 界面、公开版本或发布流程，不更改维护者真实库或全局 Agent 配置。其他平台仍后置。

## 宿主启动契约

```bash
# 路径及编号由宿主在本机确定，不照抄占位值。
shield mcp serve --use-shared-settings \
  --input-root /已授权输入目录 --output-root /已授权输出目录 \
  --allow-certificate <已保存证书编号>
```

- `--use-shared-settings` 显式启用共享来源；否则默认不读应用证书库。只有该模式允许 `--allow-certificate`，可重复指定，最多 64 项且不能重复。编号限 1–128 位 ASCII 字母、数字或 `-_.`，不是路径或 Alias。当前生命周期扩展允许留空，含义是不授权任何旧证书，不是允许全部。
- 旧证书白名单不能由工具任意改写；仅当前会话创建／导入确认成功的新编号自动加入，删除成功后撤销，总范围仍不超过 64 项。写操作共用宿主 `--allow-execution`；签名及管理一次明确请求直接执行，无额外计划或重复确认，宿主本身审批策略不变。重启不自动恢复新编号授权。
- 可选 `--app-home` 属于宿主启动配置，不是工具参数。缺省使用 GUI 相同目录，指定时固定隔离上下文；无效不回退，不能从请求换库。
- 共享模式可无项目文件；如宿主传 `--config`，继续固定其字节／物理身份，不接受混入外部签名材料。共享签名及无需新密码的命令不继承外部密码；仅固定导入／创建命令使用宿主预置的两项约定环境，不改全局环境、不通过工具读取密码或回退外部签名材料。
- 原模式保持原三项只读工具，执行仍要求固定项目及原密码环境。

共享上下文目录与输出目录不得互相包含。保留原路径用于密文兼容，不通过 canonicalize 改写派生上下文；仅核对目录身份、查找位置及文件形态，不固定整库／GUI 配置摘要。父目录改向、目录替换、资料文件变为链接／非普通文件时失败关闭。缺失资料保持缺失，查询不创建；同一固定范围内正常创建配置或更新 SQLite 不误判为材料改变。

## 工具及公开结果

共享模式新增只读 `shield_certificates`，可选 `certificate_id` 进一步筛选，未知字段及白名单外编号直接拒绝。复用 `cert list` CLI 和同一应用库，不在 MCP 复制 SQL、解密或写入逻辑。原摘要只在本地管道解析，经白名单过滤后才返回，不把整个 JSON 送给模型。

每条公开记录只有 `id`、`is_default` 和依次对应 V1–V4 的 `signing_versions` 四个布尔值；不含名称、路径、Alias、备注、校验说明或密码，不返回整库总数。缺失库／空库可返回空数组。保留现有 CLI 输出上限，过大或畸形响应失败关闭，不用通用数据库读取兜底。

共享 `shield_plan` 必须明确输入、输出及允许范围内 `certificate_id`，不能只说“以后用默认项”。可选 `runtime_profile` 没有默认值，省略时继承 GUI 共享模式；ABI 排除仍逐次授权。规划／执行不接受配置路径、密码、Alias、绑定或环境变量名；生命周期工具仅按其专用有限参数接收新材料标识。

加固执行／状态查询参数保持原样：加固只收 `plan_id` 和原摘要，不接受新输入、输出、证书或绑定。只有宿主允许执行时才发现写工具，查询不授予写权限。独立签名及管理写入按各自单次参数处理，不复用加固的待消费计划。

## 会话绑定与执行

CLI 返回版本 3 计划及绑定，MCP 复用 CLI 的严格解析，检查来源版本、白名单编号及原请求编号一致。绑定只留在本会话有限计划记录中；公开计划、执行响应及状态查询均移除 `shared_binding`，不要求模型回传它。断开／到期后不恢复，不新增计划数据库或全局一次性票据。

执行从已消费记录中取得绑定，经原 `agent protect` 处理。父端仍是唯一交付者，MCP 不重实现加固、签名或提交。默认项／GUI 模式变化不替换已有身份；相关记录或实际材料变化仍阻断。

原 16 条容量、10 分钟期限、一次消费、摘要不匹配不消费、开始尝试即消费、取消／断开／超时、未知收尾锁定及产物证据保留继续有效。执行结果的私有绑定须与缓存一致；旧来源必须返回版本 2，异常不换来源或自动重试。

2. 验证启动范围、缺失库不创建、默认工具不变、白名单筛选、无自由文本输出及不存在写管理工具。
3. 隔离资料和自有 APK 验证双模式、默认／备注／模式变化、证书指纹、SDK 对齐、一次消费、记录变化及状态无绑定。
4. 补共享取消／断开及未知结果，保留旧协议回归；完整 `.app` 源码外验收与实际宿主注册分别记录。

## 单次独立签名

维护者确认的简化方案已在开发特性接入并通过本机完整 macOS `.app` 验证，具体设计与实际证据见[受控签名设计](controlled-signing.md)及[任务计划](../process/controlled-signing-plan.md)。实际宿主注册仍未验，不据此推定公开 1.4.3 安装包已经更新。

- 仅共享模式且启用原 `--allow-execution` 时注册 `shield_sign`。独立签名基线的外置只读／执行为 3／5 项、共享只读／执行为 4／7 项；管理首批为 5／11 项，生命周期扩展为 5／15 项，外置不变。不增加 `--allow-sign` 或签名专用状态工具。
- 参数仅为相对 `input`、`output` 和可选 `certificate_id`。一次调用内部规划并执行 `agent sign`，不接受密码、Alias、版本覆盖、运行模式、计划引用或摘要，不加固、不安装、不发布、不覆盖。
- 显式编号直接固定；省略时，唯一允许项直接选定，实际存在性由 CLI 检查。范围多项时经原 `cert list` 的脱敏投影选择范围内共享默认项；默认项在范围外或无法确定时返回 `CERTIFICATE_REQUIRED`，不猜选、不挂起询问，不在 MCP 复制 SQL 或解密。
- 签名记录直接进入运行态，与加固共用容量、期限、活动调用和未知停写规则；其引用不能作为加固计划消费。返回的 `plan_id` 仅供原 `shield_execution_status` 查询。
- 请求 `_meta.progressToken` 时，阶段通知的 `_meta["mocika-shield/plan_id"]` 提供同一任务查询引用，便于取消后查询；不要求调用者先取得引用再签名。进度仍只表示阶段，不表示耗时百分比。
- 默认项查询和签名共享同一次调用期限，不为第二个子进程重置预算。结果仅接受独立计划 4 与有限签名阶段；换证书仅返回固定 `SIGNING_CERTIFICATE_CHANGED` 警告，不转发原文。
- 普通规划错误只有在 CLI 确认工作组／管道停止并实际关闭临时目录后，才可报告清理完成并继续处理后续明确请求。停止、提交、回执或清理未知仍锁住两类写操作，不按错误名称猜测已安全，也不自动重试或重启服务。
