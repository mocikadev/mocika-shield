# Agent 受控执行器

最后更新：2026-11-06。维护者已明确确认“CLI 工作子进程隔离，首版仅支持 V1–V3”。本文限定实现边界，开发特性已接入[单任务命令](agent-cli-contract.md)，不代表公开 Release 已包含能力；完成情况见[任务与验收记录](../process/agent-integration-plan.md)。

当前已通过默认关闭的 `agent-executor` 开发特性接通 macOS 内部父端及工作入口，复用统一计划完成真实小包和 ClassIn 大包的加固、签名、验收与无覆盖交付。该特性只供维护者从源码显式验证，不进入默认 CLI、GUI 或现有发布 CI；对应的 `tempfile`、`rustix`、`libc` 运行时依赖也仅在显式启用时加入。Linux、Windows、正式写命令、Agent 客户端及安装分发门槛尚未通过，不宣称跨平台正式交付。

## 证据与方案决策

现有 `protect_apk` 的取消标志仅在阶段边界检查，不能中断正在等待的 Java；签名链路没有统一取消参数。旧加固/签名可以直接写最终位置，不能把它们简单串联后称为受控执行。V4 会额外生成 `.idsig`，两个独立文件不能靠一次普通重命名一起原子提交。

| 方案 | 取舍 |
|------|------|
| CLI 工作子进程隔离（已确认） | 父进程管理任务、整组停止和发布；工作进程复用核心。保持核心公开接口和 GUI 不变，但须维护有限内部协议及各平台进程生命周期 |
| 核心内统一任务上下文 | 可细化阶段取消，但需贯穿检查、Java、加固和签名接口，迁移旧调用方；仍需解决后代进程和父进程异常退出 |
| 只包装现有取消标志和软超时 | 无法证明 Java 已停止，不能满足受控执行门槛，不作为正式实现 |

不新增 crate、常驻服务、队列、网络端口、模型 SDK 或统计。先完成内部基础层与失败路径验证，最后开放一个单任务执行入口。旧 CLI 和 GUI 保留原行为；新入口 V4 明确拒绝，不静默关闭，不影响旧签名功能。

## 职责与数据流

- CLI 父进程拥有任务状态、总期限、取消信号、私有暂存和最终提交权。除自身纯 Rust 检查外，所有可能启动 Java 的准备、证书核对、预检、加固、签名及最终验签均进入受控工作进程，不能在计时前做一轮无界 Java 检查。
- 同一 CLI 的内部工作入口只接收有限任务描述，复用核心和同一份计划语义，只写本次私有目录。不得接受任意 shell，不将最终用户路径作为核心输出。
- 工作进程输入、配置、资源、JAR、keystore 由任务快照绑定，复制到私有目录并流式核对。Java/JDK 不整套复制，须记录并复核所选工具身份；不承诺完整依赖锁定。
- 密码只由宿主本地注入子进程环境，不写协议、临时任务描述、参数、摘要或日志，不读 GUI 数据库。环境不是同权限进程间的凭据保险箱。
- 计划摘要只防材料/配置漂移，不是授权令牌。写操作授权、ABI 排除、设备操作和发布许可互不替代。

只读 `plan-protect` 仍返回 `execution_ready: false`，可描述 V4 输出但不执行。它与内部执行入口共用 CLI 私有准备逻辑；执行路径在启动 Java 之前明确拒绝 V4，不把含密码的配置序列化，不复制核心资源或 ABI 规则。

### macOS 开发验证入口

仅当显式启用 `--features agent-executor` 且目标为 macOS 时编译隐藏的 `__agent-probe`、`__agent-worker`，默认构建不注册二者。探针请求是本机私有 JSON 文件，仅包含本地配置、输入、最终输出、资源模式、逐次 ABI 排除和总期限；拒绝未知字段及密码字段，文件须为当前用户独占的普通文件，不接受链接、宽松权限或超过 16 KiB 的正文。总期限限于 1–3600 秒，不受阶段进度刷新。

父端分两次受控工作：准备进程得到计划、证书及八类源身份摘要，确认停止后父端复核；执行进程重新计算同一计划，摘要吻合后才固化六类材料并调用核心。两次准备、真实 Java、加固、签名、验收、复制和提交前复核均纳入同一个总期限。计划描述与源证明文件只在本次私有目录中存在，不作为公开协议或凭据存储。

工作进程的临时环境变量和 JVM 的 `user.home`、`java.io.tmpdir` 指向本次任务目录，使 apktool 框架缓存及临时文件不落宿主用户目录；不修改宿主的 `HOME`、Java 选择或全局环境。宿主已有非空 `JAVA_TOOL_OPTIONS`、`_JAVA_OPTIONS`、`JDK_JAVA_OPTIONS` 时探针明确拒绝，不覆盖或执行未知注入参数。任务目录包含无法安全表达的引号、反斜杠或控制字符时拒绝；中文和空格已验证。

父端读管道使用独立线程和容量为 4 的有界阻塞队列，短时合法突发产生背压，不丢消息或误判超限；监督线程每次最多等待 20 毫秒，持续检查期限。停止后有界排空并回收读线程；无法证明工作组停止或读线程回收时保留目录并返回未知，不以析构清理代替停止证明。启动时限已到的早退路径也执行同样的停止/回收门槛。

工作进程复用核心验签、加固标记和证书指纹，再给出有限摘要证据；父端在确认停止后重新核对源身份、材料与实际文件、静态对齐及固化输出摘要。安装 ZIP 对齐只要求 `Stored` 未压缩条目，签名器追加的压缩条目不要求偏移对齐；不得签名后重写 ZIP 破坏 V2/V3。真实样本另外通过 SDK `zipalign -c -P 16 4` 独立检查，但该检查不证明 ELF 页大小或设备运行兼容。

探针返回有限 JSON，并显式标记 `experimental: true`、`retryable: false`；无原始路径、Alias、密码或工具日志。工作消息新增有限的计划证据与拒绝枚举，没有任意文本。内部取消信号及原生停止已验证，但尚无正式可交互取消接口；不能把工作进程租约或组件取消测试称为 Agent 客户端取消已交付。

维护者真实专项入口（必须显式选择经授权的本机 APK）：

```bash
SHIELD_AGENT_TEST_APK=/绝对路径/测试.apk \
SHIELD_AGENT_TEST_ZIPALIGN=/绝对路径/Android/sdk/build-tools/36.0.0/zipalign \
cargo test -p shield-cli --features agent-executor --test execution_probe \
  --offline --locked 真实安装包临时证书副本隔离加固签名与无覆盖交付 \
  -- --ignored --exact --nocapture
```

测试自行创建临时证书并重新签名副本，原 APK 只读；不读取维护者业务证书或 GUI 数据库。输出仅用于测试且随测试回收，不能拿来覆盖安装业务包。运行期间不要原地重建同一路径的验证二进制：执行器文件身份已经在下述检查点绑定，持续变化会阻断交付，而不是支持热更新。完整 JDK 冻结与发布来源真实性仍不在该保证内。

### 执行器与工具身份

`identity.rs` 只负责可执行文件的身份，`launch.rs` 只负责同一执行器的启动、私有描述和局部工具选择；父端继续拥有期限、停止及提交，工作端继续复用核心业务规则。没有新 crate、依赖、核心公开接口或全局环境状态。

- 首次启动前绑定选定 CLI 的查找路径、解析路径、SHA-256、设备/文件编号、权限、大小及纳秒级修改/变更时间；摘要读取前后核对文件状态。后续阶段不能换为另一个路径或同字节但不同文件的执行器。
- 父端首次绑定时读取完整摘要，启动前、握手后允许开始前、准备结果读取后及最后提交前采用路径、文件编号、权限和时间等元数据快速复核，最终产物验收时再重算完整摘要。工作进程在调用 Java 前核对自身文件身份与描述相符，在签名前和提交候选证据前再次复核。避免在每个检查点重复哈希整个 CLI；父端大文件哈希保留总期限/取消检查点，不因身份检查重置时限。
- 准备完成后绑定计划中的 Java/keytool 身份；父端执行启动和握手前先复核，工作进程在重新规划前复核并在规划后核对工具快照吻合。加固阶段边界、签名前后、候选返回及父端验收/提交前继续检查。持续改写、替换、权限变化、查找链接改向均阻止交付；可分别返回固定 `EXECUTOR_CHANGED` 或 `TOOLCHAIN_CHANGED`。
- 执行工作进程的 PATH 前置计划中 Java 的原查找目录，保留该子进程原有 PATH 作为其余工具查找来源。沿用核心的 Java/keytool 解析，不复制 JDK 或把单个 Java 二进制挪到任务目录。仅调整新建子进程环境，不修改宿主 PATH、JAVA_HOME 或默认 Java；重新规划结果与原计划不相符时仍拒绝。
- 私有 `bootstrap.json` 格式升为 `2`，最多 64 KiB，增加执行器和可选工具身份证明；准备模式必须无工具绑定，执行模式必须有绑定。请求文件仍限 16 KiB，不增加密码/程序/任意参数字段。控制帧、公开检查响应、计划身份、资源与 DEXB 版本不变，旧/新描述不混用。

这是本机可信安装与非对抗环境中的变更发现，不是执行器的发布签名或内存代码证明。第一次快照之前的替换不能追溯；路径检查与实际执行之间仍有窗口，瞬间替换再恢复、包装启动器的间接目标、完整 JDK 模块/动态库及外部依赖都未冻结。阶段检查不能保证其他工具在任意瞬间绝不被解析/尝试启动，更不能抵御同权限恶意程序；不据此扩大权限沙箱承诺。遇到变更须停止本次任务并重新人工检查，不自动回退或重试。

## 暂存与单 APK 提交

1. 最终输出父目录必须已存在，任务只在该目录的同一文件系统创建独立私有暂存，不创建或占用最终文件名。
2. 最终位置存在普通文件、目录、软/硬链接或悬空链接，均拒绝。准备时的检查不替代提交时的无覆盖原语。
3. 工作进程完全停止且产物通过加固标记、签名、证书与对齐核对后，父进程把产物复制成自身持有的新文件，逐块检查期限/取消并计算摘要。输出摘要必须匹配工作进程提交的验收证据；新文件同步完成后才能发布。复制只写暂存，不逐字节写最终位置。
4. 发布仅使用原子无覆盖原语。Unix 基础实现固定父目录句柄，以相对句柄硬链接发布一个已经完整写好的文件；不支持硬链接或跨文件系统时失败，不回退到覆盖重命名或直接复制。Windows 必须另行实现并原生验证后才能启用，不用 Unix 测试替代。
5. 输出父目录和暂存目录须在提交前复核；Unix 发布绑定已打开的父目录，不因随后路径改向写入新目录。提交后目录路径已变化时记录位置不确定，不能声称原请求路径交付成功。
6. 提交点之后，清理或目录同步失败只能成为附加状态，不得改写成“没有输出”、删除已经发布的 APK 或自动重试。原子可见与断电持久性分开记录。
7. 清理仅针对本次创建且身份仍匹配的暂存目录；无法确认目录身份时保留并报告，不扫描或清理其他任务、用户证书或缓存。

提交基础层显式区分复制检查点和最后的提交检查点：复制与身份复核全部完成后才允许父进程进入提交临界区，然后调用原子原语。目标已存在的冲突明确拒绝；其他链接调用错误保守返回 `CommitUnconfirmed`，避免网络文件系统等“已生效但回执丢失”的情况被误报为无输出。此时保留本次暂存及已固化文件，连析构兜底也不得擅自清理；父进程必须记录状态未知，不自动重试。

暂存基础层只核对文件边界和字节身份，不能单独证明 APK 合格或进程树已停止。其发布方法只能由通过生命周期和产物验收门槛的父进程调用。它不是权限沙箱，不防御同用户权限的恶意进程、恶意 JAR 或对文件系统的对抗性修改；目录复核也不是对任意文件系统故障的事务保证。

## 生命周期与有限协议

状态流为准备、启动、执行、取消中、收尾、提交，再进入成功、失败、已取消、超时或未知。一次任务只发一个终态；客户端断开/超时不等于停止成功，状态未知不得自动重跑。发布前可取消；提交点已发生不能再报成“已取消且无输出”。

- Unix：独立进程组，停止整组而非只杀工作进程；不使用 `killall java`。保留工作进程句柄直到整组停止，避免提前回收 PID 后误杀复用进程。父进程死亡通过租约/控制管道 EOF 触发停止；管道不能被 Java 继承消费。
- Windows：工作进程握手执行前纳入 Job Object，关闭任务句柄停止后代；入 Job 失败即停止，不绕过权限或退回无控制执行。
- 工作进程握手、消息长度/总量、进度频率和错误种类均有限；非法消息、EOF、异常退出、超限都失败关闭。标准输出由协议独占，核心自由文本与 Java 原始输出不转发模型。
- 总期限覆盖准备、握手、工作、复制和收尾，纯 Rust 大文件操作也逐块检查。文件系统调用本身可能阻塞，不承诺硬实时中断。具体默认期限结合已有大包耗时验证，不拍定过短阈值。
- 停止证明不足时不发布，不冒险删除仍可能写入的目录；成功也须确认没有继续写任务。平台未实现或未验证时拒绝新执行入口，保留只读计划，不降级为旧命令串联。

### 候选内部控制协议

协议和状态规则分为 CLI 私有模块，依赖方向为消息编解码使用有限生命周期数据，生命周期不依赖管道、文件系统、GUI 或消息解析。两者先由组件测试验证，再接入上述开发特性；不新增进程服务或公开核心执行 API。

- 编码为四字节大端长度加 JSON 帧；单帧正文最多 4096 字节，每个方向最多 128 帧、256 KiB（含长度首部）。接收先核对长度及预算，再分配正文；不使用无界按行读取或重新同步。
- 信封必须包含内部协议版本 `1`、固定 16 字节任务标识、从零严格递增的序号和消息。任务标识仅绑定一次本地任务，不是设备标识、认证凭证或持久身份；该协议版本与外层 CLI 检查、资源和 DEXB 版本无关。
- 父进程仅发开始、停止；工作进程仅发握手、有限阶段进度、候选证据或固定错误类别。读写两端都检查方向，不信任对方自己声明身份。消息没有任意命令、日志、路径、Alias、密码字段；拒绝未知/重复字段、未知枚举、错误类型或尾随数据。握手使用空结构体变体，避免序列化库对单元变体额外字段的忽略行为。
- 进度只有 12 个有限阶段，不传原始文本、百分比或心跳；每阶段至多一次、允许省略但禁止重复或倒退，不能靠频繁进度延长总期限。候选只含固定长度摘要、证书指纹、字节数和三项验收声明，声明本身不证明 APK 真的合格。
- 任何编解码、序号、标识、预算或传输错误都永久关闭本次编解码会话；不尝试丢弃日志后继续，也不自动重发。发送失败不证明消息没有送达，后续须走整组停止流程。
- EOF 永不代表成功。主动停止期间的流关闭可以等待平台停止证明；其他阶段意外断流使任务失败关闭。工作进程发出候选后再发进度或结果，会使候选失效。

该编解码器只限制消息大小和内容，不自带操作系统定时器。开发父端已经把可能阻塞的管道读取与期限/取消监督分离，使用上述有界队列，并通过整组停止解除读取；不在唯一监督线程同步读帧。本节控制消息仍不是完整任务计划，配置/材料通过独立私有描述绑定。

开发阶段另以显式构建的同一 CLI 调用真实工作入口，验证执行失败、内部取消、执行中超时、计划/材料变化、输出占位和工作进程异常退出。故障门槛仅由测试专用临时 Java 启动器提供，不进入正式请求或配置；父端仅保留私有进程构造函数的测试接缝，不允许调用者选择任意执行程序。取消/超时及组长异常退出后，以停止证明、终态后后代心跳不再写入、无最终文件和原包不变共同验收；真实专项不进入日常重型 CI。详细结果及剩余边界见[验收记录](../process/agent-integration-plan.md#真实工作入口异常回归记录)。

### 候选父进程状态规则

状态机使用单调时间，创建时确定总期限；拒绝空/溢出期限及时间倒退，阶段和消息不刷新期限。不采用事件总线、全局可变状态或通用任务框架，父进程独占状态。

- 收到握手且平台层已确认隔离，才允许发送开始；工作进程消息不能设置平台隔离或整组停止标志。
- 候选须绑定预期计划和证书，字节数非零，验签/加固标记/对齐声明齐全；之后先请求停止，仍不能提交。平台确认整组停止后，才进入父进程验收，再允许复制固化和最后提交。
- 取消/超时只有请求停止、确认停止两步都完成才有相应终态；停止无法确认则报未知、保留活动目录。故障不被后来取消掩盖，保留首个故障；取消和超时保留首先观察到的原因。
- 最后提交检查点之前，取消或总期限到达会阻断提交；临界区内只记录请求，等明确回执后决定。提交成功以事实为准，清理/目录同步失败成为附加状态；提交明确未发生才可报取消、超时或失败。提交回执未知则记录输出不确定，不清理、不重试。
- 提交后路径位置不确定时，结果为未知但保留“已提交”的事实；不能伪装成无输出。每任务终态只能取一次，重复回调、后到取消和超时都不能复活任务或发出第二个终态。

前期组件联动测试显式模拟隔离、停止和验收事件，只证明状态/文件/消息边界相互一致。进程控制和真实 APK 专项分别补充原生停止及完整工具链证据；正式命令、分发和客户端门槛通过之前，公开只读计划的 `execution_ready` 继续为 `false`。

### 私有材料包候选

`task_materials.rs` 只负责把已规划的文件身份固化到本次暂存，不解释配置、执行工具或访问 GUI 数据库。原 APK、原配置、keystore、apktool、apksigner、所选资源六类材料缺一不可且不能重复/错配，固定输出名由角色决定，不从 JSON 接收路径。Java/keytool 及完整 JDK 不复制，不声称锁定其全部依赖。

目标为当前用户拥有的私有目录，新建 `0700` 材料子目录，文件 `0600`、只新建不覆盖。按原始查找路径复核链接身份，逐块复制和核对计划摘要/长度，复制与重新读取均有取消/期限检查点。材料变更、取消或 I/O 失败不生成完整索引，留下的本次部分材料交给停止确认后的父进程清理，不在复制函数内擅自递归清场。

索引 `materials.json` 为本地私有格式 `1`，仅六个固定角色、长度和 SHA-256，正文最大 4 KiB；没有密码、Alias、原始路径或执行命令。重新读取要求索引摘要一致、字段/角色完整、实际材料摘要一致，拒绝软硬链接、非普通文件及宽松权限。索引摘要与加固计划摘要不同，必须在后续私有任务计划中绑定，不能把它当执行授权。

原配置可能含相对路径和 Alias，仅按原样保存为本机身份材料，不代表该文件可以在暂存位置直接解析执行。开发工作进程沿原配置位置解析，显式绑定固定角色、原计划摘要和已选选项，再复用核心校验；签名凭据只在内存及本次子进程环境中传递。材料索引须匹配原计划的角色、大小和摘要后再核对实际副本，不能把从副本自算的索引摘要误当权威计划。

### macOS 原生进程控制候选

`native_group.rs` 只管理自己创建的独立进程组，`native_group/macos.rs` 封装有界原生只读查询，用于本机组件测试及上述显式开发特性。没有额外监护进程或常驻服务，不按名称查杀 Java。当前实现不在 Linux/Windows 启用。

- 组创建及确认在授权开始前完成；停止时先用 `waitid(WNOWAIT)` 观察组长退出，不提前 `wait/try_wait` 回收 PID。组长仍被父进程保留期间，使用原生组列表和进程状态确认本组已无可运行成员，最后才回收组长。
- macOS `proc_listpgrppids` 返回进程个数，不是底层列表接口的字节数；最多检查 4096 个 PID，超限/短读/无法确认都不报成功。组长已有肯定退出证明时不再要求其详情查询成功；其他成员需确认已退出/僵尸或不再属于本组。真正的权限失败直接失败关闭，不提升权限、不改用全局进程扫描或重试绕过。
- 工作进程在任何实际工作之前安装租约读线程：独占读取既有有限父端协议，开始只交付一次，停止、EOF、重复开始或坏帧触发本组停止。租约从标准输入复制为带执行时自动关闭标志（`CLOEXEC`）的独立句柄，随后将标准输入重定向为空设备，Java 不会继承消费或延长租约。
- 父进程的取消、真实期限到达、正常收尾和异常离开作用域共用停止入口；只有原生证明确认后才能向状态机报告整组停止。无法确认时不回收组长来继续按复用 PID 发信号，不假装取消成功，也不清理活动暂存。
- 租约是工作进程内线程，不是权限沙箱或内核托管：父进程退出且工作进程仍存活时可以触发清场；若父进程和租约工作进程同时异常退出，不保证自动清场。主动改组/创建新会话逃离本组、操作系统不可中断状态和同权限恶意进程也不在保障范围内。这些情况不得据此自动提交、清理或重试；若未来要求更强故障保证，需另行评审监护进程或平台隔离方案。

本机原生组件测试启动测试二进制、其子孙进程及临时心跳写入，验证开始门槛、实际时钟到期、取消后写入停止、工作进程退出后的后代清场、父进程退出租约、作用域清理、控制断开/重复开始和后代标准输入隔离。另有开发探针测试真实期限停止挂起工具，以及小/大 APK 的真实 Java/签名和最终产物验收。组件夹具的就绪文件仍不是正式工作协议；Linux、Windows Job、Agent 客户端及设备运行继续独立设门槛。

## 实施顺序与验收

1. 暂存及原子无覆盖提交基础：竞态占位、链接/目录冲突、摘要错误、取消、提交点与清理失败；当前先在本机验证，不开放命令。
2. 有界内部协议、私有计划与状态机：材料快照、凭据边界、V4 明确拒绝、唯一终态及取消/期限。
3. Unix 进程组、父死租约及 Windows Job：启动前握手、孙进程停止、异常退出与资源回收；必须分别原生验证。
4. 复用核心完成真实样本加固、签名、验签/指纹、加固标记及对齐核对，再连接父进程提交。验证失败/取消/超时无最终产物、原包不变，旧命令和 GUI 回归不受影响。
5. 满足已启用平台的完整门槛后才开放写命令，随后再做 Skill/MCP 和可安装交付。不新增逐提交重型 CI，不预占版本或发布。

回滚只需移除 CLI 新入口及内部执行模块；不改持久化、资源协议、DEXB 或已有加固 APK，不迁移 GUI。架构或 V4 边界发生变化需重新确认，不能把本次批准扩展成多产物事务或核心接口迁移许可。
