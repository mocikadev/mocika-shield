# Agent 受控执行器

三平台 `1.5.0-beta.1` 已交付受控 CLI／MCP。执行器采用工作子进程隔离，父进程拥有期限、停止确认和最终提交权；不是把普通加固和签名命令串起来。公开接口见[命令契约](agent-cli-contract.md)，实际证据见[平台验收](../process/agent-desktop-platforms-plan.md)。

## 方案与职责

普通核心取消主要在阶段边界检查，无法靠一个布尔值中断正在等待的 Java。为兼容旧 GUI／CLI，保留核心接口，由受控父进程监督准备与执行两个工作阶段。

| 单元 | 拥有的状态 |
|---|---|
| 父进程 | 总期限、任务状态、停止证明、产物固化、最终提交与收尾回执 |
| 工作进程 | 同一计划规则、Java 工具和核心业务，只写本次私有暂存 |
| 材料层 | 固定角色、文件身份、流式复制与摘要，不解释 APK／签名业务 |
| 原生层 | 进程组或 Job、管道及文件句柄，不决定业务成功 |
| 协议层 | 有界编解码、方向、身份与序号，不代替停止证明 |

所有可能启动 Java 的准备、证书核对、预检、加固、签名和验签都在受控工作进程内，不能在计时前做无界检查。GUI 不因共享业务能力而自动迁移为这套执行器。

不新增守护进程、后台队列、模型 SDK、网络服务或任务数据库。首版只交付 V1–V3 单 APK；V4 的 APK／idsig 是多文件问题，明确拒绝，不静默关闭。

## 计划与材料

输入、配置、证书、工具、资源及有效参数必须固定；执行重新计算并匹配原计划。外置配置与共享证书是两个完整来源，不混合密码或重新选择默认项。

私有描述／材料索引不含密码、任意程序或 shell 指令；拒绝未知字段、超限、链接及非普通文件。Unix 私有目录／文件使用 `0700/0600`，Windows 在创建时限制 ACL；它们不是同权限恶意进程之间的沙箱。

外置配置按原路径解释，不能复制后换基准解析相对路径。共享来源允许没有项目文件，使用记录绑定和有效参数；当前角色与私有版本见[共享绑定](shared-agent-binding.md)，不能沿用初期“六角色缺一不可”的假设。

密码由本地共享服务或宿主预置环境提供，只存在受信任执行内存与工具子进程环境，不进入参数、索引、摘要、结果或日志。同权限／高权限进程仍可能读取环境。

## 执行器和工具身份

父进程固定当前可信 CLI 的绝对路径，并在相关阶段复核身份；Java、keytool、JAR、资源及签名材料按计划绑定。相关变化停止本次任务，不回退另一工具或证书。

不复制完整 JDK，不冻结所有动态库／模块和包装启动器间接依赖；快照前的替换、瞬间替换再恢复及路径检查与执行间窗口不在完整来源认证承诺内。任务存活期间不能原地编译替换同一路径的 CLI。

## 有界内部协议

- 四字节大端长度加 JSON，单帧最多 4096 字节；每方向最多 128 帧、256 KiB，分配前校验预算。
- 信封检查内部版本、固定 16 字节任务标识、严格递增序号及方向；任务标识不是安装 ID 或认证令牌。
- 父端只发开始／停止，工作端只发握手、固定阶段、候选证据或有限错误。拒绝重复／未知字段、错误类型、尾随数据及非法状态。
- 有限阶段可省略但不能重复或倒退；进度不延长期限，候选声明不等于 APK 已实际验收。
- 编解码／传输失败永久关闭本次会话，不扫描日志后重同步、不重发；EOF 永不代表成功。
- 阻塞读取与生命周期监督分开，有界队列和有限收尾不能被慢读拖成无限等待。

控制消息不是完整任务计划；配置、材料和有效设置另有私有描述与身份绑定。公开逐行事件是另一协议，不混用内部帧。

## 停止与生命周期

```text
准备 → 启动 → 执行 → 停止／收尾 → 验收 → 提交 → 唯一终态
```

握手与平台隔离确认后才开始。收到候选仍须确认整组已停止，父进程再独立验收材料、签名、证书、加固内容／标记和对齐。取消、超时或客户端断开只是请求，不是停止完成证明。

- macOS／Linux 使用独立进程组，保留组长直到停止确认，避免 PID 提前回收；父死租约不能由 Java 继承延长。
- Windows 使用本次 Job Object 和创建时归属；不能在工作启动后补挂 Job 或入 Job 失败后降级。停止需核对活跃成员和相关句柄。
- 停止无法确认时不提交、不删除活动材料，返回未知；不按名称查杀其他 Java。
- macOS 的有界组查询与 Linux `/proc` 处理不同，Windows 也不伪装成 Unix；具体规则见[原生设计](agent-desktop-platforms.md)。

准备、工作、复制、最后复核都属于同一总期限，大文件纯 Rust 操作也需检查点。系统不可中断 I/O、强杀、逃组、多重崩溃及同权限对抗不属于正常清场保证。

## 暂存与单 APK 提交

1. 最终父目录预先存在；只在同文件系统建立私有暂存，不占用最终名字。
2. 拒绝任何已有最终目标，含目录、链接和悬空链接；准备检查不能替代提交时的无覆盖原语。
3. 整组停止且工作产物验收后，父端固化为自己持有的文件，逐块校验摘要、取消和期限，再同步文件。
4. 最后复核材料和目录身份，通过后进入提交临界区；Unix 以固定目录句柄硬链接，Windows 使用相对固定目录句柄的无覆盖重命名。不回退覆盖复制。
5. 提交前可取消，临界区内按实际回执处理；晚取消不能删除已发布 APK。
6. 已交付、位置、目录同步及清理分别记录。Windows 如实返回 `directory_synced=false`，不承诺断电目录持久性。
7. 提交／位置无法确认时保留已知事实与恢复材料，不自动重试；清理只针对本次身份匹配的暂存，不递归清理其他目录。

V4 多文件交付未获受控事务支持。普通签名现有暂存回滚也不能冒充本执行器的总期限、整组停止或无覆盖保证。

## 验收与维护

组件覆盖协议／状态／材料／文件边界，原生专项覆盖后代停止与父死，真实工作入口覆盖失败、取消、超时、计划／材料变化、输出竞争和异常退出。成功还须独立验签、证书／摘要一致、原包不变与 SDK ZIP 对齐。

隐藏的 `__agent-probe`／`__agent-worker` 是内部实现和测试入口，不供 Skill／用户调用。各平台同样要求启用特性，不能沿用最初“仅 macOS”的编译边界。

真实大包、完整应用和设备矩阵按影响验证，不给每次提交增加重型任务。最新通过范围和未验限制统一见[平台验收](../process/agent-desktop-platforms-plan.md)及[阶段记录](../process/agent-integration-plan.md#实际验证与限制)。

回滚以入口和配套实现为单位，不迁移本地资料或已生成 APK。若改变核心边界、权限或 V4 交付，需要重新设计，不将既有批准扩大为任意多产物事务。
