# 不受支持的 ABI 排除方案

## 背景与决策

Issue #119、#120 中，旧 SDK 附带的 armeabi、mips、mips64 库导致 Runtime ABI 一致性校验失败。保留这些目录却不注入对应壳会导致设备加载失败，不能简单忽略校验。

标准模式检测到混合 ABI 时，GUI 在开始任务前列出将排除和保留的 ABI，由用户选择“取消”或“排除这些架构并继续”。确认只对当前任务有效，不持久化。仅有不受支持 ABI 时阻止加固；无 Native 库和只有受支持 ABI 的 APK 保持原行为。Android 4.4 工控模式保持现有限制。

## 实现边界

- 核心库负责排除清单校验及临时目录清理，只允许排除输入 APK 中实际存在且不受标准模式支持的 ABI；拒绝路径片段、支持架构及移除全部原生架构。
- 默认清单为空，旧调用方继续拒绝不支持的 ABI。GUI 和 CLI 不能仅凭前端确认绕过核心校验。
- 仅删除任务临时解包目录中的对应 lib/ABI 目录，保留其他架构完整依赖，不修改原 APK。排除清单以进度信息记录。
- Runtime 注入仍以保留后的 ABI 集合严格校验，缺失壳资源必须失败。
- CLI 使用单次显式参数 --exclude-abis，逗号分隔，不从配置文件继承。
- GUI 确认后传入明确的 ABI 名称清单，切换 APK 后重新确认；预检失败时不允许启动。

## 任务与验收

1. 核心：先补混合架构、仅旧架构、非法清单、默认拒绝和临时清理测试，再实现策略；覆盖原始 APK 保持不变和 Runtime 完整性。
2. 接入：GUI 确认、后端请求及 CLI 参数保持一致，不增加常驻设置；结果页面记录本次排除内容。
3. 验证：核心/CLI 测试、GUI 类型检查与构建、后端编译；本机 GUI 验收提供完整 macOS .app。
4. 完成一个完整阶段后提交 PR；已按维护者安排准备 `1.4.0-beta.3` 测试版，合并后由三平台发布工作流构建。
