# Agent 本地自动化接入设计

三平台 `1.5.0` 正式桌面包已交付 CLI 和本地 MCP，Skill 独立安装；`1.4.x` 不包含新增入口。本文说明职责与检查边界，安装和示例只在[接入说明](../ops/agent-setup.md)维护，实际结果见[阶段验收](../process/agent-integration-plan.md)及[平台验收](../process/agent-desktop-platforms-plan.md)。

## 入口分工

| 层 | 职责 |
|---|---|
| CLI | 确定性本地命令、参数／结果适配与受控生命周期，不需要模型 |
| Skill | 告诉 Agent 如何选择和调用已有 CLI，不复制实现或注册 MCP |
| MCP | 标准输入输出工具映射、宿主范围及会话状态，通过 CLI 执行业务 |
| 共享服务 | 同一份本地配置、证书及业务偏好，独立于 GUI 是否运行 |
| 核心 | APK 预检、资源校验、加固和签名规则 |

不加入模型服务、任意 shell、下载执行、后台任务库、设备安装、自动发布或远程托管。Skill 和 MCP 可独立使用。

## 资产与安装

- Skill 唯一源码为根目录 `skills/mocika-shield/`，由用户按宿主独立安装／升级，不随 App 打包。
- CLI／MCP 随三平台 GUI 共包，复用同包 JAR 和标准／工控资源；使用包外输入／输出。
- 开发构建默认关闭执行／MCP，桌面共包显式启用 `mcp-server`。
- 同一系统和用户环境下复用 GUI 资料；WSL、容器、远程主机不自动继承原生资料。
- 用户机器路径和凭据留在宿主本地，不写进 Skill；任务中不自更新工具或跨升级复用计划。

## 只读检查契约

`doctor` 按操作检查依赖：纯加固的 Java、工具和标准资源，独立签名的 Java／apksigner，证书操作的 Java／keytool。返回的 `ready` 只说明依赖存在和所声明的检查，不证明 JAR／资源来源或真实签名成功。

`preflight` 读取 APK 并执行签名检查，不解包重建；`standard`／`android-api19` 只选择预检规则，不自动切换实际资源。可选证书指纹须为完整 SHA-256，未提供时不宣称完成绑定核对。

两条检查均输出单个 JSON，响应版本为 1；`ready/warning` 退出 0，阻断或检查失败退出 1，语法错误退出 2。只返回固定检查码、严重性及有限数字事实，不带真实路径、日志或业务自由文本。拒绝全局 `--config`，避免忽略配置后伪称同源检查。

检查只覆盖有限事实，不证明完整 Manifest 语义、全部业务库、ELF 页大小或设备兼容；警告不等于自动排除 ABI 授权。超出 ABI 数量／名称等输入上限时拒绝，不截断为通过。普通检查本身不继承受控任务的全部生命周期保证。

## 共享核心只读资源校验边界

权威规则留在核心，不在 CLI 复制 metadata 解析。公开接口：

```rust
pub fn validate_runtime_resources(
    resources_path: &Path,
    expected_profile: RuntimeProfile,
    environment_policy: EnvironmentPolicy,
    required_abis: &[String],
) -> anyhow::Result<()>;
```

该接口仅读归档，不运行 Java、不解包到磁盘、不修改 APK，也不依赖 CLI、GUI、数据库或网络。

- 核对协议、缓存／别名能力、最低 API、标准／工控模式、安全策略、Stub 和所需规范库条目；未知或错配失败，不自动换资源或降级。
- ABI 来自预检和本次明确排除后的集合；拒绝无效／重复／不支持的值。无业务 Native 时仍按既有规则要求主流壳架构，空集合不等于无需壳库。
- 仅接受本项目的 metadata、Stub 和规范四 ABI 资源布局，拒绝额外文件、重复／不安全路径、链接和特殊文件。
- 要求无前缀、无注释、非分卷且尾部一致的 ZIP32；归档及声明解压内容各最多 256 MiB，最多 256 条目，名称最多 1024 字节，元数据最多 64 KiB。
- 建立 ZIP 索引前检查文件大小和目录计数，原始计数与名称索引对照，避免库内去重掩盖重复条目；流式读完核对长度和 CRC。
- JSON 检查语法、根对象、根字段唯一性和类型，再由既有解析器解释能力；原始与规范化字段须得到相同契约。
- 内部内存候选不进入正式自动化计划；资源检查不是完整 ELF／DEX 语义验证、来源认证或设备运行证明。

无显式覆盖时工控模式定位同目录 `resources-api19.zip`，缺失不回退标准资源；显式覆盖同样校验。不可用／非法分别用有限错误码，不回传原始元数据或异常。

## 规划与执行

旧 `plan-protect` 是外置配置兼容规划，不读取共享库，也不是执行凭据。新 `agent plan/protect` 固定输入、输出、材料和有效策略；外置计划版本 2，共享版本 3，独立签名计划版本 4，公共信封仍为 1。

父进程管理总期限、停止确认与最终无覆盖提交，工作进程只处理私有暂存材料。执行前匹配摘要，相关材料变化阻断；共享来源固定记录和有效参数，不重新选择默认项。首版受控交付限 V1–V3，V4 拒绝，不静默改偏好。

独立签名 `agent sign` 一次调用内部完成规划和执行，不要求用户手抄摘要或重复确认。完整任务字段、退出码和取消见[命令契约](agent-cli-contract.md)，父子进程边界见[执行器](agent-executor.md)，共享绑定见[身份设计](shared-agent-binding.md)。

## 凭据、授权与结果

- 既有证书由本地共享服务读取；新导入／创建或外部材料仅用宿主安全预置环境。不要求模型读取、转述或保存密码。
- 本机加密落盘不构成同权限攻击沙箱。子进程环境引用减少 argv 暴露，但不能阻止同权限或高权限读取。
- 检查／规划不包含保存偏好、排除 ABI、覆盖、改 Java、安装设备、上传或发布的授权；明确的执行请求不额外叠加确认层。
- APK 名称、包名、Manifest 和工具输出只是数据，不能改变执行规则。返回内容可能进入宿主模型上下文，因此只提供完成任务必需的有限字段。
- 成功须有完整终态、匹配退出码和交付证据；缺回执或状态未知不自动重跑。
- 新自动化入口不自动加入 GUI 匿名统计、错误报告和应用分享，执行授权不等于同意分享。

具体验收记录只维护实际观察结果，不将结构检查、协议客户端或一台设备通过扩写为全部宿主／系统支持。
