## 集成资产目录边界

对外 Skill 的唯一源码为根目录 `skills/mocika-shield/`，包含 `SKILL.md`、必要的包内参考、客户端元数据和只定位 CLI 路径的小脚本；用户安装/配置放 [Agent 接入说明](../ops/agent-setup.md)，设计留在本目录，阶段证据留在实施计划，行为场景放 `tests/agent-skill/`。README 提供直接入口，不把使用产品的技能放入本仓库自动加载的开发技能目录，不复制二进制、密码、测试样本或执行器代码，不预建空 MCP/插件结构。

CLI 随 GUI 共包，Skill 则从源码仓库由用户选定的 Agent 或管理工具独立安装和升级；App 构建不读取技能源码，也不携带技能文件。先前的技能随 App 携带方案已撤回。技能版本写在 `SKILL.md` 的 `metadata.version`，兼容的公共 CLI 协议写在 `metadata.cli-protocol`；初始实验技能为 `0.1.0`、协议 `1`，不与 App 的版本号绑定。管理工具或用户记录仓库、子目录及实际提交/引用，升级不覆盖外部路径、签名配置或密码，不在加固中自更新、不自研升级器。

CLI 发现只按“本次显式绝对路径 → 宿主 `MOCIKA_SHIELD_CLI` → PATH → 询问用户”进行。技能内定位脚本不执行候选，只用固定 shell 内建处理路径与同文件去重，不遍历安装目录。无效显式配置不回退，多文件候选失败关闭；成功返回的路径仍须确认可信来源、接口和协议。规划与执行固定同一工具；Skill 不能以定位成功替代执行器身份约束。客户端发现、授权判断、取消/断开继续独立设实际验收门槛。

目标场景：用户授权开发 Agent 对既有 APK 完成环境检查、风险预检、加固、指定证书签名和产物验证。Agent 解释需求、编排流程和说明结果；确定性检查及 APK 修改仍由现有核心实现，不由模型生成替代算法。

| 层次 | 负责 | 不负责 |
|------|------|--------|
| `shield-core` | 现有检查、预检、加固、签名、对齐及有限诊断 | Agent 提示词、MCP 会话、模型接入 |

## 第一阶段：只读 CLI 检查契约

本阶段按局部结构变更实施：不修改旧命令协议，不扩大核心公开 API，不增加外部依赖或可变全局状态；CLI 内独立的自动化检查模块组织调用和安全输出，继续调用核心预检与环境定位函数。

新增命令始终输出一个 JSON 对象及换行；可显式传入 `--json`，与默认行为相同：

```bash
shield doctor --operation protect
shield doctor --operation sign
shield doctor --operation certificate
shield preflight -i input.apk --runtime-profile standard
shield preflight -i input.apk --runtime-profile android-api19
```

### 环境检查

`doctor` 根据操作检查实际所需依赖：纯加固检查 Java、apktool、apksigner 和标准资源包；独立签名检查 Java 和 apksigner；证书检查 Java 和 keytool。后续自动签名须同时满足证书核对依赖，不把纯加固检查结果当作自动签名就绪。

复用现有 Java/PATH/JAVA_HOME 定位，不修改系统环境。仅运行既有 Java 版本探测；JAR 和资源包只检查是否为可读普通文件，不执行、不解压、不校验版本或协议兼容。`ready` 仅表示本阶段依赖检查通过，返回 `scope: dependency_presence` 和逐项 `verification`，不承诺后续执行一定成功。

可以显式指定本次 `--apktool`、`--apksigner`、`--resources` 路径；不悄悄回退无效显式路径，与所选操作无关的工具参数直接拒绝。`--resources` 仅用于依赖存在性检查，不构成对任意资源的正式支持。输出不包含定位路径、环境变量或版本原文，仅返回 Java 主版本及固定检查码。

### APK 预检

`preflight` 复用 `preflight_apk`；仅读取输入，执行本地签名检查，不调用 apktool 解包/重建，不生成加固产物。默认标准系统策略；`android-api19` 只选择预检规则，不切换任何实际加固资源或扩大 Android 4.4 ABI 支持。真实执行阶段必须绑定同一模式和资源，不能把本参数当成 `protect` 已支持的公开模式开关。

可指定 `--apksigner` 和 `--expected-cert-sha256`。证书指纹须为完整 SHA-256，可含冒号或空格；校验失败返回参数错误，不自行猜测证书。未指定指纹时，返回 `certificate_binding_checked: false`，不能宣称已与计划签名证书核对。

前置确认输入可读、Java 就绪及 apksigner 文件可读，避免使用仅凭 ZIP 签名条目推断的无工具回退。核心预检结果仍是有限检查，不证明清单已完整解析、所有业务库完整、ELF/ZIP 对齐全面合格或设备运行通过。输出 `scope: apk_preflight`、固定检查码、严重性及数字事实；不回传原始工具日志或核心检查的自由文本 `detail`。ABI 名称来自输入，仍为不可信数据；超过 64 个架构或单个名称超过 64 字节时返回 `INPUT_LIMIT_EXCEEDED`，不截断成不完整的通过结论。

现有核心的布尔验签失败既可能来自 APK，也可能来自工具异常。新适配将该项输出为 `signature_not_verified` 并阻断，不沿用容易误导的 `unsigned` 文案；不能据此断言原包一定未签名，更不能自动换证书重签来绕过。原核心规则及旧接口不变，细分证据安排到执行契约阶段。

### 协议、失败与兼容

- `schema_version: 1` 是新增检查响应版本，与 CLI 配置版本、资源版本、DEXB 和遥测协议无关。
- 所有响应带 `tool_version`、`operation`、`type`。结果 `type: result`，包含 `status: ready|warning|blocked` 和 `data`；无法完成检查时 `type: error`，包含固定 `code` 与中文 `message`。
- `ready`、`warning` 退出 `0`，`blocked` 或执行错误退出 `1`；调用方必须读取 `status`，不得把警告视为自动排除 ABI 的许可。
- 参数语法错误由 clap 写标准错误，退出 `2`；帮助/版本退出 `0`，不是 JSON 结果。不得声称所有失败都有 JSON。
- 本阶段新命令不接受 `--config`，返回固定错误，避免悄悄忽略配置造成检查/执行不同源。后续统一解析生效任务配置后再开放。
- 旧 `protect/sign --json`、`--json-progress`、`check-apk`、`check-keystore` 的参数、事件和退出行为保持不变，不能直接把旧事件当新增检查协议。
- 核心签名布尔检查的子进程输出必须被捕获或丢弃，不可穿透污染 CLI 的 JSON；诊断提取保留现有路径，不把原始输出上传或转交模型。
- 固定新增错误包括 `CONFIG_NOT_SUPPORTED`、`ARGUMENT_NOT_APPLICABLE`、`INPUT_NOT_FILE`、`TOOL_NOT_FILE`、`INPUT_LIMIT_EXCEEDED`、`JAVA_PROBE_FAILED`；其余复用核心有限诊断分类，无法确定时返回 `UNKNOWN`，不根据任意文本推断根因。

本阶段继承现有 Java 探测/签名检查的子进程生命周期，尚无统一超时或取消保证，也不是不可信 APK 的完整沙箱。对外正式接入前必须补齐相关执行门槛，不能依赖 Agent 重试解决卡住的检查。

机器输出示意（省略具体检查项）：

```json
{"schema_version":1,"tool_version":"开发构建版本","operation":"doctor","type":"result","status":"ready","data":{"scope":"dependency_presence","checks":[]}}
```

### 初期设计记录：签名资料引用与只读执行前计划

本节保留原外置配置阶段依据，`plan-protect` 仍保持该只读契约；后续 `agent plan/protect` 已新增显式共享来源，见[共享绑定设计](shared-agent-binding.md)。以下不读取 GUI 库的约束仅适用于原外置流程，不代表当前所有入口都隔离资料。

本轮先实现 `plan-protect`，只规划“加固后用指定证书签名”的单任务，不开放执行器，也不把前次只读阶段改写为已经支持写操作：

```bash
shield --config shield-cli.toml plan-protect -i input.apk -o protected-signed.apk
```

复用格式版本 `1` 的本地 `shield-cli.toml`，不新增凭据库、密码字段或命名档案。当前凭据引用就是维护者指定配置中的 `[sign]` 材料；一个配置对应一套签名资料，多个证书可使用不同本地配置。宿主在启动 CLI 前注入既有 `MOCIKA_SHIELD_KS_PASS` 和可选 `MOCIKA_SHIELD_KEY_PASS`，命令只接受配置引用及输入输出，不提供密码参数。缺少密码、材料或证书读取失败时失败关闭，不读取 GUI 数据库或自动创建证书。此引用方式不是凭据沙箱，具有终端权限的 Agent 仍可能读取同一权限下的文件与环境；后续 MCP 须实施独立白名单和授权边界。

输入和最终签名输出必须显式指定，覆盖旧配置中的同名默认路径；配置中的工具、环境策略、Alias、证书类型和签名版本继续生效。加固与签名若显式指定不同 apksigner，拒绝而不猜测采用哪个。计划支持显式 `--runtime-profile standard|android-api19`，默认标准模式；APK 预检、ABI 条件、资源选择和计划身份使用同一请求模式，资源必须通过下述共享核心校验。已有 `[protect].resources` 本地覆盖也不能绕过校验，不根据文件名推断实际资源能力。配置必须由用户/宿主提供，不得根据 APK 元数据自动改写工具路径或选择不明 JAR。

规划先解析本地配置和宿主凭据，再确认输出位置，之后读取工具/材料并执行证书与 APK 检查。检查覆盖：输入可读、输出父目录存在且是目录、所有预期输出均不存在（包括 V4 的 `.idsig`）、本地配置有效、宿主密码存在、工具和签名材料可读、证书读取和输入证书一致、所选模式 APK 预检、显式 ABI 排除和资源校验。任何已存在的输出、软链接（含悬空链接）、硬链接或目录均拒绝，不覆盖、不创建输出目录、不写占位文件；规划阶段不等于已经取得目标目录写权限或执行时仍无冲突。

对输入、配置、keystore、选定 Java/keytool、apktool/apksigner 和选定资源进行流式 SHA-256 摘要，并在工具检查后复查，检测观察到的期间变更；同时记录查找路径和解析后路径，避免只复查旧目标而漏掉链接改向。配置相对路径继续按调用者提供的配置位置解析，不因配置本身是链接而改用目标文件目录。计划摘要绑定版本、文件身份、最终路径、Alias/类型、证书指纹、签名版本、环境策略和本次 ABI 授权，不包含密码。输出只包含计划摘要、输入摘要及有限检查摘要，不返回真实路径、Alias、证书内容或原始日志。摘要只是选定文件和参数的检查身份，不是完整 JDK/依赖来源证明，也不是执行授权令牌。

返回 `scope: protect_sign_plan`、`plan_schema_version: 2`、请求模式及 `execution_ready: false`；`ready/warning` 仅代表本轮规划检查状态，不能据此调用旧 `protect/sign` 冒充受保护执行。资源只有确实通过共享校验才标记 `resource_protocol_checked: true`，未进入资源校验的阻断结果仍为 `false`。核心布尔验签不通过须阻断；证书读取成功只确认该 Alias 的证书，不保证私钥密码正确或私钥可签名，明确返回 `private_key_access_checked: false`。ABI 排除必须逐次显式指定，使用核心规则校验，不从警告自动生成授权。

前一子阶段收紧了核心已有 keytool 证书读取与 apksigner 签名的密码传递：改用各工具支持的环境变量引用，仅设置本次子进程环境，不修改系统环境。旧 CLI 参数接口保留，但不建议公开命令行传密码；子进程环境仍可被同权限/高权限进程访问，不能宣称为安全保险箱。不改变 GUI 证书持久化与既有核心接口。

签名引用与文件计划子阶段为 L2 局部适配：CLI 计划编排、文件身份/输出位置检查分开，复用原有配置合并和核心证书/预检/ABI 规则，使用工作区既有 `sha2`。本轮共享资源接口属于下述已确认的公开边界扩展；不新增 crate，不引入 Agent SDK、网络、持久化或任务状态。

### 已确认：共享核心只读资源校验边界

2026-11-06 继续审查发现，权威协议解析与运行时选择位于核心私有的 `protect/runtime.rs`、`runtime_metadata.rs`；现有公开 `preflight_apk` 只接收 APK 预检条件，不接收资源包。经方案比较后，维护者明确选择按推荐方案继续：新增最小只读核心接口，保持旧公开接口和 GUI 调用不变。该确认覆盖本节接口与 CLI 只读计划接入，不包含实际自动执行。

| 方案 | 收益 | 成本与风险 |
|------|------|------------|
| 新增最小只读核心接口（推荐） | 复用私有解析与规则；旧预检、加固、GUI 调用不变；只增加一个明确能力 | 需维护一个新增公开函数及其契约测试 |
| 扩展现有 APK 预检接口 | APK 和资源可集中给出检查报告 | 需修改公开选项/报告及多处构造调用，扩大本轮 GUI/调用方迁移范围 |

不采用在 CLI 复制 metadata JSON 解析和协议规则的方式，否则计划与核心实际加固会形成两套解释。也不把整个私有 Runtime 模块、壳类名、Manifest 字段或资源内部类型公开。

已确认的最小接口（实施及验证状态见任务记录）：

```rust
pub fn validate_runtime_resources(
    resources_path: &Path,
    expected_profile: RuntimeProfile,
    environment_policy: EnvironmentPolicy,
    required_abis: &[String],
) -> anyhow::Result<()>;
```

边界与数据流：核心仅读资源归档，复用既有元数据解析、协议和策略规则，再确认请求模式与所需壳条目；不执行 Java、不解包到磁盘、不修改 APK，不依赖 CLI、GUI、数据库或网络。沿用已有 `RuntimeProfile`、`EnvironmentPolicy` 和错误载体，不预建资源服务或新 crate。ABI 参数来自 APK 预检和逐次明确授权后的保留集合；无业务 Native 库时按既有注入规则要求四个主流壳架构。接口须拒绝无效/重复/不支持的 ABI，不将空集合解释为无需壳库。

校验范围：既有新旧资源协议兼容、缓存协议、Native 别名契约、标准/工控最低 API 声明、严格环境策略能力、必需 Stub DEX 与实际规范壳库条目、条目重复或不安全路径。缺声明、未知模式、策略不支持或所需库缺失均失败关闭，不自动换资源或降级。旧资源按既有规则缺省为标准模式，不以 Release 版本号相等代替协议检查；内存 DEX 候选资源不进入新的正式自动化计划。

新增入口只接受本项目资源形态：`metadata.json`、`stub-classes.dex`、四个主流 ABI 的规范壳库及配套目录；不接受额外文件、符号链接或特殊文件。归档须为无前缀、无注释、非分卷、尾部一致的 ZIP32：文件及声明解压内容各不超过 256 MiB、条目不超过 256 个、单个名称不超过 1024 字节、元数据不超过 64 KiB。文件大小和目录计数先于 ZIP 索引解析检查；原始目录计数再与库的名称索引数量对照，避免被库内去重掩盖。条目内容流式读完核对长度和 CRC，不解包到文件系统。上述限额和布局约束只作用于新资源准入，不限制用户 APK，也不改变旧执行入口。

元数据文档在核心内部使用工程已锁定的 `serde_json` 验证语法、根对象、根字段唯一性与声明类型；只将已知根字段交回原有 `RuntimeMetadata` 解释协议，同时要求原始文档与规范化根字段在原执行解析器中得到相同契约，避免嵌套声明、数字后缀或转义规范化使新检查比实际执行更宽松。协议版本、别名及安全策略规则不在 CLI 复制。核心仅新增该既有依赖的直接依赖边，不升级或下载新版本；旧解析入口保持原样，安全策略判断提取为共享私有方法并维持原语义。

这不是 ELF/DEX 全面语义验证、资源来源证明或设备运行验收；不会把元数据中的 API 19 声明解释为所有 ABI 都能在 Android 4.4 上运行。未知最低 API 声明须明确拒绝或返回不可确认，不能只因“不等于 19”而声称匹配标准模式。核心旧执行入口的行为不在本轮擅自改变。

CLI 接入：仅为 `plan-protect` 增加显式 `--runtime-profile standard|android-api19`。默认标准资源；无显式资源覆盖时，工控模式定位标准资源查找位置的同目录 `resources-api19.zip`，缺失即失败，不回退标准资源；已有本地资源覆盖保留，但必须通过同一核心校验。预检、ABI 条件、计划摘要与资源检查使用同一请求模式。资源缺失/不可读返回 `RUNTIME_RESOURCE_UNAVAILABLE`，校验失败返回 `RUNTIME_RESOURCE_INVALID`，不包含路径或原始异常。内部计划身份版本递增到 `2`，以区分早期未校验资源的摘要；CLI 配置格式、外层检查响应版本、资源格式与 DEXB 不变。

迁移与回滚：先补新增核心只读契约测试，再接 CLI；旧公开预检和加固签名调用保持原样。移除新增 CLI 接入与只读函数即可撤回，不涉及持久化迁移、资源重编译或已加固 APK。`execution_ready` 继续固定为 `false`，不得因资源检查通过而跳过私钥、进程超时/取消和原子输出门槛。

验收任务：标准/工控正反匹配、缺省旧资源、新旧已支持协议、未知/歧义声明、严格策略不支持、内存候选拒绝、缺 Stub/所需 ABI、空 ABI 集合、重复/不安全条目及不解包不写原文件；CLI 另测默认资源定位、显式覆盖错配、缺工控包不回退、单次 ABI 排除和输入/输出不变。最后使用本机既有标准/工控资源做只读验证，不将其等同于真机加固回归。

在开放 Agent 写操作前完成：

- 明确有效配置、输入身份、资源模式、运行环境策略、输出和覆盖策略，预检与执行使用同一份计划；输入改变必须重新检查。
- 加固绑定计划签名证书；不同证书、指纹读取失败或未知策略失败关闭，不靠模型自动降级。
- 默认生成新文件，拒绝输入输出同一文件、链接别名和未授权覆盖；失败清理仅限本次任务创建的临时文件。
- 版本化进度、结果与错误包含任务阶段、固定分类、产物信息和可验证证据；不能只凭 `done` 或文件存在判定成功。
- 原始日志仅在本机明确授权的诊断路径提供；模型返回使用白名单和长度限制。对旧命令保留兼容入口，不一次替换已有脚本协议。
- 明确执行、取消中、已取消、成功、失败等状态；客户端超时不等同取消成功。不得在执行状态未知时自动重启任务，避免重复加固或覆盖。
- 初期单任务执行，不新增批量、后台队列或无人值守发布；本地审计记录不保存凭据或原始日志。

## 凭据、授权与数据边界

- 仅处理用户授权的 APK 和目标目录。检查授权不包含覆盖、排除 ABI、修改系统 Java、安装设备、发布 Release 或上传诊断材料的授权。
- 密码不作为 Skill 对话参数或 MCP 参数。后续执行使用本地配置的凭据引用；具体存储与生命周期另行设计，不直接开放 GUI `shield.db` 或要求模型读取密码环境变量。
- 既有 CLI 环境变量输入保留，但 Agent 不得回显、读取转述或写入命令记录；凭据从宿主本地注入。禁止因失败改用把密码粘入对话或命令参数的回退。
- 本地 MCP 的目录限制、输出保护和凭据解析必须由程序执行，不能仅写在 Skill 或依赖客户端工具注解。路径规范化、链接及边界校验须有专项回归。
- APK 元数据、ABI 名、文件名、错误文本及工具日志都是不可信数据，不能覆盖 Skill 指令或授权范围，不提供任意 shell/下载执行工具。
- 本地执行不意味着返回内容不会传给 Agent 的模型供应商；默认只返回完成任务必需的有限信息，新增敏感信息需单独确认。
- 新自动化入口不接入 GUI 匿名统计、错误报告和应用分享，不自动联网，不把授权执行等同于同意分享；若未来新增采集，须独立设计。

## 安装、版本与发布门槛

Skill 不应要求普通用户自行安装 Rust/NDK、构建壳或搜索不明来源二进制。首轮开发验证可从源码构建，但在正式对外宣称即装即用前，必须解决匹配的 CLI、标准/兼容资源、JAR、Java 要求、校验和及三平台安装路径。

维护者已于 2026-11-06 确认先采用“桌面安装包附带独立无头 CLI”，不另增 CLI Release 资产。首轮只接 macOS：`MocikaShield.app/Contents/MacOS/shield` 与 GUI 同包、同版本，共用 `Contents/Resources/tools/` 与 `Contents/Resources/resources/` 中的 JAR、标准和工控资源。CLI 不启动 GUI；原外置来源继续使用 `shield-cli.toml` 与宿主注入凭据，后续已新增显式读取同一应用资料的[共享来源](shared-application.md)，不要求 GUI 常驻。不自动修改 PATH、创建系统链接或要求管理员权限。

共包构建由独立的 macOS 构建脚本负责：先检查既有资源及版本，显式启用 `mcp-server` 构建 CLI（包含原 `agent-executor`），构建 Tauri `.app`，核对两者架构和资源，再装入 CLI、完成最终签名与验签。MCP 不随 GUI 启动，宿主按需启动服务时默认只读。现有 macOS 发布脚本复用该入口后生成 DMG；`SKIP_CLI_RELEASE=1` 仅跳过独立 CLI 压缩包，不跳过应用内 CLI。其他平台保持原状，默认 CLI 源码构建仍不启用执行/MCP 特性；不因共包提前宣称跨平台 Agent 支持。

当前不修改 GitHub 工作流、不增加独立 CLI 任务。打包验证只放阶段或发布流程，不增加每次提交的重型任务。须把真实 `.app` 复制到源码目录以外，在 GUI 关闭时用其内置资源完成规划、加固、签名、验签和独立对齐核对，并验证缺资源时不借源码目录或用户目录补齐。调用者应按只读方式使用应用包，把配置、输入和输出放在包外授权目录；CLI 不自动向安装目录保存应用级状态，但不把这一使用约定说成对任意显式输出路径的系统写保护。不能随意提取裸二进制并假定资源完整。实际 Agent 客户端、跨平台原生控制和对外发布仍各设门槛。

不预占下一版本。只读源码入口先本地验证；完成安装交付与 CLI＋Skill 闭环后才确定版本范围。MCP 是否同版交付取决于兼容与生命周期验收，不为宣传连续发布空的 Alpha/Beta/RC。现有稳定缺陷修复可独立发布，不被 Agent 工作阻塞。

## 验收与停止条件

只读阶段验收：真实 CLI 子进程输出可解析；缺依赖、低/未知 Java、无效路径、中文路径、阻断预检、模式选择、证书指纹、原始输出隔离和旧命令回归通过。只改隔离子进程环境，使用临时夹具，不操作用户证书或设备。

写操作阶段必须补充真实已签名 APK 加固与重签名、证书一致性、原包不变、失败不破坏输出、取消清理与三平台行为；Android 4.4、16 KB 等继续使用原有专项门槛，不用本阶段的 CLI 测试冒充设备验证。

Skill 验收使用真实支持的 Agent 客户端，覆盖正常任务、缺依赖、用户拒绝覆盖、取消、资源模式、签名不一致和恶意元数据；MCP 另验证发现、参数/结果、协议独占输出、超时/取消、断开和重复调用。若仅增加接入复杂度而无真实闭环收益，停在 CLI＋Skill，不扩张远程服务。
