# Java 工具无损参数适配

Windows Java 8／17 的原生 argv 可能损坏中文路径、Alias 和主题，统一输出编码不能解决。core 使用旁置 Java 8 JAR 和私有 UTF-8 请求；GUI、CLI、MCP 复用同一实现。问题依据见[中文兼容说明](chinese-toolchain-compatibility.md)，覆盖范围见[验收表](../process/java-tool-adapter-plan.md)。

不改用户系统代码页、全局 Java、数据库、密码格式、GUI 配置、Android 壳或 DEXB；不内置 JRE、不运行时编译、不使用 JDK 内部 API。

## 职责与入口

| 位置 | 职责 |
|------|------|
| core 的 `java_adapter` | 有界请求、资源校验、固定工具调用及有限诊断 |
| `java_directory`／`windows_private` | 安全目录别名、身份及私有材料访问控制 |
| `shield-services` | 证书业务、实际 Alias、无覆盖保存、数据库及默认项 |
| CLI 执行器 | 资源绑定、总期限、整组停止、取消、最终提交及未知保留 |
| `tools/java-adapter/src/` | Java 标准证书接口及两个固定工具公开入口 |

`JavaToolContext` 只固定适配 JAR 和借用工作根，不持有数据库、任务或进程模型，不清理调用方材料。`*_with_context` 要求明确工具；旧入口及 `ProtectOptions`／`SignOptions` 调用方式保留，不复制签名或加固编排。core 不反向依赖 CLI、Tauri、Tokio 或数据库。

Windows 普通证书、签名、加固、预检与验签默认使用适配；macOS／Linux 默认保留原工具路径，显式上下文可单独验收。普通写入会话在输出父目录创建同卷私有根，只读操作使用系统临时位置；完整成功才回收，失败／取消保留。普通同步会话不承诺 Agent 的硬期限、整组停止或无覆盖最终提交。

## 构建与资源

- 唯一源码为 `tools/java-adapter/src/`；生成物 `tools/java-adapter/build/java-adapter.jar` 不入库。
- `scripts/build_java_adapter.py` 用构建 JDK 17 的 `javac --release 8`；用户运行支持 Java 8，不需要 javac。普通 Cargo 编译不隐式调用 Java 编译器。
- 校验应用版本、协议、主类、源码及字节码清单、摘要和 Java 8 class 版本；同一构建环境可重复生成，不承诺跨 javac 版本同字节。
- GUI／CLI 共用包内 `tools/java-adapter.jar`，维护压缩包沿用 `lib/`；具体布局见[三平台设计](agent-desktop-platforms.md#桌面共包)。不放进 Android 资源 ZIP，不共包 Skill。
- 桌面命令缺资源立即失败；首个已存在位置异常不改选其他来源。只有调试源码入口允许使用仓库生成目录，不从用户数据、PATH 或网络补猜。
- Manifest 版本是兼容标记，不是防伪签名；受控任务还绑定摘要与文件身份。

## 引导与路径

业务路径在修改子进程 cwd 前按调用目录绝对化，Windows 使用 `dunce` 规范化。引导 JAR 复制到本次私有目录，以固定 ASCII 相对名称启动；业务路径及文本经请求传递，不放回原生 argv。

Windows 要求系统已有、句柄身份一致的 ASCII 目录别名；不得启用短名、改名、移动用户目录或换根重试。补充字符的真实**引导工作目录**即使有 ASCII 别名仍可能启动失败，因此启动前拒绝；这不等于禁止 UTF-8 请求中的补充字符业务文件名。输出父目录含补充字符时不能承诺支持。

apktool 单独设置 `-Djava.io.tmpdir=.`，框架缓存使用本次私有 `-p` 目录，解包保留 DEX 字节。Windows 重建时的项目、框架及候选父目录同样要求安全 ASCII 别名，因为 Java 可读取 Unicode 不代表 aapt2 也能读取。

缺别名、身份不符或不支持路径时明确失败，不继续传递有损字符串。JDK 安装位置、长路径和无短名的卷不能从当前样本外推支持。

## 请求、结果与生命周期

当前私有协议为 **MSJA 4**：固定 magic／版本、参数条数及每段 UTF-8 长度，最多 64 段、总计 64 KiB。Java 完整校验并确认 EOF 后才执行，不接受任意类名、classpath、JVM／shell 参数或模块开放选项。旧协议资源须重建，不能只修改版本号。

Rust 在私有根独占写入请求，关闭写句柄后只读重定向 stdin；核对普通文件、身份及长度，不接受链接、FIFO 或边写边读。Unix 收紧权限；Windows 在创建时设置并复核当前用户／SYSTEM 访问边界，不修复借用目录权限。密码只放本次工具专用环境，不写请求、argv、普通配置、日志或回执；工具不继承控制租约，读完请求只得到 EOF。

证书结果整体最多 64 KiB，Alias 最多 256 项、单项 UTF-8 最多 4096 字节，指纹为证书 DER 的 SHA-256。错版本／操作、未知或重复字段、超限及非法输出整体失败，不返回部分结果。错误映射到既有固定类别，不透传 Java 异常原文。

JAR stdout／stderr 同时持续排空，每流只保留前 64 KiB 并标记截断；原文不进入 Agent JSON 或普通错误。版本／指纹查询遇非零、截断或非法编码即失败。只有原工具明确报告无有效签名时可返回未签名，引导错误不能被 ZIP 标记猜测掩盖。

有限文件没有 stdin 写线程，但不因此获得通用硬超时。受控任务沿原总期限及进程组／Job 确认停止后才清理、提交；停止未知保留材料且不重试。普通 GUI 同步调用不等同迁入受控执行器，也不承诺算法内部即时取消。

## 证书与 APK 语义

### 证书

查询使用标准 `KeyStore`／证书接口，返回实际 Alias，包括受信／Secret 条目；Secret 条目没有证书时明确失败，指纹查询不验证 Key 密码。只接受 JKS／PKCS12，不改写导入原件。

新建使用 `create_keystore_draft_with_context`：标准接口验证主题并转为可往返的 RFC 2253 ASCII 表示，原 keytool 在预留私有材料中生成密钥，再核对并恢复实际 Alias。Rust 预留文件，Java 只填充同一文件，不跟随、替换或覆盖用户材料；核验主题、链、私钥、类型和密码后才交给 services 发布。

JKS 支持已验证的中文及分离密码；PKCS12 限 ASCII 密码且 Store／Key 相同或 Key 留空，不静默忽略独立密码。服务保留同卷无覆盖保存；工具失败不入库或改默认项，入库失败时保留已发布证书并明确提示，不能丢失私钥。

### 签名与加固

apksigner／apktool 只调用固定公开主类，保留上下文类加载器及原工具退出行为，不反射内部 keytool 或提供任意命令接口。`sign_apk_with_context`、`protect_apk_with_context` 和检查入口共用原业务。

- 普通签名保留 V1–V4；Agent 受控签名仍限 V1–V3。
- 原地签名要求工作根与输入同卷；写回失败不先删原包，不跨卷复制降级。普通指定输出的替换语义不等同 Agent 最终无覆盖提交。
- 加固共用 Manifest、ABI、DEX 加密／证书绑定、缓存身份、壳注入及对齐，不新增选项必填项，不因默认资源路径绝对化而开放内存 DEX 候选。
- `extractNativeLibs=false` 保留原值，全部 Native 库以 Stored 存储并做 16 KB 对齐。
- 显式项目只产私有候选，清理归调用方。失败不先删旧输出；阶段取消不等同算法内部或同步提交区间可中断。

## Agent 绑定与兼容

Windows 适配 JAR 纳入来源、计划摘要、私有材料及阶段复核；工作端只读已核对副本，不重新搜索。来源包含查找／规范路径、大小、SHA-256 和原生身份，同字节替换、改向或材料集合不符均拒绝。

| Windows 私有契约 | 加固后签名 | 独立签名 |
|------------------|------------|----------|
| 工作引导版本 | 5 | 6 |
| 来源证明版本 | 4 | 5 |
| 材料索引版本 | 4 | 5 |
| 私有摘要域版本 | 5 | 6 |

MSJA 仍为 4，内部消息帧仍为 1，公开事件与共享绑定不变；非 Windows 保留原私有版本。旧 Windows 计划缺少适配绑定时须重新规划，执行中不自动改绑。配置、证书库及 Android 资源不迁移。

回退按整套桌面程序和匹配资源进行，不在失败任务内降级为有损 argv，不改用户系统设置。ACL、摘要及身份检查不构成管理员／同权限隔离或原子按句柄执行保证。
