# macOS 本地 MCP 接入设计

当前主干已接入[共享来源与证书范围](shared-mcp.md)、[单次独立签名](controlled-signing.md)、[资料管理](shared-mcp-management.md)及[证书生命周期](mcp-certificate-lifecycle.md)。当前共享模式为 5／15 项工具，最简配置和能力清单统一见[接入说明](../ops/agent-setup.md)。下文的固定外置配置和首批工具表继续说明原兼容模式，不作为共享模式的新限制。源码、完整包、当前 Agent 标准流调用与宿主原生注册的证据分别记录，见[交付审查](../process/agent-delivery-review.md)。

> 2026-11-09 目标修订：采用[多入口共享应用能力](shared-application.md)。本文“不读取 GUI 配置／证书库”“不管理证书／独立签名”描述最初外置模式，不适用于后续共享扩展；共享基线见[共享计划](../process/shared-application-plan.md)，独立签名见[签名计划](../process/controlled-signing-plan.md)。默认只读、宿主固定范围、无秘密输出及受控提交／取消边界继续保留，签名不增加逐项确认层。

最后更新：2026-11-09。维护者已确认推荐方案：同一 `shield` 二进制增加默认关闭的 `mcp-server` 特性及 `mcp serve` 入口，使用官方 Rust SDK，经子进程复用既有 CLI。先以当前 Mac 原生验收为准，不以其他平台验证作为前置条件，不扩大跨平台承诺。实现状态见[实施计划](../process/local-mcp-plan.md)。

## 目标与非目标

让支持 MCP 的 Agent 发现并调用环境检查、APK 预检、受控计划及后续加固签名，不必拼接任意命令。Skill 与 MCP 独立使用：前者说明工作流程，后者提供受程序约束的工具；不强制同时安装。

仅本机标准输入输出传输，不监听端口、不上传 APK、日志或凭据。不做模型接入、GUI 聊天、独立常驻服务、批量／队列、远程调用、设备安装、自动发布或 MCP Tasks 扩展，不新增遥测。最初外置模式不提供共享资料与独立签名；后续共享扩展通过 CLI／本地服务接入，不在 MCP 复制 SQL、密码解密或业务执行。

## 架构决策

本次为架构级变更：新增协议和会话生命周期，但不改变共享核心或既有执行器的所有权。

| 方案 | 收益 | 成本和风险 |
|------|------|------------|
| 同一 CLI 的独立模块和可选 SDK（已选） | 共用应用资源和版本；不增加安装资产；复用现有执行进程 | CLI 增加可选异步依赖，需要严格隔离协议和进程控制 |
| 独立 MCP 程序/crate | 可单独发布和演进 | 多一套程序定位、构建、签名与版本配对，当前无独立发布需求 |
| 继续只有 Skill | 不增加协议依赖 | 不能为只有 MCP 工具接入能力的客户端提供结构化接口 |

不手写另一套 MCP 协议栈。使用官方 `rmcp`，仅启用服务端及本机传输所需能力；关闭默认的无关特性，不启用 HTTP/OAuth/下载。实施时锁定实际发行版本、核对 Rust 下限和依赖差异，不追踪 SDK 主分支。SDK、异步类型仅留在 CLI 私有模块，不传入核心或 GUI。默认 CLI 构建不编译 MCP；macOS 专项显式启用 `mcp-server`，并依赖原 `agent-executor` 特性。共包阶段已决定由现有 macOS 构建脚本显式启用该特性，不另增二进制或安装资产；完整包验证与公开发布分别设门槛，当前公开安装包未变。

首批实际选择 `rmcp = 3.9.0`（精确版本，Rust 下限 1.88），仅启用 `server` 和 `transport-io`；`tokio`、`tokio-util` 复用工作区已有锁定版本。SDK 内部需要另一个版本的 SHA-256 依赖，不替换核心现有密码算法或依赖。服务首轮仅声明并验证 `2025-11-25`，不随 SDK 默认能力扩大协议范围。

`apps/shield-cli/src/mcp/` 负责传输/工具映射、启动策略和子进程桥接。协议会话拥有一个活动调用及有限计划记录；CLI 子进程拥有任务执行，既有 CLI 父端仍独占最终 APK 提交权。子进程通过本次可信 CLI 的绝对路径启动，不运行 shell、不搜索 PATH 选择第二个 `shield`，不开放任意程序/参数。

第二阶段实现中，`session.rs` 独占会话计划/状态，`runner.rs` 编排单次调用，`server.rs` 限定 SDK 工具与通知，`transport.rs` 负责连接断开/输出期限；原策略、CLI 桥接和结果白名单各自保留。会话规则不依赖 SDK 类型，GUI 和核心不依赖这些模块，不增加 crate 或任务服务。

现有 `run_agent` 会登记进程级信号并读写标准流，不能在 MCP 进程内直接调用。MCP 消费 CLI 的有界 JSON 输出并白名单映射，不把 CLI 标准输出直接连接到 MCP 标准输出。标准错误也不能携带原始业务日志或密码。

## 原外置模式的启动策略与工具

开发入口为 `shield [--config /绝对路径/shield-cli.toml] mcp serve --input-root /输入目录 --output-root /输出目录 [--timeout-seconds 120] [--allow-execution]`。启动参数由用户/宿主管理，不由工具调用修改；配置继续使用现有格式，不新增 MCP 配置文件或密码字段。仅显式启用开发特性时提供，正式安装包尚未交付。

默认不注册写工具。没有签名配置时仍可检查环境/预检，但计划返回固定缺配置错误；开发实现已支持 `--allow-execution`，开启时必须提供宿主固定签名配置，额外注册执行和状态查询两项工具。所有工具拒绝未知参数、过长字符串及无效枚举；不接受密码、可执行路径、工具覆盖或任意配置路径。

| 工具 | 参数与能力 | 边界 |
|------|------------|------|
| `shield_doctor` | 固定操作枚举，检查默认应用工具和环境 | 不修改 Java；仅依赖存在性检查，不代表签名配置就绪 |
| `shield_preflight` | 输入根目录内的相对 APK 路径、运行模式、可选证书指纹 | 复用既有预检，不解包/重建，不接受工具覆盖 |
| `shield_plan` | 输入/输出根目录内相对路径、运行模式、逐次明确 ABI 排除 | 调用受控 `agent plan`，绑定启动时固定配置；不是授权执行 |
| `shield_protect` | `plan_id` 与 `expect_plan_sha256`，不重复接受任意路径 | 仅显式允许执行时注册；一次计划只尝试一次，不自动重试 |
| `shield_execution_status` | `plan_id` | 随执行能力注册；查询本会话的执行/清理/提交证据，不建立持久后台任务系统 |

操作系统模式、签名 V1–V3 和 V4 拒绝沿用 CLI。MCP 不复制 ABI、证书、资源协议、APK 修改或最终提交规则。默认只读模式不等于不执行本机 Java：环境探测、验签和计划都可能启动工具；须有期限和清理检查。

## 路径、配置与凭据边界（外置基线）

- 根目录必须为用户明确选择的现有目录，启动时规范化并固定物理身份；拒绝整个文件系统根目录。CLI 自身和可信工具不从 APK 目录推断。
- 工具只接受相对根目录路径，拒绝绝对路径、父级跳转、空路径、控制字符及不安全组件。不以字符串前缀判断包含关系。
- 根目录内部不接受符号链接组件；输入为普通文件，输出父目录已存在，输出不得存在（包括悬空链接/目录）。输出根不得位于应用包或 Skill 内；最终仍由 CLI 执行无覆盖和文件身份复核。
- 启动签名配置是宿主信任材料，不允许工具调用选择配置。记录其身份/摘要，后续调用发现变化即阻断并要求重启/重新规划；配置里的 keystore/JAR/资源路径属于明确的本地信任范围，不把输入目录的恶意配置当可信配置。
- 工具调用前后复核目录/路径，执行前再次复核计划绑定；这些是可信本机环境的持续变更检测，不是同权限恶意进程的文件系统沙箱，也不宣称彻底消除检查和使用之间的竞争。
- 密码只由宿主通过原有专用环境变量注入，不从 MCP 参数、消息、Skill 或 GUI 数据库提取。不给模型列出环境、读取文件或输出配置全文的工具。密码环境不传给无需凭据的检查子进程。
- 客户端 `roots` 或工具的只读/破坏性注解不是权限令牌，不能扩大启动根目录；不动态跟随客户端根目录扩大访问范围。允许执行是宿主能力上限，单任务仍应由客户端展示并取得用户授权；服务器无法证明模型所说的“已获授权”真实有效。

## 协议、期限与会话状态

标准输出只允许 SDK 的 MCP 消息，初始化/版本协商由 SDK 处理；不宣称兼容所有协议版本或客户端。首轮选择实际 SDK 和客户端共同支持的版本，并记录协商结果；只声明已实现的工具能力，不启用资源读取、采样、提示模板、Tasks 或网络传输。

输入和输出设字节/条目上限，检查单条/累计 CLI 输出及事件序列，拒绝截断、重复/矛盾终态、未知协议或退出码不匹配。只返回固定错误、数字事实、摘要及有限状态，不返回密码、Alias、真实路径、APK 自由文本和原始错误。兼容结果同时提供结构化内容及等价文本，不把 stderr 原文带入协议错误。

第一阶段一次只运行一个检查/计划，重复并发返回忙，不排队；取消通知和连接断开必须仍能被处理。检查进程独立成组，在超时/取消时结束并确认组内进程；受控计划/执行通过原 CLI 的取消输入及总期限收尾，不通过只杀 CLI 父进程冒充整组清理。

第二阶段计划记录只在会话内保存，最多 16 条；未消费计划在就绪后 10 分钟到期。执行中的记录不因原计划期限被清除，结束后的证据再保留 10 分钟；记录满时拒绝新规划，不抢删仍可查询的记录。断开/重启后不可恢复；观察到根目录、执行器或固定配置变化时作废尚未消费的计划。匹配引用与摘要、开始尝试即消费，之后即便在启动 CLI 前因路径/配置被阻断也不可重试；摘要不匹配的无效请求不会消费计划。结果未知时保留未知，不自动重试。活动调用最多一个，状态查询绕过工作许可且不启动第二项任务；`planned` 状态及 `live_policy_checked:false` 不是新的环境就绪证明。

执行成功须匹配原计划摘要、退出码、唯一终态、交付/清理证据、产物摘要和大小，且目录同步必须确认为真；缺回执、截断或矛盾证据按提交未知记录，执行尝试已消费。执行后不复用“输出不得存在”的规划检查，而是检查授权输出的普通文件/路径及大小。若 CLI 已报告发布、后续本机身份检查却失败，保留已报告的交付证据、将整体结果标记未知，不删除产物。独立重算产物摘要、验签和 SDK 对齐属于验收证据，不宣称 MCP 又实现了一套签名/提交流程。

客户端提供 `progressToken` 时，转发经过校验的阶段递增通知；只表示阶段序号，不换算耗时百分比。未提供时仍可通过状态查询看当前阶段。CLI 阶段队列最多 16 项，单任务至多 13 个阶段，不转发原文。进度发送最多等待一秒，标准流单帧写入/刷新最多等待两秒；阻塞或断开即请求取消，收尾继续由后台任务持有工作许可。底层 macOS 标准流的阻塞线程可能在运行时退出时仍未返回，不把有限等待解释为所有系统调用都可中断。

收到 MCP 请求取消时先请求底层停止，不因发出取消请求就宣告清理成功。协议取消后客户端可能不再接收该调用结果，因此通过本会话状态查询提供已观察到的终态；连接已断开则不承诺客户端可再查询。底层已提交成功时不因晚到取消删除 APK，提交/清理未确认沿用 CLI 保守状态。重连不自动恢复或继续执行。双重崩溃、强杀、恶意逃组和不可中断文件系统故障仍不在自动清场保证内。

会话一旦观察到任务结果未知、提交不确定或清理未确认，就锁住新的规划/执行，返回 `SESSION_RECOVERY_REQUIRED`；包括受控只读规划缺失有效收尾证据、检查进程组停止未确认的情况，不能借新计划绕过。既有缓存或记录到期不会解除锁定，状态查询及只读检查仍可用。必须人工检查本机进程、任务材料和产物后，由用户重新建立会话，禁止自动重试、重连或重启服务。状态响应通过 `session_execution_blocked` 区分会话锁定与单项任务结果。MCP 自己能明确证明尚未启动 CLI 的参数/输出拒绝或取消，报告无需清理，不因此锁定会话；不能将旧 CLI 早退的 `unconfirmed` 擅自改写为完成。

## 验收、交付与回滚

先在当前 Mac 完成路径策略、默认只读、初始化/工具发现、结构化结果、真实检查/受控计划和超时/取消/断开，再接执行。两者完成后集中审查和提交，不为每个文件建 PR。真实 `.app` 交付仍按项目规则，裸 CLI 测试只用于协议专项，不替代应用包验收。

执行阶段须覆盖真实小包加固签名、证书/摘要及独立 SDK 对齐、输入不变、输出占用、计划漂移、重复执行、取消、断开、晚取消、子进程失败和结果未知。当前会话使用协议客户端的测试与实际 Agent MCP 工具注册/调用分别记录；不能把其中一个冒充另一个。未经确认不修改用户全局 Agent 配置。

不新增每次提交的重型 CI、不打标签、不更改公开版本。macOS 共包沿用 `scripts/build-macos-app.sh`，应用内 CLI 显式启用 MCP，但启动 GUI 不会启动 MCP，不增加 Tauri 权限或自启动项；服务仍由宿主按需拉起、默认只读。Skill 不随包携带。完整包须在源码目录外使用包内 JAR 与双资源验收，不能以带源码路径覆盖的配置冒充独立运行。Linux/Windows 后置；公开版本另行决定。关闭共包中的新特性并移除入口即可回滚，不迁移 GUI 数据、不修改壳、DEXB 或旧命令；Skill 和 CLI 继续可独立使用。

## 已核对的官方依据

- [本机传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)：标准输出由协议独占。
- [工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)：工具发现、结构化结果及注解不能替代授权。
- [生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)与[请求取消](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation)：初始化、协商、停止和晚到取消的边界。
- [进度通知](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/progress)：只向提供进度标识的活动调用发送递增进度，不把阶段当成耗时百分比。
- [官方 Rust SDK](https://github.com/modelcontextprotocol/rust-sdk)：实施时选择实际发布版本并核对精确特性，不把主分支说明当作已验客户端兼容结论。
