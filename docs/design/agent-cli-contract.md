# 单任务自动化命令契约

> 2026-11-09 扩展：按[共享应用设计](shared-application.md)接入显式共享来源。下文外置配置示例仍兼容；新来源、有效参数与私有证据版本见[共享绑定契约](shared-agent-binding.md)，不能移除执行前绑定和凭据保护。

共享来源使用无状态 `--shared-binding`，不新增计划库／强制计划文件；仅开发特性下的 `agent` 接入，旧 `plan-protect`、公开 Release 和 MCP 的外置配置边界不自动改变。

最后更新：2026-11-06。维护者已明确选择独立的 `shield agent plan/protect`、受控规划与摘要匹配、统一逐行 JSON、信号与可选标准输入取消。源码已按本契约接通开发入口，不代表现有 Release 已包含命令；验收范围见[阶段任务](../process/agent-integration-plan.md)。首轮仍限 macOS 的 `agent-executor` 实验特性，默认 CLI 源码构建不启用；经后续确认，macOS 应用共包入口显式启用，不增加独立 CLI 发布资产或工作流。

## 方案比较与边界

| 方案 | 取舍 |
|------|------|
| 独立 `agent plan/protect`（已确认） | 确定性本地自动化，不需要模型；旧参数和 JSON 不变；需维护新的版本化契约 |
| 给旧 `protect` 增加受控开关 | 命令少，但旧隐式配置、自由日志、签名与输出行为产生组合，容易把旧模式误称为受控模式 |
| 继续只用内部探针或直接开发 MCP | 延后 CLI 契约成本，但探针不宜成为客户端接口，MCP 仍缺可靠的底层执行与取消契约 |

CLI 内新增接口适配，不新建 crate、守护进程、任务数据库、端口或网络服务。父进程仍独占状态、期限、停止证明与最终提交；工作进程复用共享核心。结果映射、进度传输和取消信号各自隔离，不修改核心公开 API、GUI、壳、资源或 DEXB。

## 命令与计划绑定

```bash
shield --config shield-cli.toml agent plan -i input.apk -o protected-signed.apk
shield --config shield-cli.toml agent protect -i input.apk -o protected-signed.apk \
  --expect-plan-sha256 <刚才结果中的完整计划摘要>
```

- 外置配置分支均要求显式本地配置、输入、最终输出；宿主注入既有密码环境变量，不读 GUI 数据库，不接受密码参数。显式共享分支可不提供项目文件，使用绑定记录及有效设置，不接受外部密码环境。
- 共同参数为 `--runtime-profile standard|android-api19`、逐次 `--exclude-abis`、`--timeout-seconds`、`--control-stdin`。总期限默认 1200 秒、有效范围 1–3600 秒，从准备开始，不因进度刷新。
- `protect` 必须指定完整的 64 位十六进制计划摘要，先受控重算并匹配，再启动实际加固。变化时返回 `PLAN_MISMATCH`，不静默按新材料执行。摘要不是授权令牌，不替代用户确认、凭据或单次 ABI 排除授权。
- `plan` 也走受控准备工作进程；证书/预检/资源检查属于同一期限。它可以创建并回收输出父目录内的私有任务目录，以隔离 Java 缓存，但不创建最终 APK、输出父目录或占位文件。
- 两者仅规划/执行 V1–V3；配置要求 V4 时明确拒绝，不静默关闭。输出父目录须已存在，拒绝任何已存在目标或链接，不提供覆盖选项。
- 外置配置分支的工具、环境策略、证书 Alias/类型和签名版本继续来自原配置；不新增外部任务文件或任意执行程序参数。共享分支从已保存记录取得材料，按绑定固定模式、策略和签名版本，项目文件如有则继续绑定其实际身份。
- 旧 `plan-protect` 保留原来的只读响应和生命周期边界；新自动化调用优先使用受控 `agent plan`，不把旧命令改成另一种协议。

## 输出与终态

标准输出始终为 UTF-8 逐行 JSON，无颜色、自由日志或工具输出；不另外提供人类/JSON 双模式。语法错误仍由参数解析器输出到标准错误并退出 2，帮助/版本也不属于运行结果流，客户端不得把任意标准错误当结构化诊断。

公共信封包括 `schema_version: 1`、`experimental: true`、`tool_version`、`operation: agent_plan|agent_protect`、本次随机 `task_id`、从零递增 `sequence`、`type`。任务标识只绑定本次调用，不是设备标识、凭据或重试幂等键；初始化失败尚未分配标识时可为 null。

- `started`：调用已接受，不代表预检、授权或写入已完成。
- `progress`：仅固定阶段枚举和已用时；可省略、合并重复进度，不承诺百分比、每个内部步骤或频繁心跳。父端不得被输出管道阻塞；十二种工作阶段加 `publish`，每阶段最多一次。
- `result`：一次终态；仅在工作组已停止，或已明确记录无法确认停止之后形成。不以工作进程就绪、EOF 或产物存在作为成功。

终态字段：

| 字段 | 约束 |
|------|------|
| `status` | 规划为 `ready/warning/blocked`；执行为 `succeeded/blocked/failed/cancelled/timed_out/unknown`，规划也可失败/取消/超时/未知 |
| `code` | 固定安全错误码或 `OK`，不回传原始异常 |
| `output_state` | `not_published/published/uncertain`；已发布事实不能被晚到取消或清理失败抹掉 |
| `cleanup_state` | `not_needed/complete/incomplete/retained/unconfirmed`，不知道则不谎称已回收 |
| `directory_synced` | 已知发布的目录同步事实，未发布或该事实不明时为 null；位置不确认的未知终态也须保留已知同步事实 |
| `retryable` | 固定 false，不按未知状态自动重跑 |
| `elapsed_ms` | 本次调用已用时，不刷新期限 |
| `plan` | 只有规划完成或执行确知计划时返回摘要/内部计划版本；规划明确私钥实际签名尚未验证 |
| `artifact` | 仅在已发布且证据确定时提供字节数和 SHA-256；不是任意路径、包名或业务信息 |
| `cancel_source` | 可选有限来源，记录请求来源而非承诺一定取消成功 |

所有运行失败走相同信封，包含早期参数语义、配置、材料、准备、握手和提交问题。内部结果若声称已发布但又已取消、失败缺错误码、未发布却携带同步证明或未知提交却声称已清理，适配层失败关闭为 `unknown`，不输出矛盾回执。不修改旧检查的 `schema_version`、旧事件、内部工作帧或资源版本。受控准备的本地证据文件用私有版本 `1` 封装源身份和有限警告位，以同一证据摘要校验；不把私有文件变为公开协议。新增安全字段可兼容追加，删字段或改变含义须递增公共版本。

规划完成但仍有非阻断警告时返回 `warning`；执行仍须逐项通过原规则，不能把警告解释为授权排除 ABI。已交付且位置确认时清理失败属于附加状态，可保持成功；提交是否发生或位置无法确认时返回未知并保留已知事实，不删除已交付文件。

## 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 规划 ready/warning，或执行成功；仍须检查收尾事实 |
| 1 | 已知阻断或失败 |
| 2 | 命令语法错误，可能没有 JSON |
| 3 | 状态/交付回执未知，或最终输出流无法确认送达；不得自动重试 |
| 124 | 确认停止后的总期限超时 |
| 130 | 确认停止后的取消（含受控信号取消），不等同于任意进程收到信号后的系统退出码 |

客户端必须同时核对完整终态和退出码；缺终态、截断 JSON 或进程被强杀一律按未知处理。即使退出 3，文件也可能已经完整交付，不能反推无输出。

## 取消、断开与输出阻塞

- macOS 的 SIGINT/SIGTERM 只登记取消请求；信号处理器不分配内存、不操作文件或执行清场。新命令的父进程生命周期内安装/恢复处理器，不改变旧命令、GUI 或核心的信号行为。
- 普通调用不读标准输入；只有显式 `--control-stdin` 时接受一行 `{"type":"cancel"}`，正文最多 1 KiB。未知字段、类型、超限或非法编码使本次任务失败并收尾，不回传输入原文；空缓冲区 EOF 请求断开取消，半帧 EOF 按非法控制收尾。接收一个有效取消后不再解释后续数据，不从标准输入读取密码或任意命令。
- 信号、标准输入和输出断开汇入同一内部取消标志，重复请求幂等。先请求停止工作组，再确认无后代活动，最后才能报告取消和回收；停止无法确认只能报告未知、保留材料。
- 提交前最后检查点仍可取消；材料复核期间返回的取消/超时须同步到任务状态，不降为普通发布失败。进入最终提交临界区后以实际回执为准。已发布不能删除来满足晚到取消，不从 signal handler 强制退出绕过这一规则。
- 标准输出由容量 32 的有界队列和独立写线程处理；单帧正文最多 4 KiB，一次最多十五帧（开始、十三种阶段、终态）。进度合并重复，父端不能同步阻塞写管道。生命周期监督使用非阻塞描述符状态查询发现输出关闭并请求取消；不消费输出导致写线程阻塞时，监督仍须到期/取消并停止工作组。
- 终态形成后，最多给予 2 秒输出排空宽限；序列化、帧上限或入队失败同样标记回执未确认，不能仅凭写线程正常结束宣称送达。无法确认终态送达则退出 3，不无界等待写线程，不撤回已交付 APK。操作系统不可中断 I/O 仍不是硬实时保证。
- SIGKILL、父子同时崩溃、恶意逃组、同权限攻击或文件系统故障不在正常取消承诺内；旧租约单故障边界保持不变。没有后台“按任务编号取消”服务，不查杀用户其他 Java 进程。

## 实施与验收顺序

1. 先把内部结果补全为能保留输出、清理与持久性事实的模型；接公共信封和参数校验，不靠错误字符串猜是否已发布。
2. 复用已有受控准备支持 `agent plan`，透传有限规划警告；`protect` 比较外部摘要后才创建执行任务。
3. 接有界事件输出，验证唯一终态、顺序、未知状态、原始输出隔离与慢/断开读端；不在唯一监督线程同步写 stdout。
4. 接生命周期内的信号和可选输入控制，验证规划/执行/提交边界取消、非法控制和普通 stdin EOF 不影响默认调用。
5. 显式运行小型真实 APK 的规划→执行、摘要漂移、取消/超时、输出占位、慢/断开读端及原包不变回归。保留大包既有记录，不重复纳入日常 CI。
6. 跑旧 CLI、默认/开发构建、核心及桌面后端回归；设计、任务及使用文档一起同步。满足已启用平台门槛后再讨论正式构建与客户端，安装分发、Skill/MCP 和版本另行确认。

撤回只移除新命令注册和 CLI 适配，保留旧命令；无持久化迁移、资源重编译或已加固 APK 影响。未经原生验证的平台不启用、不降级旧命令串联。首次源码开放仍标注开发能力，不把该确认扩大为恢复 CLI 发布 CI、改变 GUI 或发布新版本的许可。
