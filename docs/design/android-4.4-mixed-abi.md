# Android 4.4 混合架构单包兼容

## 需求与范围

2026-10-23，工控用户确认业务 APK 同时包含五种架构，希望一份加固 APK 同时运行在 Android 4.4 ARM 工控板及较新系统设备上。`armeabi` 来自第三方库，可经用户确认排除，不要求支持真正的旧 ARM 设备。

本次只扩大兼容模式可接受的 APK 架构组合，不取消 ABI 校验，不新增旧架构、不新增 4.4 x86 支持、不改 DEXB 或 Android 壳运行行为、不发布正式版。4.4 的运行承诺仍为 `armeabi-v7a`／NEON，`arm64-v8a`、`x86`、`x86_64` 用于 API 21 以上系统。

维护者已批准以 `1.4.2-rc.3` 通过 GitHub CI 生成三平台 GUI 测试包，供用户使用同一加固 APK 验证实际设备；保留 rc.1、rc.2，不移动旧标签，用户验收前不宣称正式兼容通过。

## 架构判断与方案

变更等级为 L2：复用核心 ABI 排除规则、GUI 预检与单次确认，调整跨层一致性，不新增 crate、依赖、配置或数据库字段。核心提供同一套模式校验，GUI 不再自行维护另一份 v7a 独占规则；资源声明负责识别兼容模式，注入仍严格比较保留 ABI 与实际壳 ABI。

| APK 中的 ABI | 兼容资源 | 运行边界 |
|---|---|---|
| armeabi-v7a | r25c／Rust 1.77.2／API 19 | Android 4.4 起，CPU 须支持 NEON |
| arm64-v8a、x86、x86_64 | 原有 r29／API 21 | Android 5.0 起 |
| armeabi 等旧架构 | 不提供壳 | 单次明确确认后仅从输出排除 |

现有 `resources-api19.zip` 已使用标准四 ABI 壳、仅替换 v7a 为 API 19 产物，继续复用，不再新增 NDK 或让用户加固时现场编译。Android 按设备／进程 ABI 选择库，不在同一 ABI 目录放不同系统版本的同名库。

有 Native 库的兼容输入须包含 v7a，避免纯 64 位／x86 包被误认为能在 4.4 ARM 工控板运行；纯 DEX 输入保持可用。不替第三方补齐各架构业务库，用户仍须测试第三方功能。支持架构不能排除，只有旧架构的包不能靠全部排除继续；未确认排除时核心仍拒绝。

无界面重设计：仅复用现有排除确认、修正中英文模式提示与预检结果。切换 APK 或模式仍重新预检；排除不持久化，不修改原始 APK。兼容资源缺失时必须明确失败，不能静默退回标准资源。

## 任务计划

- [x] 核心：统一模式／ABI 排除校验；增加混合四 ABI、五 ABI 排除、缺 v7a、仅旧架构、非法清单回归。
- [x] GUI：删除重复限制，复用单次排除确认，缺兼容资源明确失败；仅同步文案，不加布局、常驻选项或配置。
- [x] 注入：覆盖原包不变、业务库字节保留、缺壳仍拒绝、只注入原包保留架构。
- [x] 文档：纠正旧设计表中 x86／API 19 规划与实现混淆，同步使用指南、双语 README 和路线图。
- [x] 验证：运行 Rust、前端及脚本测试，执行混合 ABI 真实加固／签名及双 NDK 资源审计，构建 macOS `.app` 供本机验证。
- [ ] 用户设备验收：同一签名 APK 在 4.4 ARM 与较新 64 位设备首次启动、缓存命中、覆盖安装及业务 Native 功能；未执行时明确保留为待验证。

完成代码、自动化与文档后整阶段提交，不因单个修改创建多个 PR；发布版本与用户验证包另按维护者安排，不移动既有标签。无设备时不把构建成功写为运行兼容通过。

发布任务：同步 rc.3 版本与双语说明，PR 必需检查通过后合并，推送新标签触发现有三平台 GUI 工作流；本次不增加 CLI 发布或日常重型 CI。

## 本地实施与验收（2026-10-23）

- 核心以已有资源 `min_android_api=19` 识别兼容模式，复用 `RuntimeProfile` 校验，CLI 显式选择兼容资源时也不能绕过。未声明最低 API 的历史资源按标准模式处理，不改变 APK 协议。
- Rust 测试共 282 项通过（核心 164、CLI 5、GUI 108、核心集成 5），既有需外部条件的测试仍忽略。覆盖纯 DEX、v7a 单架构、双架构、混合五架构和缺壳失败；未把占位库测试当作真实业务 Native 加载。
- 前端构建及 12 项测试、21 项脚本测试通过；Rust 格式和核心／CLI 严格 Clippy 通过。GUI 普通 Clippy 通过但保留原有四项警告，不宣称全仓库零警告。
- `RUNTIME_PROFILE=android_api19 ABI_FILTER_TEST=1 bash tests/scripts/run-protect-e2e.sh` 与标准模式 `ABI_FILTER_TEST=1` 均通过，包含真实双 DEX 加固、显式排除、原包不变、业务库字节保留、签名及 Native 不压缩打包。
- 本机没有连接 Android 设备，没有重新构建 Native。复用已有官方 1.4.1 标准／兼容资源，ELF 审计确认 v7a 为 32 位 ARM／API 19，不含 `dl_iterate_phdr` 名称；其余为对应架构／API 21，字节与标准资源相同。兼容端到端输出四种壳均与兼容资源逐字节相同。
- 本机 ARM64 `.app` 已构建，包含两个资源包、apktool 和 apksigner，按现有 macOS 发布步骤完成完整应用的 adhoc 签名与严格校验。路径为 `target/release/bundle/macos/MocikaShield.app`，不是已发布的新版本，仍显示本地 1.4.2-rc.2；未移动或重发远端标签。
- 尚待：真实桌面确认／取消交互、Windows 原生流程、用户同一 APK 在 4.4 v7a／NEON 与新系统 64 位设备的首次启动、缓存命中、同签名覆盖安装和第三方功能。没有真实混合业务样本，不宣称所有第三方库组合已兼容。
